# NOLO CV1 有效验证记录

这里只记录当前仍成立的实现与验证结果。已放弃的标定算法、临时网页和无效采样不保留；
当前操作方法以 [入口说明](../README.md) 为准，未完成工作以 [TODO](TODO.md)
为准。

## 2026-08-24：采集正确性、诊断与显式零偏标定

- Fusion AHRS 改为直接使用 `Ahrs::new()`，Offset 与显式零偏门限直接来自
  `OffsetSettings::default()`；工程不再复制 Fusion 参数，只保留 NOLO 协议必需的
  采样率和 IMU 单位换算。
- Fusion 只消费采样序号实际变化的新 IMU 样本，重复旧负载不再被重复积分。
- USB 报告静默超过 200 ms 后，三个来源统一发布不可用状态；同一报告的头部和手柄
  使用同一个单调接收时间戳。
- API 拆分通信新鲜度、新样本、未知光学有效性和本帧可用性；旧 `flags` 固定为零，
  网页不再把它显示成真实 tracking flags。
- 增加实测采样率、抖动、序号缺口、重复报告和 Fusion 加速度拒绝状态诊断。
- 内部采集保持设备原生频率，网页 SSE 按来源限制为最高约 60 Hz；离线和恢复事件不
  延迟。
- 实时复核发现两种 Controller 报告中的 HMD 序号流相位不同；后端改为分流判断后再
  合并，现场恢复为约 240 Hz、零虚假丢包，避免交错序号产生数千 Hz 的错误统计。
- 增加显式陀螺仪零偏标定；持续时间和角速度静止门限直接采用
  `OffsetSettings::default()`，超过门限会重新计时。
- 依据保留的历史 SDK 增加实验性握持点位置，原始标记位置继续保留且仍为默认值。
- 新增序号回绕、缺包、重复/超时、握持点旋转、90 度静态姿态和零偏标定测试。
- 现场快速纵轴旋转捕获确认停止后约 1 秒的回拉来自 `gain=0.5` 的标准重力残差收敛，
  而非 acceleration recovery；不叠加自定义快速收敛或动态增益。
- Controller 0 实机复测通过：空间位置关系正常，自身姿态正常；快速绕头尾中心轴
  旋转并停止后未再报告异常回拉、过冲或抖动。复测时手柄约 120 Hz、头部约
  240 Hz，HMD 交错序号分流统计无虚假丢包。
- 最终 6 秒标定流程实机通过：第一秒按键抖动不参与 Fusion 标定，从第二秒开始完成
  Fusion 初始化和陀螺仪零偏采集，最后记录的原点、零姿态和人体方向均正常。
- 修复浏览器保持 SSE 连接时 Ctrl-C 无法退出的问题；关闭信号现在会先通知所有 SSE
  流结束，再完成后端优雅退出并释放 USB。
- 切换网页设备或采样失效时会取消未完成的长按状态，避免返回原设备后由过期计时完成
  标定。

## 2026-08-24：协议未知字段受控复核

- 新增 Rust `nolo-unknown-probe`，原样统计解密后的未知字段和两只手柄 IMU
  负载变化。
- 明确手柄有省电休眠/关机机制；协议采样前必须逐只唤醒并通过动作确认负载更新。
- 有效 12 秒采样中，Controller 0/1 分别收到 1441/1440 包，IMU 分别有 1204/1074
  组不同负载。
- 字节 22 在两只活跃手柄上分别稳定为 `35`、`93`，仍只列为电量/链路质量候选。
- 字节 23 在两只活跃手柄上严格按 `6/7` 交替；冻结 fixture 中为 `0`，过渡段出现
  `2/3`，但 bit 1/2 仍未命名。
- `31–36`、`60–62` 在有效采样中全部为零；`43–48`、`55–58` 会话内固定。
- 字节 63 覆盖全部 256 种值，但 2880 次相邻转换只有 9 次恰好
  `+1`，不是采样序号。
- 未找到可以可靠表示基站开机或光学跟踪有效的字段。

## 2026-08-24：控制器与 HMD 中继采样序号

- 确认偏移统一使用解密数组零基下标。
- `report[24]` 是当前 Controller 的采样序号；有效上报时逐包 `+1`，停止后固定。
- `report[59]` 是 HMD/USB 中继采样序号；控制器停止时仍可继续 `+1`。
- Rust 后端用 200 ms 未变化判断控制器/HMD 中继采样是否新鲜，并停止对重复控制器
  IMU 积分。
- 两个序号都不能判断基站电源或光学跟踪状态。

## 2026-08-24：Rust 直连 USB 后端

- 新增 [Rust USB 后端](../src/nolo-usb-server/)，通过 HIDAPI/libusb 直接打开
  `0483:5750` 或 `28e9:028a`，解密新版 64 字节报告。
- 发布 Controller 0、Controller 1 和 Head Marker；三者分别维护 Fusion 状态。
- USB 报告合计约 240 Hz，单只手柄约 120 Hz；HMD 字段每包出现，按约 240 Hz
  更新并发布。
- 姿态使用 Rust `fusion-ahrs 0.7`，沿用已实机求得的单位和轴变换。
- HTTP 提供 `/api/status`，SSE 提供 `/events`，同一进程承载现有网页。
- API 保留按键、触摸板、原始 IMU、控制器采样序号和 HMD 中继采样序号。
- API 用 `source_online` 和 `sample_sequence` 统一表示三种设备的采样状态；Head
  Marker 不再复用 `controller_online` 或伪造 Controller 序号。
- Rust 单元测试、Clippy `-D warnings`、release 构建和现场 USB
  端到端输出均已通过。

## 2026-08-24：当前网页标定与设备切换

- 网页可切换 Controller 0、Controller 1 和 Head Marker，两个手柄各自保存标定；
  保留俯视图、正视图、Three.js 空间视图和姿态视图。
- 静态契约测试覆盖固定 Three.js CDN、三设备按钮、DOM ID 和通用
  `source_online` 字段，并通过资源版本号避免远程浏览器复用旧脚本。
- 标定流程固定为一次 Menu 长按 6 秒；第一秒用于按键后摆稳，进入第二秒时同时重启
  Fusion 官方初始化并开始连续 3 秒陀螺仪零偏采集，最后约 1.2 秒记录原点和零姿态，
  不需要前移轨迹或第二次按键。
- 页面使用最后约 1.2 秒样本求位置中位数和同半球四元数平均。
- 人和手柄正对基站时，以“标定位置指向基站原点”的水平向量定义人体前方；
  距基站小于 50 cm 时拒绝标定。
- 位置人体坐标固定为右 `+X`、上 `+Y`、前 `-Z`；姿态使用相对零姿态和已验证的
  手柄模型轴映射 `[-x, z, y]`。
- 当前人体坐标仍不是机械臂外参，网页不承担机器人安全控制。
