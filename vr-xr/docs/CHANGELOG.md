# NOLO CV1 有效验证记录

这里只记录当前仍成立的实现与验证结果。已放弃的标定算法、临时网页和无效采样不保留；
当前操作方法以 [入口说明](../README.md) 为准，未完成工作以 [TODO](TODO.md)
为准。

## 2026-08-24：仿真主路径收敛到 MoveIt Servo

- 删除 Rust 中自写 FK/IK、Jacobian、DLS 参数和运行时 `SimulationController`：设备配置
  不再复制关节原点、关节轴和 TCP 变换；IPC 升级到 v2，由官方
  `robot_state_publisher`/TF2 返回 `base_link -> tool0`，用于当前 TCP 显示和 Squeeze
  接管原点。Rust 只保留目标 TCP 坐标映射、IPC 契约、反馈校验、夹爪网页状态和诊断快照。
- 完整复审采集到 Servo 的算法边界：显式/持久化陀螺仪零偏切换时清空 Fusion Offset，
  避免同一偏差重复应用；Servo 反馈序号必须递增，状态缺失、停止或未知均禁止输出。
- IPC/反馈故障恢复后增加 Squeeze 松开再接管门槛，避免仍按住时用旧相对位移自动恢复；
  工作空间越界仍只丢弃本帧，不锁死后续安全目标。
- 服务启动先占用 HTTP 和 IPC 端点，再启动 USB；已有 IPC socket 一律拒绝覆盖，避免
  第二个服务实例解除正在运行实例的 MoveIt 入口。
- 回归测试覆盖 1:5 三轴平移、1:1 三轴局部旋转、故障恢复、越界恢复、非法配置和
  溢出四元数。
- 将示教平移比例从 1:1 调整为 1:5：手柄移动 5 cm，机械臂目标 TCP 移动 1 cm；姿态
  映射不变。
- 新增 `arm/ros2/stararm102_teleop_moveit`：通过标准 `PoseStamped`、`JointState`、
  `ServoStatus` 和 `ServoCommandType` 对接官方 Jazzy MoveIt Servo。
- 复用厂家 URDF/SRDF、碰撞 STL、KDL、`JointTrajectoryController` 与
  `mock_components/GenericSystem`；厂家完整仓库仍在 `~/Develop/temp`，项目只维护补丁。
- 补丁按新品产品表收紧模型和 mock hardware 关节范围，添加 `tool0`，修正 Jazzy mimic
  配置，并把 ROS `joint6` 最大速度明确覆盖为 `3.14 rad/s`。
- 网页改为显示 MoveIt 后端、Servo 状态和关节反馈年龄，不再展示已经无来源的自写 IK
  误差或最小奇异值。
- 在官方 `moveit/moveit2:jazzy-release` 中完成三包构建和运行验证；模型、KDL、碰撞
  监视、控制器、Pose 模式和 Rust↔ROS/TF2 IPC 均正常，三轮端到端检查反馈年龄约
  0–9 ms。
- 当前只运行仿真输出端；真实 102-FL `ros2_control`/驱动与夹爪输出保留为 TODO，不会
  因启动仿真而打开机械臂串口。

## 2026-08-24：接管键与夹爪职责分离

- 修复把 NOLO 位置轴映射误用于手柄自身姿态的问题。位置继续按前 `-Z`、右 `+X`、上
  `+Y` 映射到机械臂前 `+X`、右 `-Y`、上 `+Z`；姿态改用独立正规正交矩阵，并以头部
  抬起、左侧倾和左转向三个实机动作建立回归测试。
- 审核现成运动学方案：`k` 的方阵路径无阻尼、OPW 不满足当前腕部几何、IK-Geo Rust
  尚无可直接使用的 URDF 模型层。当时的 DLS 只供仿真，随后已由本页上方记录的
  MoveIt Servo 主路径替换。
- Controller 0 右侧 Squeeze 键改为示教接管键；启动时必须先观察到松开，新按下时记录
  相对位姿原点，松开或故障后禁止自动恢复。
- Trigger 不再控制接管，只在 active 状态产生两态夹爪命令：按下闭合、松开张开。
- 仿真快照新增夹爪命令、角度和速度；开位 `45°`、闭位 `0°` 直接由厂家 FL 配置
  `[-270°, 0°] / direction=-6` 推导，并复用已有速度/加速度约束。
- 独立机械臂仿真页新增 J7 和左右夹爪联动显示；真实机械臂仍未接入或放行。
- 修复把 FL 逻辑角直接作为 URDF 角的错误；按厂家
  `model_angle = logical_angle / direction` 换算，避免 J2 符号相反导致机械臂主体落到
  基座平面下方。后续 MoveIt 收敛已删除当时的自写 Jacobian。
- 当时修复单次 IK 未收敛被误当成手柄故障并永久锁定的问题；后续 MoveIt 收敛后，
  工作空间、Servo 奇异、碰撞和关节边界统一进入可恢复的 `constrained`，USB、采样、
  非法输入和反馈故障进入 `faulted` 并要求重新接管。
- 新增 `/test-dashboard/` 联合测试页，把原有手柄查看器与机械臂仿真并排显示；两个原始
  页面及其代码边界保持独立，仍可分别打开。
- 调整机械臂仿真的默认相机构图，使地面网格在画面中下移到接近中线；地面物理高度仍
  保持 `Z=0`，没有通过移动几何平面掩盖模型坐标错误。
- J1–J7 改为可拖动的模型角滑块。拖动自动进入 `LOCAL ONLY`，只修改当前浏览器里的
  URDF 模型并显示完整七轴角度；“恢复实时”重新跟随后端，全程没有写请求或执行器接口。
- 根据现场模型确认，把 J1–J7 全部 `0°` 固定为唯一默认姿态和示教启动姿态；不再设置
  另一套展开姿态或自动切换阶段，J7 初始为闭合 `0°`。
- 统一约束语义：工作空间、关节限位、奇异和碰撞约束只提示并丢弃或限制本次目标，
  下一采样继续处理；网页不再把这种可恢复状态显示成“停止”。

## 2026-08-24：完成 FL 设备边界与末端示教仿真

- 新增严格只读探针，只允许 ID 0–6 `ping` 和 `Present_Position`，关闭总线时不释放

- 新增独立 `/arm-simulator/` 只读页面：按厂家 URDF 构建关节树、加载 9 个厂家 STL，

## 2026-08-24：Controller 0 相对示教意图

- 新增独立 Rust `TeleopIntent` 状态机，直接消费进程内 Controller 0 最新采集帧，不经过
  网页 SSE，也不连接机械臂。
- Squeeze 新按下沿记录滤波位置和 Fusion 姿态原点；按住时发布相对平移与相对四元数，
  松开立即回到 idle；Trigger 独立控制夹爪。
- 通信超时、USB 读取中断、标定、非有限数据、缺失滤波位置或无效四元数进入 faulted；
  数据恢复后必须先松开再重新按下 Squeeze，不能自动恢复运动意图。
- 使用 Tokio `watch` 保存唯一最新意图，并在 `/api/status.latestTeleopIntent` 提供只读
  诊断快照；`optical_tracking_valid=null` 保持未知，不伪装成光学有效。
- 单元测试覆盖首次接管、相对位姿、松开、断流恢复、标定、非法数据、USB 故障和
  `q/-q` 四元数符号等价。

## 2026-08-24：采集正确性、诊断与显式零偏标定

- 两只手柄新增相互独立的三轴 One Euro 位置滤波输出 `filtered_position`；直接使用
  固定提交的官方 `casiez/OneEuroFilter` Rust 实现和上游参考参数，原始 `position`
  语义保持不变。USB 断流、序号停止、完整标定和非法输入都会重置滤波历史，网页诊断
  区并列显示原始和滤波位置。

- 陀螺仪换算由历史 OpenHMD 近似值 `0.001 rad/s/count` 改为 `nolo-teleop` 使用的
  signed `i16`、±2000 °/s 量程解释（`2000/32768 °/s/count`）。项目接受该
  第三方实现数据，不再安排本地转台验证，也不把它写成 NOLO 官方规格。
- Fusion AHRS 改为直接使用 `Ahrs::new()`，Offset 与显式零偏门限直接来自
  `OffsetSettings::default()`；工程不再复制 Fusion 参数，只保留 NOLO 协议必需的
  采样率和 IMU 单位换算。
- Fusion 只消费采样序号实际变化的新 IMU 样本，重复旧负载不再被重复积分。
- USB 报告静默超过 200 ms 后，三个来源统一发布不可用状态；同一报告的头部和手柄
  使用同一个单调接收时间戳。
- API 拆分通信新鲜度、新样本、未知光学有效性和本帧可用性；旧 `flags` 固定为零，
  网页不再把它显示成真实 tracking flags。
- 增加实测采样率、抖动、序号缺口、重复报告和 Fusion 加速度拒绝状态诊断。
- 内部采集保持设备原生频率，网页 SSE 按来源限制为最高约 60 Hz；离线和恢复事件不
  延迟。
- 实时复核发现两种 Controller 报告中的 HMD 序号流相位不同；后端改为分流判断后再
  合并，现场恢复为约 240 Hz、零虚假丢包，避免交错序号产生数千 Hz 的错误统计。
- 增加显式陀螺仪零偏标定；持续时间和角速度静止门限直接采用
  `OffsetSettings::default()`，超过门限会重新计时。
- 依据保留的历史 SDK 增加实验性握持点位置，原始标记位置继续保留且仍为默认值。
- 新增序号回绕、缺包、重复/超时、握持点旋转、90 度静态姿态和零偏标定测试。
- 现场快速纵轴旋转捕获确认停止后约 1 秒的回拉来自 `gain=0.5` 的标准重力残差收敛，
  而非 acceleration recovery；不叠加自定义快速收敛或动态增益。
- Controller 0 实机复测通过：空间位置关系正常，自身姿态正常；快速绕头尾中心轴
  旋转并停止后未再报告异常回拉、过冲或抖动。复测时手柄约 120 Hz、头部约
  240 Hz，HMD 交错序号分流统计无虚假丢包。
- 最终 6 秒标定流程实机通过：第一秒按键抖动不参与 Fusion 标定，从第二秒开始完成
  Fusion 初始化和陀螺仪零偏采集，最后记录的原点、零姿态和人体方向均正常。
- 后续将首次成功的三路陀螺仪零偏持久化到忽略 Git 的状态文件；后端启动和 USB 重连
  会按来源加载。存在有效记录时，重复记录原点只更新网页参考系，不再重启 Fusion 或
  重复零偏采集；诊断按钮仍可显式覆盖对应记录。
- 修复浏览器保持 SSE 连接时 Ctrl-C 无法退出的问题；关闭信号现在会先通知所有 SSE
  流结束，再完成后端优雅退出并释放 USB。
- 切换网页设备或采样失效时会取消未完成的长按状态，避免返回原设备后由过期计时完成
  标定。

  组不同负载。

- 字节 23 在两只活跃手柄上严格按 `6/7` 交替；冻结 fixture 中为 `0`，过渡段出现
  `2/3`，但 bit 1/2 仍未命名。
- `31–36`、`60–62` 在有效采样中全部为零；`43–48`、`55–58` 会话内固定。
- 字节 63 覆盖全部 256 种值，但 2880 次相邻转换只有 9 次恰好
  `+1`，不是采样序号。
- 未找到可以可靠表示基站开机或光学跟踪有效的字段。

## 2026-08-24：控制器与 HMD 中继采样序号

- 确认偏移统一使用解密数组零基下标。
- `report[24]` 是当前 Controller 的采样序号；有效上报时逐包 `+1`，停止后固定。
- `report[59]` 是 HMD/USB 中继采样序号；控制器停止时仍可继续 `+1`。
- Rust 后端用 200 ms 未变化判断控制器/HMD 中继采样是否新鲜，并停止对重复控制器
  IMU 积分。
- 两个序号都不能判断基站电源或光学跟踪状态。

## 2026-08-24：Rust 直连 USB 后端

- 新增 [Rust USB 后端](../src/nolo-usb-server/)，通过 HIDAPI/libusb 直接打开
  `0483:5750` 或 `28e9:028a`，解密新版 64 字节报告。
- 发布 Controller 0、Controller 1 和 Head Marker；三者分别维护 Fusion 状态。
- USB 报告合计约 240 Hz，单只手柄约 120 Hz；HMD 字段每包出现，按约 240 Hz
  更新并发布。
- 姿态使用 Rust `fusion-ahrs 0.7`，沿用已实机求得的单位和轴变换。
- HTTP 提供 `/api/status`，SSE 提供 `/events`，同一进程承载现有网页。
- API 保留按键、触摸板、原始 IMU、控制器采样序号和 HMD 中继采样序号。
- API 用 `source_online` 和 `sample_sequence` 统一表示三种设备的采样状态；Head
  Marker 不再复用 `controller_online` 或伪造 Controller 序号。
- Rust 单元测试、Clippy `-D warnings`、release 构建和现场 USB
  端到端输出均已通过。
