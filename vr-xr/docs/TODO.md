本文件记录已经完成的统一控制迁移、当前契约和仍待真机执行的现场验收。ROS 只看到一套
机械臂、控制器、话题和 IPC；是否连接真机只由 Rust 运行时是否持有串口决定，网页始终显示
同一个关节反馈状态。

状态说明：

- `[x]` 表示当前工作区已经实现并完成自动化或仿真验证的基线。
- `[ ]` 只表示文末尚未执行的真机或后续功能，不代表统一控制迁移仍有第二条旧路径。
- 当前统一迁移已经通过自动化和纯模拟 ROS 集成；真实 USB 机械臂也已完成串口反馈与运动的
  部分定性验收。尚未执行的定量现场项目保留在文末，不阻塞当前阶段完成。
- 手柄采集层已经完成 `1:2` 输入缩放，本 TODO 不修改该逻辑，也不把它列入本次实现或验收。

## 已冻结的术语和行为

- **手臂关节**：J1–J6，对应六元素弧度数组。
- **当前末端 link**：厂家 URDF 的 `link6`。MoveIt arm 链、TF 和 IPC 统一使用它；夹爪 TCP
  未实测前不添加额外工具坐标系。
- **夹爪关节**：ROS 主关节 `joint7_left`，以绝对弧度值表示；其他夹爪模型关节仍由机器人
  描述中的 mimic 关系处理。
- **统一关节状态 `ArmState`**：J1–J6 实际/软件反馈、夹爪实际/软件反馈和反馈来源。角度是
  唯一权威值；页面若显示“开/合”，只能从角度派生，不能另存一份权威布尔状态。
- **串口状态 `SerialState`**：`selected_port`、`connected` 和当前 `error`。它只陈述 I/O
  事实，不复制关节角，也不派生运动权限。
- **软件反馈**：未连接串口时，ROS 控制器当前输出的关节设定值回写为 `ArmState`。
- **真机反馈**：连接串口后，由 Rust Monitor 读取的实测关节值覆盖同一个 `ArmState`。
  “软件/真机”是反馈来源，不是两套 backend、executor、ROS 配置或页面状态。
- **起始位**：冷启动且尚无反馈时，J1–J6 为 `[0°, 0°, -3°, 0°, 0°, 0°]`，夹爪为
  `+1°`。它只是尚无反馈时的默认显示和起始位按钮的目标，不是连接真机或启动模拟的前置条件。
- **普通运动请求 `MotionRequest`**：只描述任意 J1–J6 目标及其执行状态。
- **夹爪请求 `GripperRequest`**：只描述一个夹爪绝对角度，交给 `hand_controller`；
  不触发 J1–J6 的 MoveGroup 规划。
- **普通起始位运动**：起始位按钮提交 J1–J6 `[0°, 0°, -3°, 0°, 0°, 0°]` 的普通
  `MotionRequest`，保持夹爪当前位置不变。起始位
  不是第二条执行路径。
- **夹爪完整路径**：命令、控制器输出、软件/真机执行、反馈、IPC、ROS `joint_states`、
  Rust 状态、HTTP/SSE 状态和网页模型全部携带夹爪角度；不表示把夹爪塞进六轴手臂规划组。

## 不可违反的实现原则

- 遵守仓库根目录 `AGENTS.md`：不擅自增加用户未要求的门限、保护、拒绝条件、安全流程或
  重复底层已有的限制。
- 只保留本次涉及且已确认的项目数值：J1–J6 起始位 `[0°, 0°, -3°, 0°, 0°, 0°]`、夹爪
  起始位 `+1°`、已有依据的 `30 rad/s²`，以及已有可复现实测依据的 MoveIt 配置。
- 不为理论边界条件建立新状态机、恢复路径、缓存层或大量 `if/else`。只有可复现失败且现有
  组件不能正确表达时才添加处理，并用测试复现原因。
- 优先删除分支和合并数据流，不用新抽象同时保留旧的模拟/真机架构。
- Rust 不复制 MoveIt、ROS 控制器、URDF 或舵机驱动已经负责的规划、插值和关节限制。
- 平台或依赖强制执行的限制只注明来源，不包装成项目自行设计的规则。
- 每轮修改后执行对应测试；发现问题后允许继续修改，但修复后必须重新进行相关验收和全量
  回归，而不是只验证最后一个问题。

## 一、冻结统一接口

- [x] `ArmState` 固定只包含 J1–J6 弧度数组、夹爪弧度值和 `software/serial` 反馈来源；
      尚无反馈时 J1–J6 为 `[0°, 0°, -3°, 0°, 0°, 0°]`，夹爪为 `+1°`。
- [x] `SerialState` 固定只包含所选端口、是否连接和最近一次连接结果；不把它扩展成第二套
      机械臂运行状态。
- [x] 只保留 Compose 专用 `servo-ipc` 卷内的 `/ipc/moveit-servo.sock` 这一个双向 ROS IPC
      地址，删除宿主机 socket 和 `moveit-servo-hardware.sock`。IPC 明确区分：Rust 发给 ROS
      的手柄目标/运动请求/夹爪请求、ROS 控制器发给 Rust 的七关节设定值，以及 Rust 返回
      ROS 的七关节反馈。
- [x] `MotionRequest` 固定为 J1–J6 完整目标；`MotionStatus` 使用同一个 request ID 表示
      planning、executing、succeeded、failed 或 cancelled；取消只针对该普通请求。
- [x] 多个 `MotionRequest` 的接受、抢占和结果沿用 MoveGroup action 的现有语义；Rust 不再
      添加队列、自动取消、额外拒绝或恢复状态。用户显式取消时才发送取消请求。
- [x] `GripperRequest` 固定为单个绝对弧度值，可与手臂运动独立提交；它没有
      `open/closed` 二选一协议，也不触发手臂重新规划。
- [x] 起始位按钮仅用普通 `MotionRequest` 提交 J1–J6 `[0°, 0°, -3°, 0°, 0°, 0°]`，并以
      MoveIt 返回的普通轨迹执行结果判断完成；删除 `HomeRequest`、`HomeStatus`、`HomeState`、
      专用起始位 API 和起始位反馈二次门限。
- [x] 串口接口固定提供状态查询、按端口连接和断开；未选择或未连接串口就是纯软件模拟。接口
      不接受 simulation/hardware backend 或启动模式参数。
- [x] HTTP、SSE、IPC 和 ROS 字段使用同一单位与顺序：弧度、J1 到 J6、最后单独的夹爪弧度。
      页面只为带 `°` 标签的显示和输入做显式换算，协议中不混用单位。

## 二、把 Rust 执行层压薄

- [x] 用唯一的 `ArmJointIo` 替换 `SimulatedExecutor` / `FashionStarSerialExecutor`；
      名称在本 TODO 中不再保留“最终可调整”的歧义。它是 Rust 内部的薄 I/O 边界，不是第二个
      ROS hardware plugin。
- [x] `ArmJointIo` 接收 ROS 控制器输出的 J1–J6 与夹爪设定值，并发布一个 `ArmState`。
- [x] 未连接串口时，收到的七关节设定值直接成为软件反馈；不得另跑一套模拟 executor。
- [x] 连接串口后，同一组设定值由 Rust 编码写入舵机；Monitor 的 J1–J6 与夹爪实测值覆盖
      同一个 `ArmState`。
- [x] 串口有/无只在 `ArmJointIo` 内形成一次分支；ROS、运动 API 和页面不再判断 backend。
- [x] Rust 只负责命令转发、串口编解码、实测读取和状态发布，不做轨迹规划或插值。
- [x] Python 只负责 ROS 与 IPC 互通；删除 Python 串口节点和厂家总线实现。
- [x] 串口断开后保留最后一次 J1–J6 与夹爪实测位置作为软件反馈起点，不自动移动、不返回起始位、
      不重启 ROS。
- [x] 串口连接错误作为事实返回页面，不派生运动闭锁、锁存状态或恢复状态机。

## 三、实现运行时真机连接

- [x] 用户选择串口后，Rust 打开串口并读取 ID 0–6 的当前反馈，不先发送运动命令。
- [x] 软件和真机 J1–J6 与夹爪可处于任意姿态；连接不检查起始位。
- [x] Ping 和 Monitor 读取成功后，把该串口附着到现有 `ArmJointIo`，并用实测状态替换
      当前软件反馈；不替换 ROS 配置或启动另一条执行路径。
- [x] 已连接时再次连接，先释放已有串口句柄再重新打开。
- [x] 真机串口已连接时，网页隐藏端口输入和“连接”按钮，改为显示已连接设备、命令去向和
      “断开”按钮；断开后才恢复连接控件。
- [x] 连接失败只报告实际打开、Ping 或 Monitor 错误，不增加姿态容差、连接门槛或前置流程。
- [x] 当前阶段用可控假串口覆盖任意软件/真机姿态连接、命令写入、Monitor 回读和断开续接。

## 四、统一 ROS 路径

- [x] 只保留一个 launch、一个 controller 配置、一个 `JointStateTopicSystem`、一组话题和
      一个 IPC 地址；ROS 不知道串口是否连接。
- [x] `JointStateTopicSystem` 的命令侧输出 J1–J6 与夹爪设定值，状态侧只接收统一
      `ArmState`；不根据运行模式更换 hardware plugin。
- [x] MoveIt Servo 手柄控制继续输出到同一个 `JointTrajectoryController`。
- [x] 普通 J1–J6 目标由 MoveGroup 规划并交给同一个 `JointTrajectoryController`。
- [x] 夹爪目标由同一 ROS 实例中的 `hand_controller` 执行，再经相同 IPC 和
      `ArmJointIo` 到软件状态或真机。
- [x] 离散手臂轨迹执行时暂停 MoveIt Servo 对同一手臂控制器的写入；完成、失败或取消后基于
      最新统一反馈重建手柄参考。这只解决两个命令源同时写同一控制器的问题，不扩展为保护
      流程，也不阻止独立夹爪命令。
- [x] 普通规划若因真实的起始自碰撞失败，只把本次检测到的起始接触对加入本次请求的允许碰撞
      矩阵，再重试同一个 MoveGroup 路径；该能力适用于任意 J1–J6 目标，不为起始位建立旁路。
- [x] 停止模拟只停止 NOLO 模拟输入数据，不发送运动或夹爪命令；起始位始终由起始位按钮提交普通
      J1–J6 `[0°, 0°, -3°, 0°, 0°, 0°]` 目标。
