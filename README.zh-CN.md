# Robot Arm

智能机器人控制平台。通过浏览器连接相机、输入设备和机械臂，完成观察、交互、规划与实际操作。

![关节控制与真机反馈驱动的机械臂三维预览](.github/media/motion.jpg)

## 关于这个项目

桌面上放着一个海绵，你想让机械臂把它放到指定区域。说出这句话很简单，真正动起来之前却有不少事情要处理：相机看到的是什么，物体在哪里，夹爪从哪边接近，途中会不会碰到桌面，闭合后有没有夹住。

Robot Arm 把这些工作放在同一个工作台里。相机画面、物体标注、三维定位、关节控制、运动状态和舵机反馈可以连着看、连着操作。你可以自己选择目标，也可以把任务交给能看图、调用工具的大模型；需要调整时，原有的手动功能仍然都在。

项目面向真实机械臂。当前使用 StarArm-102 六轴机械臂和 RealSense D415，已经完成过海绵等物体的实际抓取与放置。网页里的三维机械臂跟随电机反馈，不只是播放一段演示动画。

我们希望保留两种使用体验：熟悉机器人时，能直接操作关节、坐标和设备参数；只想完成一件事时，可以从画面和自然语言开始，不必先把自己的意图翻译成一串角度。下面按页面中的五个模块介绍目前能做的事情。

## 可以用它做什么

### 让机械臂帮你挪动桌上的物体

把物体和放置区域放进相机视野，使用保存好的标定，从画面中选择目标，或者直接告诉 AI 想做什么。识别、定位、选择抓取姿态、规划和执行连接在同一条任务里。等待期间可以看到当前步骤，也可以留着浮动视频看机械臂实际动作。

目标没被模型认出来时，可以换一种描述，也可以自己框出来。比如，一个区域没有合适的类别名，但你知道那里可以放东西，就可以把它标成放置区。人工选择和模型识别可以共同组成一次任务，不需要二选一。

### 用手柄或空间控制器直接操作

想自己找一个合适的姿态时，可以用方向按钮、摇杆或跟踪控制器操作。先确定哪些输入控制位置、哪些控制朝向，再调整移动比例和方向。摆好之后，可以查看真实关节角度、末端位置，以及机械臂的三维姿态。

这种方式也适合熟悉一台新机械臂：先从一个方向、一种动作开始，观察反馈，再逐步打开更多控制分量。你不必为了试一下工具旋转，就重新写一段控制程序。

### 把 AI 当成能操作工作台的助手

有时只需要问“相机现在看到了什么”，有时需要“回到工作位”，有时才是一次完整抓放。AI 可以读取当前画面与设备状态，也可以调用运动和夹爪工具。你可以在同一会话里追问执行结果，或者补充参考图片。

下面是不同粒度的指令示例，不是额外的预设任务：

| 想做的事 | 可以怎样表达 |
| --- | --- |
| 观察现场 | “看看相机里有什么，先不要运动。” |
| 了解机械臂 | “告诉我当前关节角度和夹爪的负载反馈。” |
| 准备操作 | “回到工作位。” |
| 小幅调整 | “沿工具自己的方向前进 1 厘米。” |
| 调整夹持 | “把夹持反馈目标设为 30。” |
| 完成抓放 | “把紫色海绵放到中心区域。” |
| 查询进度 | “刚才那次任务进行到哪一步了？” |

模型调用的工具与人点击的功能相同，既能把一件事交给它，也能展开过程，看看它具体做了什么。

### 做机器人应用，也研究机器人本身

你可以只研究一张图的分割，不连接机械臂；也可以用同一幅 RGB-D 观测比较目标定位与抓取候选，再进入运动规划。需要调硬件时，执行页提供电机原始反馈和参数读写；需要看空间关系时，可以查看三维模型和 MoveIt/RViz 场景。

这些能力分别有自己的入口。抓放把它们串起来，但不会让“查看相机”“运行分割”之类的单独操作也被迫启动完整任务。

## 控制绑定

### 选择顺手的操作方式

没有手柄也可以使用网页上的方向控制。前后左右、上移下移，以及俯仰、转向和绕工具轴旋转都有对应按钮，按住时运动，松开后停止。适合在机械臂旁边观察，一次调整一个方向。

需要连续操作时，可以连接 SDL3 支持的手柄；需要空间位置和朝向输入时，可以使用 NOLO CV1。页面展示发现的设备和它们实际具备的能力，也可以给设备起一个容易辨认的名字。

位置来源和姿态来源可以分别选择。例如，用一个设备提供位置、另一个设备提供朝向，不需要把所有控制都塞进同一个控制器。没有空间跟踪能力的手柄也可以通过按钮和摇杆控制相对移动。

### 按自己的习惯绑定动作

绑定面向动作，而不是某一款手柄的固定键位。一个动作可以使用单个按钮、连续轴，或一对正负方向按钮。方向不顺手时可以反转；更换设备后也能重新选择对应输入。

可配置的动作包括平移、圆弧运动、工具旋转、工具轴向运动、夹爪开合，以及控制接管等。位置变化与夹爪自身朝向可以分开操作，避免每次移动物体都要重新调整全部关节。

对于有振动能力的设备，还可以选择反馈设备和反馈能力，让夹持负载变化通过手柄反馈出来。输入与反馈都在同一页配置，不需要另外维护一套手柄程序。

### 先看输入，再让机械臂动作

输入测试会显示选中设备的按钮、轴和位姿信息。按下了哪个键、摇杆是否归零、设备是否在更新，都能直接核对。页面也提供模拟输入，方便检查绑定关系。

设备名称和动作绑定可以保存。需要进一步定位问题时，可展开原始位姿、控制输入和设备发现状态；日常使用不需要一直面对这些数据。

## 空间

### 把“往前一点”变成一致的方向

拿着控制器操作机械臂时，最容易混淆的是方向：控制器自己的前方、操作者的前方、机械臂的前方，不一定相同。空间页负责这些关系，让运动和执行层收到已经转换好的控制量。

可以配置输入坐标到前、左、上坐标的映射，调整平移倍率，并以接管时的位置与姿态建立相对原点。这样，手部移动的距离和机械臂移动的距离可以不同，也不用把跟踪设备的绝对位置当成机器人目标坐标。

页面同时展示人体空间、设备自身姿态、前后左右上下的变化，以及当前控制过程。调整映射时，可以对照画面理解结果，而不是只猜矩阵里的正负号。

### 同一个转动，可以有不同含义

把控制器向下倾斜，有时是想让机械臂沿圆弧下移，有时只是想让夹爪在原地低头。两种动作在这里可以区分：

- 垂直姿态可以映射为垂直圆弧，也可以映射为工具定点垂直旋转。
- 水平姿态可以映射为水平圆弧，也可以映射为工具定点水平旋转。
- 底座坐标平移、工具轴向平移、轴向旋转和螺旋运动有各自的控制分量。
- 不需要的分量可以关闭，让一次操作只影响你想调整的部分。

没有绝对位置或姿态输入时，系统使用配置的平移速度和圆弧角速度处理按钮、轴输入。这些转换集中在空间层，手柄和机器人驱动不必各自实现一遍。

## 感知

感知页把相机与标定放在前面，下面是统一的 AI 工作区。你可以在同一页查看现场、处理分割、进行三维定位，再选择抓放目标。暂时不用的配置和工具可以收起。

### 相机来源与配置

相机列表显示型号、序列号、连接信息、驱动和支持的流配置。分辨率、像素格式和帧率来自设备实际报告，不要求所有相机都使用同一个固定配置。暂时不能使用的选项仍然会显示，并说明不可用状态。

常用操作包括：

- 刷新设备列表，选择相机，保存并启用配置，重置或停用当前相机。
- 分别选择彩色流和深度流的分辨率、格式与采集 FPS。
- 独立设置感知上送频率。例如相机持续采集，感知只每秒取一帧，观看视频不必也降到每秒一帧。
- 查看并调整驱动提供的 RealSense 专属参数。
- 查看彩色图、深度图、相机内参和外参。

彩色视频可以浮动、拖动和收起，操作其他栏目时仍然能留意现场。普通图像也有刷新入口，适合在移动物体之后确认当前画面。

除了设置值，页面还显示实际运行的彩色与深度流、实测采集和上送 FPS、设备缺帧、主动略过的帧与最近帧序号。需要低频感知时，可以分清哪些帧是按设置主动略过，哪些是设备没有送到。

相机配置与已应用的标定由后端保存，按设备身份关联；换 USB 口或枚举顺序变化不会把它当成一份新的索引配置。重启后需要重新选择启用相机，但已经保存的配置和标定仍可复用。

### 相机外参标定

固定在场景中的深度相机，需要知道自己相对机械臂底座的位置与方向。外参标定用于建立这层关系，让画面里的三维点可以转换到机器人坐标。

安装 ChArUco 标定板后，可以从网页开始自动标定。机械臂先到工作位，再按型号预设的姿态依次移动、采图、采样，完成求解后返回工作位。页面会显示到了哪一组、记录了多少样本、当前在等什么，以及最后的拟合结果。

采样使用新的实际电机反馈计算末端位姿，不把命令里希望到达的角度当成真实姿态。标定板参数可以展开查看和调整；求解结果经确认后保存，页面保留上次应用的外参数值，并提供重新标定入口。

板子的格数、字典、单格与 Marker 尺寸，以及实际量到的板宽板高都能查看或设置。结果既有整体拟合 RMS 和最大残差，也有各组样本的平移与旋转残差，便于判断是哪一组观察不理想。重新标定时，旧的已应用结果保留到你确认替换，不会在刚点击开始时就丢失。

### 分割：让人和模型一起指出目标

不是每个物体都容易用一个名称识别，也不是每个任务都值得反复调整提示词。因此，工作区保留三种可以组合的方式：

| 方式 | 怎么使用 |
| --- | --- |
| 提示词分割 | 输入物体描述，让 YOLOE 寻找对应区域；也可以使用参考图和视觉提示框。 |
| 自动分割 | 使用无提示词模型寻找画面中的目标，先看看模型能分出什么。 |
| 手动标注 | 在原图上框选目标或放置区，并填写便于自己辨认的名称。 |

三种入口各自折叠、各自运行。运行一个模型只更新它的结果，不会清掉另一个模型或人工标注的内容；也可以单独清除某个来源。需要修改人工框时，可以编辑、删除和保存，不必重跑整个感知流程。

全部结果在一张原图上用框和标题展示。点击标题可查看详情、来源和模型置信度等信息；人工标注明确保留人工来源。手动编辑区域只显示人工标注，避免和其他模型的框混在一起。

分割处理的是固定的同一帧。载入新帧后再重新标注；后续三维定位使用这次分割对应的深度，不会拿后来一帧的深度去解释旧画面。

![同一相机固定帧上的模型识别目标与人工放置区域](.github/media/segmentation.jpg)

上图组合了模型识别的抓取物和人工标注的中心放置区。名称是这次任务使用的标签，放置区并不是模型自动识别的结果。

### 从二维结果到三维目标

只做分割时，不需要连接机械臂，也不要求先完成外参标定。需要抓取时，再使用深度、内参和已保存外参进行三维定位，得到物体位置、范围和实例点云。

三维定位与分割是独立操作，定位不重复运行分割模型。选中抓取物之后，GraspGenX 生成夹爪抓取候选，再由运动模块结合机器人可达性和碰撞场景选择可执行方案。

手动抓放的操作很直接：选择抓取物、选择放置区域、启动。系统复用这次已经确认的观测；如果载入了新场景，则需要在新场景里重新选择。页面持续显示候选准备、规划、执行和结果，而不是只留下一个没有后续的启动按钮。

### 用对话操作机器人

你也可以直接描述任务，例如“把紫色海绵放到中心区域”，让 AI 调用上述能力。相机画面可以由 AI 工具直接获取，不需要为了让它看现场，先下载图片再手动上传。另有图片附件入口，可在对话中补充参考信息。

目前 AI 可以调用的能力包括：

- 读取机械臂实际关节、TCP、夹爪负载和连接状态。
- 查看相机配置、当前场景、分割结果和标注来源。
- 获取新的相机画面，载入固定分割帧。
- 运行分割、添加图像框选、进行三维定位和生成抓取候选。
- 选择对象并发起抓放，查询同一请求的进度与结果。
- 返回工作位、设置关节目标、执行绝对或相对 TCP 动作。
- 控制夹爪开合、调整持续夹持目标，以及取消指定任务。

因此，可以围绕同一个任务继续说话，也可以只询问状态，不一定每次都抓放。历史会话、用户消息、模型回复和工具记录会保留；可以创建新会话，也可以回到原来的会话继续沟通。

模型服务地址、模型名称与思考强度可在页面配置，模型和强度既能下拉选择，也能手动输入。接口使用 OpenAI 兼容的 Responses API，密钥留在服务端。执行时可以展开工具详情，查看本轮用了什么能力、关联了哪个机器人请求、当前处于哪个阶段。

模型配置也提供模型列表刷新与连接检查；配置区会区分待保存内容和已生效设置。切换通用 AI 模型不会禁用提示词分割或自动分割，它们仍然可以独立使用。需要结束当前操作时，页面有“停止 AI 与当前动作”的入口。

AI 通过与手动页面相同的接口操作机器人。识别、空间定位、运动规划和电机执行都有各自的结果，模型可以读取这些结果继续处理任务。是否确实夹住、物体最后在哪里，仍需要结合真实画面判断。

## 运动

### 调好目标，再让它动

手动关节控制采用“编辑目标—查看预览—点击执行”的方式。拖动滑块不会马上驱动机械臂；调整期间，页面显示实际姿态和目标姿态两个模型。也可以恢复当前实际姿态，放弃尚未执行的编辑。

除了关节目标，还可以使用工作位等预设位置、单独控制夹爪，或者给出末端 TCP 位姿。TCP 支持底座坐标系下的绝对目标，也支持底座系或工具系中的相对移动与旋转。比如沿工具自身方向移动，就不必先手动换算成底座的三个坐标分量。

页面同时展示当前与目标 TCP 的位置、朝向，以及规划结果、轨迹点数和计划时长。普通运动可设置本次请求的速度等覆盖项；目标模型只是预览，是否可达要看规划结果。

### 连续控制与完整抓放

连续相对控制由 MoveIt Servo 处理，手动离散目标与感知任务由运动规划处理。它们共用同一机械臂模型、坐标关系和执行反馈。

抓放使用 MoveIt Task Constructor 组织步骤。感知提供多个候选，规划层寻找完整可执行的方案，结合候选质量、姿态变化和运动代价排序。单个候选的 IK 失败不会作为运动发给机械臂。

接近物体时，会结合实际夹爪几何和碰撞检查细化夹取深度。抓住后，将目标作为附着物体纳入运输碰撞检查；任务继续完成持物移动、放置释放和返回工作位。放置姿态的选择也考虑与前后动作的衔接。

环境来自同次观测的点云，通过 MoveIt 官方 Octomap 组件建立任务快照。抓取目标的接触、附着、运输和释放由任务阶段管理，而不是简单地把所有物体都当成永远不能接触的障碍。

### 知道动作进行到了哪里

任务会显示请求编号、当前阶段、完整方案和执行状态。出现问题时，可以区分是在准备候选、寻找方案，还是已经开始执行。

动作结果可以按请求编号查询，刷新页面后继续查看已有请求。也有取消入口，取消后继续等待实际任务反馈。这样，操作页面、AI 对话和后台执行可以围绕同一个请求说明情况。

如果需要看得更深，运动页能展开 MoveIt/Servo 状态、当前末端与目标、规划结果和型号元数据；另有浏览器可访问的 RViz 界面，用来查看机器人、点云与规划场景。平常只操作网页控制台即可，需要分析空间关系时再打开这些视图。

## 执行

### 看到实际机械臂，而不只是目标

执行页用于核对真实设备。机械臂三维模型来自电机实际反馈，旁边可以查看最后命令、当前关节和工具目标。命令已经发出但电机尚未到达时，目标与反馈的区别仍然可见。

串口既可以从枚举列表中选择，也可以手动输入路径。页面显示连接状态、当前端点和连接异常；断开后的旧数据会标为历史信息，不继续冒充当前读数。整臂上力、卸力也在这里统一操作。

### 持续夹住，而不只是闭合一次

对海绵这样的软物体，夹爪合到某个角度不等于之后一直能保持合适的夹持状态。执行层使用舵机负载反馈持续调整，运输时也继续调节，直到显式张开或卸力。

可以设置夹持反馈目标，查看实际反馈、控制功率、采样时间和调节状态。这个目标使用 0–100 的归一化负载刻度，不是牛顿单位；不同物体的接触方式不同，仍可以通过画面观察是否滑动或脱落，再调整目标。

### 舵机信息和参数不再藏在驱动里

原生 Rust 驱动支持读取 FashionStar 舵机信息、状态与配置，也提供相应的参数写入能力。页面可以查看：

- 电机报告角度、圈数、状态位。
- 电压、电流、功率和原始温度读数。
- 固件编码、设备信息，以及驱动支持的配置项。
- 参数的单位、用途、可写状态和生效方式。
- 读取进度、最近一次读取时间与字段错误。

可配置实际反馈的回读周期。串口查询、回包和写入由同一调度器处理，不让多个模块各自抢占串口。完整参数含义保留在型号文档中，日常调整则可以在执行页完成。

## 平时使用时，哪些东西会留下来

输入设备的名称和绑定、空间映射、相机配置、已确认的标定，以及 AI 的非敏感配置，都由相应服务保存。会话记录和机器人请求记录也会保留，刷新网页后可以继续查看，不必靠上一页还没关闭来记住进度。

新相机画面与旧标注则有明确区别。移动了物体，就应载入新观测；原有固定帧不会悄悄变成另一张图。模型标注、人工标注和三维定位保持来源关系，便于知道某个目标是从哪里来的。

页面提供展开式的详情和诊断：日常看画面、目标和进度，遇到问题再看请求编号、坐标、参数和原始反馈。这样可以逐步了解系统，不需要第一次打开就读懂所有机器人术语。

## 当前支持与项目结构

当前实物平台是 StarArm-102 六轴机械臂、RA8-U35H-M 舵机和 RealSense D415；输入侧支持 SDL3 手柄和 NOLO CV1。其他硬件可以从适配层接入，但不在这里宣称已经适配所有机械臂或相机。

后端主要使用 Rust 和 Dora，网页使用 Next.js、React、Three.js；相机与图像处理使用 librealsense 和 OpenCV，视觉模型为 YOLOE 与 GraspGenX，运动使用 ROS 2、MoveIt 2、Servo 和 MTC。Redis 保存请求与 AI 会话，服务依赖由各自的 Docker 镜像维护。

模拟输入和真实输入经过相同的业务链路；AI 调用和人工操作也复用同一组功能。模型权重和依赖准备好之后，本地分割、手动控制和抓放不依赖外部大模型服务。自然语言对话需要可用的模型接口，是否访问互联网取决于你将模型部署在哪里。

这是桌面机械臂项目。打印标定板、相机深度、传动间隙、夹爪形状和物体材质都会影响实际效果。我们保留实际反馈与观察入口，让这些差异能被看见、被调整，而不是用一个“任务完成”掩盖所有情况。

想了解内部如何连接，可以继续阅读[架构与调用链](docs/BACKEND.md)、[机械臂与舵机参数](docs/STARARM-102.md)；部署细节单独放在[Docker 与服务镜像](docs/DOCKER.md)。
