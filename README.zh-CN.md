# Robot Arm

面向真实机械臂的智能机器人控制平台，集成多设备输入、RGB-D 感知、多模态 AI、运动规划与电机反馈，提供统一的浏览器操作界面。

![关节控制与实际反馈、目标姿态三维预览](.github/media/motion.jpg)

## 项目概述

Robot Arm 将机器人操作划分为控制绑定、空间、感知、运动和执行五个模块。用户可以直接操作关节、末端位姿和设备参数，也可以通过自然语言调用观察、分割、定位、抓放及状态查询等能力。

AI 通过工具调用编排已有功能；三维定位、逆运动学、碰撞检测和轨迹执行由对应模块完成。人工操作与 AI 共用业务接口，真实设备和模拟输入共用下游消息契约。

当前已适配 StarArm-102 六轴机械臂、RA8-U35H-M 舵机和 RealSense D415，并完成真实物体抓取与放置。网页三维模型使用实际电机反馈，支持对照当前姿态、目标姿态和任务状态。

| 模块 | 主要输入 | 职责与输出 |
| --- | --- | --- |
| 控制绑定 | 按钮、轴、跟踪位置与设备姿态 | 设备发现、动作绑定与输入组合，输出统一控制动作和位姿 |
| 空间 | 输入位姿、控制动作与映射配置 | 相对原点、坐标换基和运动语义转换，输出机器人相对控制量 |
| 感知 | RGB-D、相机参数、实际末端反馈与任务指令 | 标定、分割、三维场景、抓取候选及 AI 工具编排 |
| 运动 | 相对控制、关节/TCP 目标、场景与抓取候选 | 连续控制、IK、碰撞检测与完整任务规划，输出可执行轨迹 |
| 执行 | 轨迹、夹爪目标与设备配置 | 串口驱动、夹持调节与遥测，输出实际关节和执行结果 |

## 控制绑定

将不同输入设备转换为与机械臂型号无关的控制动作，统一管理输入来源、动作映射与设备反馈。

### 设备接入与输入组合

| 功能 | 支持内容 |
| --- | --- |
| 手柄输入 | SDL3 手柄的按钮、连续轴与设备能力发现 |
| 空间跟踪 | NOLO CV1 的位置与姿态输入 |
| 网页控制 | 前后左右、上下平移、俯仰、转向和工具轴向旋转；按住运动、释放停止 |
| 独立来源选择 | 位置与姿态可使用不同设备，组合为统一输入位姿 |
| 无跟踪设备控制 | 通过按钮和轴产生相对运动，不要求绝对空间位姿 |
| 设备管理 | 展示发现结果、连接状态和输入能力，支持自定义设备名称 |
| 配置持久化 | 保存设备名称与绑定，不使用临时枚举索引作为长期配置身份 |

### 动作与反馈绑定

- 支持单按钮、连续轴、正负方向按钮对，以及方向反转。
- 支持平移、圆弧、工具旋转、工具轴向运动、夹爪开合和控制接管等动作。
- 位置变化与工具自身姿态可独立控制。
- 动作与设备键位解耦，更换设备后可重新映射输入，无需修改下游控制逻辑。
- 支持选择振动反馈设备及反馈能力，将夹持负载反馈关联到支持该能力的输入设备。

### 输入验证与诊断

- 实时显示按钮状态、轴值和输入位姿。
- 支持模拟输入，用于检查绑定与空间映射。
- 可展开原始绝对位姿、统一控制输入和设备发现状态。
- 输入检查与机器人运动分层，单独查看输入不触发完整任务。

### 绑定配置的组织方式

输入适配器负责设备通信和原始事件，绑定层负责将事件解释为动作。设备的按钮编号、轴编号、跟踪能力与业务动作分开保存，运动层接收的是平移、旋转或夹爪控制意图，不需要识别某款手柄的键位。

| 配置维度 | 作用 | 典型使用方式 |
| --- | --- | --- |
| 输入设备 | 指定动作由哪个设备提供 | 不同设备分别承担位置、朝向或工具操作 |
| 输入形式 | 区分离散按钮与连续量 | 按钮触发动作，摇杆或扳机提供连续输入 |
| 正负方向 | 指定一对相反的人类操作方向 | 用两个按钮控制前进/后退或张开/闭合 |
| 方向反转 | 交换当前绑定的动作方向 | 保持设备原始数据不变，调整操作习惯 |
| 位置来源 | 提供跟踪空间位置 | 用于接管后的相对位移 |
| 姿态来源 | 提供设备自身朝向 | 按空间页配置转换为圆弧或工具旋转 |
| 反馈来源 | 接收机器人负载反馈 | 使用支持的设备振动能力表达夹持变化 |

配置页面展示动作名称及方向语义，便于核对同一按钮在系统中实际代表的操作。多个输入设备可以参与同一套绑定，但位置、姿态和反馈的来源仍分别可见，不将组合输入显示为一个无法追溯的匿名设备。

### 输入测试与控制接管的区别

输入测试用于观察原始能力和绑定结果；控制接管用于建立之后的相对操作关系。测试设备按钮是否工作，不等于已经生成机械臂规划任务。机械臂实际运动还需经过空间转换、控制模式和运动节点。

模拟输入可以验证按钮与轴到动作的映射，适合没有外接控制器时检查软件配置。它只替换输入来源，不增加另一套空间变换或执行规则。页面会展示模拟输入状态，避免与实体设备采集混淆。

对于跟踪设备，原始位姿诊断保留绝对位置和朝向；对于常规手柄，按钮和轴诊断保留设备实际值。这样可以分别检查设备采集、动作绑定和空间输出，明确偏差发生在哪一层。

## 空间

统一处理跟踪坐标、操作者空间与机器人坐标之间的关系，避免在输入适配器、运动和执行层重复转换。

### 坐标与相对控制

| 功能 | 支持内容 |
| --- | --- |
| 坐标轴映射 | 配置输入坐标到前、左、上控制坐标的映射矩阵 |
| 接管原点 | 以接管时的位置和姿态建立相对控制基准 |
| 平移比例 | 调整输入位移与机器人位移之间的倍率 |
| 位置与朝向分离 | 分别处理空间位置变化与设备自身姿态变化 |
| 无绝对位置输入 | 根据配置的平移速度积分按钮、轴输入 |
| 无绝对姿态输入 | 根据配置的圆弧角速度处理相对控制 |
| 配置管理 | 保存空间映射；编辑时可恢复已保存的映射 |

### 姿态语义与运动分量

支持独立启停以下分量：

- 底座坐标平移。
- 垂直圆弧、水平圆弧。
- 工具定点垂直旋转、定点水平旋转。
- 工具轴向旋转。
- 工具轴向平移。
- 工具轴向螺旋运动。

设备垂直姿态可映射为垂直圆弧或工具定点旋转；水平姿态可映射为水平圆弧或工具定点旋转。位置运动与末端朝向变化具有明确区分，可按控制需求组合。

### 空间可视化

- 展示人体空间、设备自身姿态与转换结果。
- 显示前后、左右、上下的相对变化，以及圆弧控制量和当前控制状态。
- 提供空间配置、转换位姿和相对运动消息的诊断视图。

### 三类坐标关系

空间控制区分跟踪坐标、操作语义和机器人坐标。跟踪设备报告的位置用于描述设备在自身跟踪系统中的状态；“前、左、上”是操作方向；机器人运动则需要在对应基座或工具坐标中解释。三者之间通过显式映射关联。

| 概念 | 表达内容 | 不应混同的概念 |
| --- | --- | --- |
| 跟踪绝对位姿 | 输入设备在跟踪系统中的位置与朝向 | 机械臂的绝对 TCP 目标 |
| 接管参考位姿 | 开始相对控制时的输入基准 | 机械臂默认位或工作位 |
| 相对平移 | 相对参考位置的位移，经换基与比例转换 | 直接将设备米制位置写入机器人 |
| 圆弧控制 | 改变末端空间位置的角向运动语义 | 在固定位置改变工具自身朝向 |
| 工具旋转 | 绕工具相关轴调整末端姿态 | 两侧夹指的张开或闭合 |
| 工具轴向平移 | 沿当前工具方向产生位移 | 固定沿基座竖直方向移动 |

接管参考使控制器放置位置与机器人工作位置解耦。平移倍率只调整位移量级；轴映射调整方向关系；姿态语义决定旋转输入如何影响机器人。不同配置项分别承担不同作用，便于逐项核对。

### 空间参数与反馈核对

坐标映射支持直接编辑矩阵，并保留恢复已保存配置的入口。各运动分量的开关不会修改底层设备采集数据，而是在转换阶段决定哪些分量参与输出。未启用的自由度不会因另一个分量变化被隐式加入控制。

有绝对跟踪位姿时，输出围绕接管原点计算；仅有按钮或轴时，输出依据配置速度和输入状态形成相对变化。两种输入方式经过同一空间模块，最终由运动层处理机器人可达性与实际动作。

空间页的模型视图和数值视图用于比较输入、映射与输出。它们表达控制空间的变化，不等同于真实电机已经完成运动；实际到达情况由运动和执行页的反馈确认。

## 感知

集成相机采集、外参标定、分割、三维场景与 AI 任务编排。相机与标定独立分区，AI、分割和抓放入口在统一工作区内组织。

### 相机采集与设备配置

| 功能 | 支持内容 |
| --- | --- |
| RGB-D 采集 | 彩色图、深度图、相机参数与同帧元数据 |
| 深度对齐 | 由采集层调用相机 SDK，将深度对齐到彩色图像平面 |
| 动态流配置 | 选择设备报告的分辨率、像素格式和 FPS，不固定单一相机规格 |
| 彩色/深度流选择 | 分别查看和选择两路流配置 |
| 不可用配置展示 | 保留不可用选项并显示状态，不直接从列表移除 |
| 采集/上送频率分离 | 高帧率采集与低频感知可独立配置，实时视频不绑定感知上送频率 |
| 驱动扩展参数 | 通过统一页面展示和修改 RealSense 专属参数 |
| 相机生命周期 | 刷新列表、选择、保存并启用、重置和停用 |
| 持久配置 | 相机 profile 与已应用标定按设备身份保存，支持重新启用后复用 |
| 实时监控 | 活动流、实测 FPS、设备缺帧、主动略过帧、最近帧序号及错误状态 |

彩色视频支持浮动、拖动与收起；静态图像提供刷新入口。页面同时展示深度尺寸与编码、坐标系、内参、畸变、投影矩阵、深度比例和外参。

采集数据以同帧 RGB-D、内参、时间和外参快照关联传递。原始相机采集不依赖 ROS 相机驱动。重启后需要重新选择启用相机，已保存的 profile 和标定不因此丢失。

### 流配置与运行状态

相机支持的 profile 与当前运行的 profile 分开展示。前者来自驱动能力枚举，后者来自实际启动结果。页面可用于核对所选分辨率、格式与帧率是否已经应用，而不是只显示表单里的待保存值。

| 状态 | 用途 |
| --- | --- |
| 可选彩色/深度流 | 查看设备报告的规格组合与可用状态 |
| 活动流 | 核对实际启用的尺寸、编码和 FPS |
| 采集 FPS | 观察设备侧实际产出速率 |
| 上送 FPS | 观察进入感知链路的实际频率 |
| 设备缺帧 | 区分采集侧未获得帧的情况 |
| 主动略过帧 | 表示按上送频率策略未发布的采集帧 |
| 最近帧序号 | 检查数据是否持续更新 |
| 相机错误 | 显示启动、采集或配置操作的实际问题 |

高帧率采集与低频感知由同一个相机节点管理。待上送 RGB-D 帧进入深度对齐与消息封装，实时彩色预览使用独立节流；不增加第二个相机节点，也不要求模型跟随视频帧率运行。

厂商专属参数通过带有驱动与传感器信息的参数描述展示，保留具体设备的能力差异。参数配置仍属于相机服务，下游分割、场景与运动模块接收统一观测，不需要针对 RealSense 单独分支。

### 图像格式与三维尺度

彩色链路使用 RGB 约定，设备格式在采集边界解码；需要 BGR 的 OpenCV 编解码接口只在边界转换。灰度检测按 RGB 输入解释，深度 Z16 数据不参与颜色通道转换。浏览器预览将 RGB 数据转换为显示需要的 RGBA。

深度值通过设备报告的深度比例转换为米。三维反投影使用与深度对齐图像平面一致的内参，之后通过外参转换到机器人底座坐标。改变相机 profile 时，需要核对的是对应流的内参与编码，而非沿用另一分辨率的固定参数。

RGB 图中的像素位置、深度测量和机器人空间坐标是三个不同层次。模型输出的二维框不会直接作为机械臂坐标；只有通过同帧深度与标定恢复的三维结果才能进入机器人目标选择。

### ChArUco 外参标定

- 固定相机相对机械臂底座的外参求解。
- 按型号预设姿态自动执行工作位、逐姿态采样、求解和返回工作位。
- 采图时获取新的实际电机反馈，通过正向运动学计算末端位姿。
- 使用实际反馈角度，不把下发目标角度当作采样时真实姿态。
- 可配置字典、格数、单格尺寸、Marker 尺寸和实测板宽板高。
- 展示阶段、姿态编号、样本数、采样等待状态与求解结果。
- 提供整体平移拟合 RMS、最大残差，以及逐样本平移/旋转残差。
- 确认应用后持久保存，页面保留上次标定数值。
- 支持重新标定与取消；新结果确认前保留已应用外参。

### 标定流程与结果解释

自动标定由相机节点管理流程状态，运动服务负责姿态执行，实际电机反馈用于计算机器人末端位姿。各模块的职责在采样过程中保持不变，不由前端自行计算或替代机器人状态。

| 阶段 | 处理内容 | 页面反馈 |
| --- | --- | --- |
| 准备 | 确认相机、标定板参数与型号姿态序列 | 相机来源、板参数和姿态数量 |
| 工作位 | 发起并等待工作位运动 | 运动与当前流程阶段 |
| 姿态采样 | 逐组运动、等待、采图和读取新的实际反馈 | 姿态编号、采样等待原因与样本数量 |
| 外参求解 | 联合图像观测与实际末端位姿求解 | 求解状态、拟合与残差 |
| 返回工作位 | 求解后执行回位 | 回位状态 |
| 确认应用 | 保存本次结果到对应相机配置 | 已应用参数与重新标定入口 |

“实际反馈参与采样”表示使用本次请求获取的新电机反馈，而不是命令目标；它不表示相机曝光和总线回读已经实现硬件触发同步。图像时间、反馈时间和流程状态仍分别保留，便于分析测量条件。

拟合 RMS 描述整体样本一致性，最大残差反映最偏离的样本。逐组平移与旋转残差用于检查特定姿态的观测质量。上述指标是本次求解的一致性度量，不等同于机械臂在整个工作空间内的绝对定位精度。

标定板的几何尺寸、安装方式、相机与底座之间的固定关系会影响外参使用条件。相机启用配置可复用已保存结果，但安装关系发生变化后需要重新标定。页面同时提供内参、畸变、投影与外参信息，便于区分成像参数和相机安装参数。

### 分割与人工标注

| 方式 | 支持内容 |
| --- | --- |
| 提示词分割 | YOLOE 文本提示、参考图与视觉提示框 |
| 自动分割 | 无提示词模型的目标检测与分割 |
| 人工标注 | 在原图框选目标或放置区，保存名称与像素范围 |

三种方式可单独使用或组合，分别具有运行、清除与折叠入口：

- 运行一个模型只替换该来源的结果，保留其他模型与人工标注。
- 人工区域支持编辑、删除和保存，不要求重跑分割模型。
- 全部结果在同一张原图上展示框和标题，避免整图染色遮挡图像内容。
- 点击标题查看来源、模型置信度与实例详情。
- 人工标注保留人工来源；手动编辑图不叠加其他模型的框。
- 分割使用固定观测帧，框坐标对应原始图像尺寸。
- 载入新帧后更新观测，旧三维结果和候选不再作为新场景的结果使用。

### 提示配置与结果来源

提示词定义模型需要识别的对象描述；放置区域角色用于下游解释结果，不作为另一组输入词隐式参与模型推理。提示配置保存和模型执行是独立操作，修改描述不等于已经生成新结果。

视觉提示支持参考图与图像区域，适用于文字不易准确描述的目标。人工标注则直接提供所选像素范围，不会伪装成模型输出，也不会产生虚构的模型置信度。

| 操作 | 更新内容 | 保留内容 |
| --- | --- | --- |
| 运行提示词分割 | 当前固定帧上的提示词模型结果 | 自动模型结果、人工标注 |
| 运行自动分割 | 当前固定帧上的自动模型结果 | 提示词结果、人工标注 |
| 保存人工标注 | 人工区域、名称与像素框 | 两类模型结果 |
| 清除某一来源 | 该来源的分割结果 | 其他来源，不禁用模型能力 |
| 三维定位 | 对现有二维实例生成三维结果 | 固定观测与分割输入 |
| 载入新分割帧 | 新观测及其后续结果 | 已保存模型配置与相机配置 |

结果查看区与人工编辑区承担不同职责：前者汇总全部来源，后者只处理人工标注。点击结果标题查看详情时，模型名称、来源和实例信息共同说明该对象的形成过程；框的位置始终以原图像素坐标解释，显示缩放不会改变原始标注范围。

### 三维定位与抓取推理

- 二维分割与三维定位独立触发；仅分割时无需连接机械臂或完成外参标定。
- 使用分割对应的同帧深度、内参和外参进行三维定位。
- 输出实例位置、空间范围和目标点云，并保留场景与观测关联。
- 三维定位复用已有分割结果，不重复运行分割模型。
- 使用 GraspGenX 生成目标的夹爪抓取候选，场景几何参与后续碰撞处理。
- 为运动层提供目标、放置区域、候选姿态与绑定观测的完整场景点云。
- 手动抓放仅需选择抓取物、放置区并启动；页面跟踪候选准备、规划和执行状态。

### 抓取推理与场景几何

感知计算将目标点云与非目标环境点云区分处理，并使用当前机械臂对应的夹爪资产生成与筛选抓取提议。RGB 图像用于上游分割；当前抓取模型本身使用点云与夹爪几何条件，不将 RGB 颜色直接作为抓取网络输入。

环境预筛选使用场景点的距离关系，减少明显贴近环境的提议；相近姿态按夹爪几何位移聚类，保留代表候选及其原始模型分数。返回候选数量与模型内部探索数量具有不同含义，候选压缩不等同于重新生成一个平均姿态。

感知层不替代机械臂求解。模型分数描述模型对抓取提议的评价，不保证该姿态在当前底座、关节范围和场景中可达。最终方案还需经过运动层的 IK、全机械臂碰撞与完整路径检查。

场景几何保留两个用途：实例点云描述抓取对象，环境点云描述周围障碍。目标的观测范围用于后续附着体描述；环境通过 Octomap 进入规划，不将其他物体一律转换成填满内部空间的实心盒。几何来自实际观测，其完整程度受遮挡、深度质量和分割结果影响。

### 多模态 AI 与工具调用

通用模型通过 OpenAI 兼容的 Responses API 接入，由 Next.js 服务端通过 AI SDK 调用。模型编排平台工具，运动学与轨迹生成仍由机器人模块承担。

| 工具类别 | 可调用能力 |
| --- | --- |
| 机器人状态 | 实际关节、TCP、夹爪负载、连接状态及型号信息 |

| 图像观察 | 获取新 RGB 图像、载入固定分割帧 |
| 感知处理 | 分割、图像框选、三维定位与抓取候选生成 |
| 抓放任务 | 选择目标与放置区域，发起任务并跟踪结果 |
| 机械臂运动 | 工作位、关节目标、绝对 TCP 与相对 TCP 动作 |
| 夹爪操作 | 开合控制与持续夹持目标设置 |
| 任务管理 | 查询请求结果、取消指定任务 |

交互与配置支持：

- 直接读取系统相机图像，无需下载后重新上传。
- 在对话中添加参考图片。
- 多轮上下文、历史会话选择与新建会话。
- 用户消息、模型回复、工具记录及机器人请求关联持久化。
- 可配置模型服务地址、模型名称与思考强度。
- 模型和思考强度支持下拉选择、手动输入、模型列表刷新与连接能力检查。
- 区分编辑中配置与实际生效配置；密钥仅保留在服务端。
- 展示当前工具、执行阶段、请求编号、耗时与最终结果。
- 支持停止 AI 与当前动作。
- 通用 AI 模型选择不影响提示词、自动和人工分割的独立可用性。

例如，“查看当前画面”“沿工具自身方向前进 1 厘米”和“把紫色海绵放到中心区域”分别对应观察、相对运动与完整任务。它们使用同一工具体系，不要求为每个场景编写专用脚本。

### AI 会话与机器人请求的关联

一次用户消息可以包含多个工具调用，也可以只读取状态。会话、模型调用、工具调用与机器人请求分别有自己的记录；界面将这些信息关联展示，而不是把所有内容合并成一段无法区分阶段的文本。

| 记录 | 主要内容 | 作用 |
| --- | --- | --- |
| 会话 | 连续用户消息、模型回复和历史上下文 | 支持多轮沟通与返回历史会话 |
| 当前运行 | 使用的模型、思考配置、运行状态 | 说明这一轮对话的处理过程 |
| 工具调用 | 工具名称、输入、结果与错误 | 查看模型实际使用了哪些平台能力 |
| 机器人请求 | 请求编号、阶段、动作结果 | 跟踪真实运动或感知操作 |
| 图像引用 | 本轮观察或用户提供的参考图 | 关联模型判断与对应画面 |

模型的文字回复与机器人任务终态分别处理。模型结束回复不代表机械臂已经完成动作；任务已受理也不代表物体已经被抓住。工具可以查询原请求，AI 可在获得结果后继续解释，用户也可以从手动页面核对同一请求。

通用模型配置与本地感知模型配置互相独立。更换 Responses 模型、思考强度或服务地址，不会自动改写 YOLOE 的类别词，也不会停用手动分割。具备视觉与工具调用能力的模型服务可以承担任务编排，本地机器人能力保持原有接口。

任务文本与所使用的图像会发送到配置的模型服务，API 密钥只在服务端使用。模型服务可以部署在本地网络，也可以是远程接口；平台不内置订阅账户登录或第三方账户转换逻辑。

## 运动

基于 ROS 2、MoveIt 2、Servo 和 MoveIt Task Constructor，统一处理连续控制、离散运动与抓放任务。

### 目标控制与姿态预览

| 功能 | 支持内容 |
| --- | --- |
| 关节目标 | 编辑关节角度，点击执行后发起运动 |
| 目标草稿 | 滑块编辑不立即驱动机械臂，可恢复当前实际姿态 |
| 双姿态预览 | 实际反馈模型与待执行目标模型同屏显示 |
| 命名目标 | 使用型号定义的工作位等预设姿态 |
| 独立夹爪控制 | 单独执行夹爪目标 |
| 绝对 TCP | 底座坐标系下的位置与朝向目标 |
| 相对 TCP | 支持底座系与工具系的相对平移、旋转 |
| 当前/目标信息 | 对照 TCP 位置、四元数朝向和关节状态 |
| 单次请求配置 | 普通运动可覆盖本次请求的速度等规划配置 |

TCP 是工具中心点；相对目标按任务开始时的实际反馈解析。网页目标模型用于几何预览，可达性与碰撞有效性由规划结果决定。

### 目标表示与运动语义

关节控制适用于显式指定机械臂形态；TCP 控制适用于指定末端在空间中的目标。两种方式共享型号模型，但描述对象不同：关节目标是一组关节变量，TCP 目标是位置和朝向，需要运动学求解后才能得到关节轨迹。

| 目标形式 | 参考 | 适用操作 |
| --- | --- | --- |
| 关节角目标 | 型号的业务关节定义 | 姿态调整、已知关节配置 |
| 命名目标 | 型号定义的预设关节配置 | 工作位等重复使用的姿态 |
| 绝对 TCP | 机械臂底座坐标 | 指定明确空间位置与朝向 |
| 底座系相对 TCP | 当前反馈姿态与底座轴 | 沿固定空间方向平移或旋转 |
| 工具系相对 TCP | 当前反馈姿态与工具轴 | 沿工具朝向接近或调整自身姿态 |
| 夹爪目标 | 工具执行器 | 独立开合，不附带六轴目标 |

位置信息采用米制，朝向使用四元数；网页关节角便于以度阅读，机器人模型和规划使用对应弧度值。角度正负号、零位与 TCP 定义由型号适配统一维护，不在各页面另加软件偏移。

预览模型可以显示几何上定义明确但不可达的目标。规划失败时，实际反馈不会被目标草稿覆盖；恢复当前姿态可重新以真实反馈作为编辑起点。目标、计划与实际值分开展示，便于检查是否执行、执行到哪一步及是否到达。

### 连续控制与完整方案规划

- MoveIt Servo 处理连续相对控制。
- 关节、TCP 离散目标通过运动规划与控制器执行。
- 多个抓取候选参与 IK 与完整任务求解。
- 单个候选 IK 失败不进入执行，仅执行规划成功的完整方案。
- 结合候选质量、姿态变化和运动代价进行完整方案排名。
- 使用夹爪几何和碰撞检查细化接近与夹取深度。
- 连续控制、手动目标与感知任务共用机械臂模型、坐标关系和执行反馈。

### 规划资源与任务调度

机械臂模型、规划插件和规划器资源在运动服务初始化时建立并复用。每次抓放更新任务阶段与绑定场景，不重新启动一套 ROS 或重新加载全部资源。连续 Servo 控制与离散规划任务由同一运动节点协调，离散任务期间不并行发送另一条相对运动链路。

完整方案搜索关注能够完成任务的候选。初步获得完整解后，可在同一候选、同一起点和同一场景上细化深度及接近平面位置；实际执行使用最终选择的一份完整方案，不在接近后另外采一帧、重新选择另一个目标。

这类候选细化属于同一次任务的规划过程，与执行中重新感知、重新规划不同。页面可能展示多个求解阶段，但不会因此执行多次抓放。方案排名也不表示穷尽所有候选后得到数学上的全局最优。

### 抓取姿态与深度处理

候选姿态包含夹爪位置、朝向和模型评分。运动层进一步考虑指尖连线倾角、目标在闭合方向的跨度、目标相对夹爪的位置以及关节运动代价。指尖倾角与夹爪整个张合平面的方向是不同概念，不将夹爪主体固定为与地面平行。

夹取深度优化通过几何变体和完整路径检查寻找更深入的可执行接触位置，而不是用物体 Z 向尺寸直接截断接近距离。更深的候选只有在接近、夹持和后续运输均能形成完整方案时才可替换原方案。

模型环境筛选、末端候选碰撞和整臂路径碰撞位于不同层次。前者减少无效提议，后两者检查特定机械臂与场景下的可执行性，任何一层的通过都不单独等同于物理抓取成功。

![控制模式、规划状态与任务配置](.github/media/motion-planning.jpg)

### 环境碰撞与抓放阶段

- 通过 MoveIt 官方 Octomap 组件使用观测点云建立任务环境快照。
- 同一抓放请求绑定目标、候选与观测，避免场景订阅和任务启动之间的数据错配。
- MTC 按阶段管理目标接触、夹持、附着、运输与释放。
- 持物运输时将目标体积纳入碰撞检查。
- 组织接近、闭合、持物移动、放置释放和返回工作位。
- 放置姿态选择考虑与运输姿态、后续动作的衔接。

### 任务阶段与目标附着

| 阶段 | 机器人操作 | 场景处理 |
| --- | --- | --- |
| 准备 | 根据候选准备夹爪张开姿态 | 使用本次观测建立任务地图 |
| 接近 | 沿候选接近方向运动 | 检查夹爪与整臂路径，按阶段处理目标接触 |
| 闭合 | 进入夹持并启动持续反馈调节 | 将抓取目标附着到工具 |
| 持物回位 | 持物移动到工作位作为中间姿态 | 携带目标体积进行碰撞检查 |
| 运输与释放 | 到放置区域、张开夹爪 | 解除目标附着并处理释放 |
| 返回 | 回工作位并完成工具收尾 | 清理该任务的场景状态 |

抓取目标与其他环境体素分开管理，夹指与目标的必要接触由对应阶段处理；目标不能继续同时以原位置障碍和工具附着体重复参与运输碰撞。环境仍保持本次任务的观测快照，不要求在夹起后持续重发旧点云。

持物脱离支撑面与普通自由运动具有不同接触语义。任务阶段处理已有支撑接触，离开支撑后恢复普通碰撞检查；这不代表整体关闭环境碰撞。释放目标与附着物的空间位置关联，也不应将目标物中心、底面高度和 TCP 高度混为一谈。

### 状态、查询与可视化

- 展示请求编号、当前阶段、完整方案、执行状态和结果码。
- 查看轨迹点数与计划时长。
- 支持按请求编号查询结果，刷新后继续跟踪同一请求。
- 提供任务取消入口，并继续跟踪实际任务终态。
- 展开 MoveIt/Servo 状态、原始请求结果与型号元数据。
- 通过浏览器访问 RViz，检查机械臂模型、点云与规划场景。

## 执行

原生 Rust 执行节点负责 FashionStar 串口驱动、电机控制、实际状态回读与持续夹持调节。

### 连接管理与实际反馈

| 功能 | 支持内容 |
| --- | --- |
| 串口选择 | 设备枚举下拉框与手动路径输入 |
| 连接状态 | 当前端点、连接/断开、异常提示 |
| 实际关节反馈 | 从电机回报角度计算机械臂姿态 |
| 三维反馈 | 展示当前模型、最后命令与工具目标 |
| 命令/反馈对照 | 区分请求目标与电机实际到达值 |
| 反馈周期 | 可配置状态回读间隔 |
| 整臂上力/卸力 | 对全部电机统一操作 |
| 历史数据标识 | 断开后不将缓存遥测作为当前读数展示 |

### 闭环夹持控制

- 按舵机负载反馈持续调节夹持，覆盖闭合后的保持与运输阶段。
- 保持目标与夹爪角度目标分离，显式张开或卸力时退出调节。
- 可配置 0–100 的归一化夹持反馈目标。
- 显示目标、实际负载、控制功率、采样时间与调节状态。
- 该反馈刻度不是牛顿单位；物理抓持效果需结合相机观测判断。

### 模型反馈与工具状态

执行页的实体模型表示实际关节反馈，半透明模型表示最后命令，工具目标和抓放目标具有独立标记。用户可以在同一视图比较期望动作与电机实际状态，不需要根据一段计划动画推测硬件位置。

型号元数据统一提供关节、工具执行器、模型资源和坐标关系。界面通过关节与执行器键关联信息，不根据舵机在列表中的位置推断其机械含义。必要时可以打开关节编号和本次实读参数标注。

实际反馈保留设备报告值；为了运动规划而采用的状态处理不会替代标定所需的原始电机观测。机械臂 TCP、末端结构链接和活动夹指也分别定义，避免在显示、标定与抓取计算中使用不同的工具参考。

![执行连接、实际机械臂反馈与夹持目标](.github/media/arm-execution.jpg)

### 夹持目标、反馈与控制输出

| 量 | 含义 | 用途 |
| --- | --- | --- |
| 夹爪角度 | 工具执行器的位置量 | 表达开合几何状态 |
| 夹持反馈目标 | 归一化的负载目标 | 指定保持阶段的调节目标 |
| 实际负载反馈 | 从新舵机监测数据计算的读数 | 反映当前驱动负载 |
| 控制功率 | 反馈调节使用的动态输出上限 | 随反馈变化调整，不固定为一个常量 |
| 反馈时间 | 本次负载数据对应的采样时间 | 区分新读数与历史值 |
| 调节状态 | 是否处于持续夹持控制 | 与开合命令和运输阶段对照 |

达到目标负载后，控制器继续根据后续反馈调节，不把第一次达到目标的夹爪角度锁存为最终保持位置。改变反馈目标影响后续调节，角度和功率也不会因此被解释为恒定接触力。

摩擦、物体形变、惯性和采样间隔会影响负载读数。负载变化可作为夹持分析的一部分，但系统仍保留相机观察和实际动作结果，不将一个非零读数自动等同于确认抓住。

### 舵机遥测与参数管理

- 读取电机角度、圈数和状态位。
- 读取电压、电流、功率及原始温度读数。
- 读取固件编码、设备信息与驱动支持的配置项。
- 支持可写参数修改，展示单位、用途、可写状态和生效方式。
- 显示参数读取进度、最近读取时间与字段错误。
- 串口查询、回包与写入采用统一调度，避免多个模块并发占用同一通信链路。

### 串口事务与参数生效

驱动对同一串口使用顺序事务：查询发送后等待对应回包，期间保留最新待发运动目标，事务结束后再发送。异步节点调度不等于在物理串口上并发交错多组请求。参数扫描与实时反馈共用调度，可以显示读取进度而不建立第二条串口连接。

公开参数按写入、回读流程核对；内部参数遵循厂商相应写入过程。界面提供参数帮助和生效方式，区分即时可读、即时生效与需要重新上电后生效的设置。回读一致只说明写入结果，不替代需要重启的生效条件。

断开连接后，待发目标被清理；重新连接不会重放断开前积压的旧动作。全部上力以当前反馈位置建立保持，不自动回到上一次命令目标。真实端点已选择但不可用时展示连接错误，不切换为模拟执行结果。

## 统一数据链路与持久化

- 相机观测以 CameraFrameBundle 关联 RGB-D、内参、时间与外参快照。
- 三维场景通过 WorldScene 关联实例、候选与二进制点云，避免将大体积 XYZ 展开为网页 JSON。
- 空间变换、感知编排、运动规划和执行反馈各有明确所有者，不在前端重复实现机器人算法。
- 设备配置、空间映射、相机 profile 和已确认标定由所属服务持久保存。
- Redis 保存机器人请求和 AI 会话元数据；会话图像独立存储，不把图像或点云塞入请求状态。
- 前端、AI 与执行反馈通过同一请求标识关联受理、规划、执行和终态。
- 软件任务完成、夹持负载反馈与视觉确认分别呈现。

### 请求生命周期

| 状态层次 | 表达的事实 | 不代表什么 |
| --- | --- | --- |
| 请求登记/受理 | 系统已接收并关联请求编号 | 规划已经成功 |
| 准备与规划 | 正在生成候选、构造任务或求解 | 电机已经开始运动 |
| 执行 | 控制器正在执行选定方案 | 物体已经可靠夹持 |
| 软件终态 | 对应任务返回完成、失败或取消结果 | 视觉上已确认最终物理结果 |
| 图像与遥测 | 相机画面、实际关节和负载观测 | 单个信号能够覆盖全部物理状态 |

网页按同一请求编号关联状态，不使用另一个任务的旧结果结束当前等待。请求记录支持独立查询，刷新页面只恢复查询，不重复下发原动作。服务重启前尚未完成的记录会保留其不确定性，不自动推断为成功，也不自动重放。

取消请求与最终取消结果分开处理。系统向对应任务请求取消后继续等待实际控制器反馈；取消不会隐式打开夹爪或移动到另一姿态。持物相关场景也不应在尚未释放时直接假定已经清空。

### 模块边界与扩展

输入设备差异归属输入适配器，相机 SDK 与标定归属采集服务，视觉权重与夹爪推理资产归属计算服务，机器人运动学与 ROS 依赖归属型号运动节点，串口协议归属执行驱动。前端负责编辑、调用与展示，不保存第二套运动学规则。

大体积图像和点云与小型状态消息分开处理。网关向页面提供状态流和按需资源，请求历史保存结果与引用，不承担图像总线。实时视频与感知取样也分别控制频率，避免界面观看需求迫使模型按视频帧率运行。

模拟器提供正式契约下的测试输入，使用相同的空间转换、模型信息和运动/执行流程。新增硬件时需要实现适配并验证其能力声明；通用功能不因设备不同而维护两套业务链路。

## 技术组成与当前硬件

| 层 | 主要组件 |
| --- | --- |
| 操作界面 | Next.js、React、Three.js |
| AI 编排 | AI SDK、OpenAI 兼容 Responses API |
| 节点与消息 | Rust、Dora、Arrow |
| 相机与图像 | librealsense、OpenCV |
| 视觉模型 | YOLOE、GraspGenX |
| 运动规划 | ROS 2、MoveIt 2、Servo、MTC、Octomap |
| 状态存储 | Redis、服务持久配置与会话图像存储 |
| 部署 | 按服务拆分依赖与运行环境的 Docker 镜像 |

当前硬件为 StarArm-102 六轴机械臂、RA8-U35H-M 舵机和 RealSense D415，输入适配器支持 SDL3 手柄与 NOLO CV1。其他设备通过适配层扩展，不代表已完成所有型号的适配。

模型权重与运行依赖准备后，本地分割、手动控制和抓放不要求外部大模型服务。自然语言能力需要可用的模型接口，是否访问互联网取决于模型服务的部署位置。

平台面向桌面机器人交互与应用开发。实际效果受深度测量、外参标定、机械间隙、夹爪几何和物体材质影响，不将软件终态等同于物理抓取确认。
