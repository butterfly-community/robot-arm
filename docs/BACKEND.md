# 架构与调用链

本文说明一次操作经过哪些服务、各服务负责什么，以及哪些参数会改变抓放结果。
部署方法见 [Docker](DOCKER.md)，电机角度、夹爪尺寸和真机精度见[型号说明](STARARM-102.md)。

## 从操作到执行

深度相机抓放依次完成以下步骤：

1. 相机节点采集彩色图和深度图，并提供相机参数、已应用的标定结果。
2. 场景节点调用分割模型或读取手动框选，从深度图中计算物体和放置区的三维位置。
3. GraspGenX 根据目标点云、环境点云和夹爪模型生成候选抓取姿态。
4. 运动节点使用 MoveIt/MTC 查找能够完成接近、夹取、运输和释放的整段运动方案。
5. 执行节点发送舵机命令，并回传实际关节角和夹持负载。网页跟踪同一个请求，显示进度和最终结果。

抓放请求同时携带生成目标时使用的场景数据。因此，本次规划不会意外使用随后采集的另一帧点云。

未选择深度相机时，AI 读取外部或腕部普通摄像头的图像，通过已有的关节、末端运动和夹爪工具
逐步完成抓放。这种方式不运行深度重建或 GraspGenX，也不会仅凭相机绑定生成三维坐标。
两种方式共用相机服务、运动节点和执行节点；AI 与手动操作调用相同的业务接口。
模拟输入只替换数据来源，仍经过正式的坐标转换、运动学和执行流程。

### 常用术语

| 名称 | 本项目中的含义 |
| --- | --- |
| TCP（工具中心点） | 用来指定夹爪位置和朝向的参考点；本型号位于两指尖之间。不是夹指转轴。 |
| FK / IK | FK 根据关节角计算末端姿态；IK 根据期望末端姿态求关节角。IK 有解不代表整条运输路径可行。 |
| MTC | MoveIt Task Constructor，将接近、闭合、运输等阶段组成一个完整任务并规划。 |
| 相机内参 / 外参 | 内参描述三维点怎样投影到图像上，包括焦距、图像中心和畸变参数；外参描述相机相对机械臂的位置和朝向。 |
| 场景快照 | 某次观测得到的物体、放置区和环境点云。本次抓放固定使用这份数据，不持续更新障碍地图。 |
| 物体附着 | 在规划场景中将物体关联到夹爪，使物体参与后续运输碰撞检测；不表示传感器已证实抓住实物。 |
| OBB / Octomap | OBB 是随物体方向旋转的包围盒；Octomap 将环境点云划分为空间小格，用于碰撞检查。 |

## 请求状态与运动接口

网页和 AI 都通过 HTTP 网关向负责该功能的节点发送请求。Redis 保存请求记录和 AI 会话信息，
不保存图像或点云本体。

| 页面结果 | 表示什么 |
| --- | --- |
| 已受理 | 请求已登记，可能仍在排队；不是已经运动。 |
| 规划成功 | 找到了可执行的路径；尚不能据此判断实物抓取成功。 |
| 执行成功 | 控制器报告本次动作完成。物体是否夹住、搬运到位仍需图像或人工确认。 |
| 失败 / 取消 | 该请求已经结束，并保留错误或取消结果。 |
| `unknown` | 服务重启前的请求未取得最终结果；不能推断机械臂已停止或动作已成功，也不会自动重做。 |

下文把成功、失败、取消统称为请求的“最终状态”。运动和抓放页的“请求结果”按请求编号查询，
刷新页面只恢复查询，不重新执行。

### 请求登记与取消

`forward_value` 在下发前用 Redis `SET NX` 登记 `request_id`，重复编号返回 409，不重放动作；
无法登记时返回 503，尚未下发。`RequestHistory::observe` 将节点反馈送入异步写入队列，
`update_record` 区分受理、规划、执行及最终状态；后续反馈不覆盖已确认的最终结果。
`GET /api/requests/{request_id}` 查询独立记录，缺失返回 404，存储不可用返回 503。

`/api/motion/cancel` 可携带 `target_request_id`，对应取消排队或活动任务；省略时仅取消普通运动。
规划取消使用 `Task::preempt()`；执行直接使用官方 `execute_task_solution` Action，
由运动节点处理返回结果。取消被受理后仍需等待原 Action 的最终状态，不能据此立即确认停止。
取消不自动张开夹爪或回工作位；若任务已附着物体，保留持物碰撞几何，不假定已经释放。
正在进行的单个求解/服务调用可能先返回，取消受理不是瞬时停止。若执行已先成功，保留成功结果。

### 位置、朝向和夹爪

`MotionRequest.tcp_target` 指定末端目标，`joints` 指定关节目标，两者二选一。
末端位置单位为米，朝向用 `orientation_xyzw` 四元数表示；`relative=false` 表示底座坐标系中的绝对目标。
相对运动以任务开始时的实际电机反馈为起点，通过 FK 得到当前末端姿态，而不是沿用上一条命令值。

| 相对运动坐标系 | 平移和旋转的计算方式 |
| --- | --- |
| 底座 | 平移沿底座的轴向：`p'=p+dp`；旋转为 `R'=dR·R`。 |
| 工具 | 平移沿夹爪当前的轴向：`p'=p+R·dp`；旋转为 `R'=R·dR`。 |

其中 `p/R` 是当前末端位置/旋转矩阵，`dp/dR` 是请求的平移/旋转增量，带撇号的是目标姿态。
`resolve_tcp_target` 得到目标后，调用官方 `compute_ik`、MoveGroup 和控制器。
浏览器的目标预览不执行 IK，因此显示预览不等于机械臂一定能够到达。

`POST /api/motion/preview` 提供只读姿态计算，与执行请求使用相同的关节键、TCP 和坐标规则。
关节目标通过 MoveIt FK 计算预估末端；TCP 目标只换算为底座坐标，不求 IK。
结果包括采样反馈、当前与目标 TCP、位移和旋转变化，以及工具 X/Y/Z 在底座系中的方向。
该请求不切换控制模式、不暂停 Servo、不进入运动队列、不更新实际姿态，也不执行碰撞或路径检查。
AI 的 `move_joints` 直接指定模型关节角，不经过 TCP IK，仍使用 MoveIt 关节空间规划与碰撞检查。
需要调整构型时，可用相同的关节目标先预览、后执行，并对照返回的实际反馈；不直接写舵机协议角度。

未指定 `actuators` 的运动请求不改变夹爪角度。独立开合由 `run_actuator` 排入同一运动队列，
等待 `hand_controller/follow_joint_trajectory` 返回最终结果。夹持负载调节在执行节点中持续运行，
页面分别展示目标力度、实际负载、采样时间和调节状态。

### 图像与反馈的时间

图像保留来源、序号和采集时间；关节反馈保留 `sequence`、`sample_time_ns`、`feedback_source`。
TCP 结果附带计算它所用的那次关节反馈。请求记录的时间仅表示状态写入时间，不是相机曝光或电机采样时间。
这些字段用于辨认数据来源和新旧关系，不代表相机与电机实现了硬件同步。查询结果或读取预览不触发抓放。

## `camera-node`

源码：[节点与标定状态机](../backend/nodes/camera/src/main.rs)、[采集 worker](../backend/nodes/camera/src/capture_worker.rs)。

| 方法 | 作用 |
| --- | --- |
| `capture_worker::spawn` | 启动独立采集任务，接收命令并返回结果，避免相机 SDK 的等待阻塞节点主循环 |
| `refresh` / `select` | 枚举设备的格式、分辨率和帧率，保存用户选择；不使用易变的设备序号 |
| `start` / `stop_capture` / `reset` | 在已有采集任务中开启、停止或重置设备 |
| `tick` / `finish_capture_command` | 处理采集结果，将彩色图、深度图和相机参数一起发布 |
| `bindings::apply` / `tick` | 保存外部和腕部相机的绑定，管理各自的采集任务与在线状态 |
| `video_server::snapshot` | 等待指定相机在本次请求之后采到的新图，连同来源、序号、时间和尺寸返回 |
| `start_automatic_calibration` / `advance_automatic_calibration` | 按预设姿态采样，用实际电机反馈计算末端姿态，求解后回工作位 |
| `poll_calibration_work` / `apply_solved_calibration` | 接收本轮标定结果；用户确认应用后保存外参 |

深度来源启动时发现但不自动选择。外部/腕部绑定按保存的采集开关恢复，设备离线不丢配置。
普通相机 `connect` 开启已保存绑定，`disconnect` 关闭采集并等待释放 USB 设备但保留配置，
`unselect` 才解除绑定。网页与 AI 的 `set_camera_capture` 共用这些请求；带宽不足时轮流开启取新图。
普通 USB 摄像头由 `uvc-camera` 使用 V4L2 枚举并采集，OpenCV 在驱动边界统一为 RGB；
绑定优先保存 by-id，没有序列号时使用物理端口标识，不保存 `/dev/videoN`。
分辨率、帧率来自设备枚举，不预设固定值。同一来源不能同时占用两个角色。
绑定只指定相机用途，不产生内参、外参或深度。采集配置（profile）与已应用外参均保存到正式配置文件。
采集、彩深对齐和标定求解放在 Tokio 的阻塞任务中执行；节点主循环只收发命令和结果。
RealSense 的采集和对齐对象由同一个采集任务管理，只对需要发布的帧执行对齐。
相机采集、发往感知的 RGB-D 数据和网页视频分别控制频率；感知取样降到 1 FPS 不会强制视频也降到 1 FPS。
标定流程为工作位 → 九姿态采图/新电机反馈 FK → 求解 → 回工作位 → 确认应用；
取消或失败不覆盖已有外参。标定、图像、相机参数均由本节点管理。

分割、三维定位、抓取候选独立按请求触发。新帧/配置变化使旧结果失效，
每个请求绑定输入序号；失败不伪造结果，也不暗中重跑上游。
自动、提示词和手动分割可组合，标注保留具体模型 ID 或 manual 来源；
统一结果显示本次分割所用的原图与框，点击标题看详情，手动编辑只显示手动标注。
手动矩形经同一深度重建链路定位，不建立专用抓取路径。
提取物体点云时，用 Otsu 方法从相邻像素的深度差中确定分界，再沿上、下、左、右四个方向
连接深度连续的像素。分界阈值至少为深度格式能表达的一个刻度，不另设物体最小厚度。

| MTC `execute` / `TaskScene::cleanup` | 先找到完整方案，再尝试优化该候选的夹取位置，执行最终方案后清理任务场景 |

只有一个 ROS 工作线程处理这些请求。执行单次运动或抓放任务时暂停手柄连续控制，结束后恢复；
连续控制仅在队列空闲时发送。
Servo 位姿带当前 ROS 时间戳。选定真机端点但断连时明确报错，断连错误不被后续成功覆盖。
取消使用控制器 goal handle，收到真实 ROS 最终状态后才发布 cancelled。
模型和规划器资源启动时初始化一次；每次只构造 MTC 阶段与任务场景。

## 抓放参数

以下列出会改变识别、抓取姿态或运动结果的参数。表中明确区分源码默认值、上游库默认值和用户指定值。
实际部署以 `.env` 和网页已保存的配置为准；文档不另存一份现场配置。

### 图像分割与抓取候选

| 所在方法 / 参数 | 当前值、来源与实际影响 |
| --- | --- |
| YOLOE `predict` | 部署 Ultralytics 8.4.135；文字/自动模式沿用库输入 640、NMS IoU 0.7、最多 300 检测；应用指定 `retina_masks=True`。1920 原图不等于模型以 1920 推理；视觉提示另取原图/参考图最长边。没有应用级 0.18 置信度覆盖。 |
| `scene-core` 深度区域 | 按相邻像素的深度连续性提取物体区域，算法见上文 scene-node。生成的包围盒只描述这次观测到的范围，可能受遮挡或深度误差影响。 |
| 模型采样数 | `GRASPGENX_NUM_GRASPS` 源码默认 200，控制 diffusion 采样数；即使设为 500，也不等于 GraspMoE 最终返回 500 个候选。随机种子在模型初始化时设置，不在每次请求前重置。 |
| OBB 初始姿态 | 使用官方场景的 `dense-topandside`，从包围盒顶部和侧面生成姿态。沿表面外法线采用 -2 cm、0 cm 两档偏移，不增加向外的正偏移。这不改变夹爪资产或 TCP 定义。 |
| OBB 库内默认 | 未覆盖的 GraspMoE 参数为 36 个绕轴角、密集位置步距 1 cm、邻域 20 点/离群距离 14 mm、`advanced` OBB 与 `auto` 跳过规则；这些来自上游，不是应用新增的接近角度/深度门限，但仍影响提议生成。 |
| 夹爪资产 | 张开/中间状态的抓取体积分别为 129×15×20 / 71×15×20 mm，中心 Z=60/80 mm。采样深度约 66.471 mm 来自张开夹指网格前沿，TCP 的 Z 为 93.38 mm。**这些坐标均相对 GraspGenX 夹爪资产的原点**，不是机械臂底座高度，也不是 `link6 → tcp_link` 的偏移。资产 `standoff=[0,10] mm` 描述模型使用的抓取体积，不是执行时后退 10 mm。 |
| 模型评分 | `grasp_threshold=-1`、`topk=-1` 关闭示例 0.7 截断；保留模型分，不保证低分可抓。 |
| 环境预筛选 | 最多随机 8192 环境点与张开网格 2000 表面点，来自官方示例；是点距离筛选，不是完整连续网格碰撞保证。 |
| 环境距离 | 官方/源码默认 20 mm，实际值由网页 `grasp_collision_distance_m` 持久配置决定；是拒绝近邻候选的距离，不是允许穿透地面 5 mm。 |
| 夹爪自身点的剔除 | 模型和 ROS 共用 `self-filter.json`：删除距夹爪网格表面 **40 mm** 范围内的环境点，避免把夹爪当成障碍。该范围内的其他物体点也可能被删掉；这不是 TCP 偏移或障碍膨胀距离。 |
| 返回候选 | 用户指定最多 100；CAD 角点距离聚类、每组保留原始最高分，不重新生成姿态。 |

### 接近、夹取深度与路径规划

“接近距离”是从预抓取位置走到抓取位置的距离；“夹取深度”是物体进入两指之间的程度。
两者由不同步骤处理，增大接近距离不等于夹得更深。

| 所在方法 / 参数 | 当前值、来源与实际影响 |
| --- | --- |
| 接近 `MoveRelative` | 从抓取终点反向寻找预抓取位置，由碰撞检测和 IK 决定能退多远，不按物体高度截断。搜索范围取机械臂模型覆盖半径 R 的两倍，使搜索线段覆盖可达范围；不写死一个接近距离。这一步不决定夹取深度。 |
| 抓取 `ComputeIK` | 不做应用级 8 解截断，使用接口整数容量上界，仍受原生时间预算控制；设 0 会完全不搜索。部署厂商组默认超时 **0.005 s**，不是整任务 5 s。 |
| 真正加深搜索 | 沿候选 TCP +Z，0 到观测目标在该方向的远端面；步距来自 Octomap 5 mm，包含端点。此处仍有物体相关的几何搜索范围：防止把整个抓取参考点推进物体背后，不是接近段上限。所有变体须完成碰撞/IK/闭合/运输规划。 |
| 平面位置调整 | 找到可行候选后，额外尝试将其 XY 位置对准物体观测中心，保持原高度和朝向，并保留原始位置作为选择。移动后的姿态没有重新计算模型分数。 |
| 指尖过滤 | 用户指定两指尖连线离水平角小于 20°；不是夹爪本体倾角，也不是强制顶部抓取。 |
| 搜索与排名 | 先用 `plan(1)` 找到首条完整方案，再对选中候选的有限组位置用 `plan(0)` 搜索改进。成本为 `(1-模型分)+(投影夹持跨度+夹取偏差)/对象对角线`，越小越优；成本相同时比较指尖等高程度和归一化关节行程。公式各项见下节。 |
| ROS 场景 | Octomap 每格 5 mm，普通碰撞形状外扩 2.5 mm。为去掉目标在点云中的重复占用，临时将目标过滤形状每面扩大 5 mm，过滤后恢复观测尺寸。地面顶面为底座坐标系 Z=0，水平尺寸 2×2 m、厚 1 m；不允许固定的地下穿透量。 |
| 允许接触 | 用 MoveIt 的允许碰撞表（ACM）允许夹指接触目标。持物离开支撑面时允许起始已存在的接触，但不能继续压入；回到工作位后恢复检查。其他障碍仍参与碰撞检测。 |
| 放置 | 物体中心释放 Z 为 `max(目标 Z, 0.05 m)`，相对场景 Z=0 的下限为 5 cm；不是目标上方偏移或物体底部净空。XY 为目标中心，位置容差继承库 0.1 mm，姿态自由。 |

### 速度与夹持反馈

| 所在方法 / 参数 | 当前值、来源与实际影响 |
| --- | --- |
| 运动 | 速度缩放 0.125、闭合 0.0625，来自用户多次降速；不另设加速度缩放，继承规划器默认。型号最高关节速度仍是用户指定 34 rpm。 |
| 保持力度 | 目标由执行页持久配置决定，是监测功率换算负载刻度，不是牛顿。400 mW 零负载、2000 mW 满刻度/指令上界；30 对应 880 mW 只是调节目标/初始估计，实际输出随新反馈动态积分，不锁角、不固定 880 mW。 |
| 执行反馈 | 默认每 100 ms 回读一次。力度调节按采样间隔和单条舵机命令的 100 ms 运动时间计算调整幅度。输出最小编码为 1 mW，因为厂商协议的 0 表示最大功率。轨迹执行完成后仍需图像或人工核对物体搬运结果。 |


## MTC 模块边界

| 模块 | 责任 |
| --- | --- |
| `pick_place_server.cpp` | 接收抓放请求、报告进度、组织方案搜索和夹取位置优化，执行后清理任务 |
| `task_factory.hpp` | 将 MoveIt 原生阶段组合为完整抓放任务 |
| `task_scene.hpp` | 发布点云并确认地图已更新，去掉目标的重复点云占用，恢复目标尺寸并清理任务地图 |
| `grasp_candidates.hpp` | 生成不同深度和位置的候选，对完整方案评分排序并缓存结果 |
| `planner_adapters.hpp` | 检查规划器返回的轨迹，处理离开支撑面和自由朝向的放置目标 |
| `planning_resources.hpp` | 初始化并复用模型、插件和规划器 |

实际执行顺序是：张开夹爪 → 接近 → 闭合 → 持物回工作位 → 运输到放置区并释放 → 回工作位并闭合。
闭合后，规划场景将目标关联到夹爪；释放后解除关联。

规划分两步，但机械臂只执行一次最终方案：

1. 从候选中找到一条能完成全部阶段的方案。只有 IK 有解但后续运输失败的候选不会执行。
2. 保持起始状态和地图不变，对选中候选尝试不同夹取深度，以及 XY 对准观测中心的位置。
   在完整路径可行的前提下选更深的夹取；深度相同则选较短的关节行程。没有改进时保留原方案。

整个过程不在抓取中途重新拍图或更换目标。它优先找到可执行方案，不保证遍历所有候选得到全局最优解。

排名中的“投影夹持跨度”是物体 OBB 沿夹爪闭合方向的宽度，用于比较抓取长边和短边所需的开口。
“夹取偏差”根据物体观测中心在 TCP 坐标系中的 `(x,y,z)` 计算：`sqrt(x²+y²+max(z,0)²)`。
横向偏离中心会增加成本；中心已进入指尖后方（z≤0）时，不因继续深入而增加这一项成本。
两项长度都除以物体包围盒的对角线长度，再与 `1-模型分数` 相加。它们是几何评分，不是实际接触测量。

环境使用一次观测建立的 Octomap。抓取目标单独建模，以便随夹爪移动；其他物体仍保留点云形状，
不全部替换成实心盒。释放位置指定的是所持物体中心，不是 TCP。
TRAC-IK 的 Distance 模式求解允许自由朝向的位置目标，完整运输路径仍由规划器检查。

## RGB、图像与视频

彩色图在服务之间统一使用 RGB。相机驱动按设备实际格式和每行字节数（stride）解码，
RealSense SDK 将深度图对齐到彩色图。Z16 是 16 位深度数值，不按彩色图片处理。
OpenCV 灰度计算使用 RGB2GRAY；仅在需要 BGR 的编码/解码边界转换，检测原图不预模糊。
浏览器使用 @thi.ng/pixel 将 RGB888 转 Canvas RGBA。实时彩色视频与低频上送 RGB-D 独立节流，
同一 camera 节点发布，不增加视频节点；网页入口转发，浏览器按 depth/external/wrist 分别订阅。
每个浮窗收到首帧后才出现，可独立拖动/收起；断流清除旧画面并提示，解除绑定隐藏浮窗。
`/api/camera/snapshot?role=external|wrist|depth` 返回 PNG，`x-camera-frame` 携带同帧元数据。
快照等待请求后的下一帧，不读取感知缓存；不同角色独立采集，不承诺同步双目。

## 网页与配置归属

五个 Next.js 应用共用 UI 组件和消息格式。关节滑块只修改待执行目标，点击执行才发送运动请求。
模型预览显示当前姿态和待执行姿态，但不预先保证目标可达。

AI 栏目包含自动、提示词、手动分割，以及可折叠的抓放操作。
分割结果使用选定的那帧图像，实时视频更新不会替换它。已应用的相机标定显示保存值，
通过“重新标定”开始新的采样，避免普通开始按钮覆盖原结果。

设备配置保存到 `backend/config/runtime`；网页保存失败时保留待保存内容，`temp/` 不存正式配置。

| 配置 | 保存配置的节点 |
| --- | --- |
| 输入设备与按键绑定 | controller-input |
| 相机来源、外部/腕部绑定、采集参数、外参标定 | camera |
| 分割模型与提示词 | scene |
| 串口、反馈频率、夹持力度 | execution |
| AI 服务地址、模型、思考强度 | Next.js 服务端写入 Redis |

通用 AI 在 Next.js 服务端，使用 AI SDK 的 OpenAI Responses provider。模型可看图、回答或组合
已有工具，不固定为抓放流程。深度抓放复用手动按钮的 startPickPlace；未选择深度来源时，
AI 通过 `observe_camera(role)` 读取外部/腕部图像，组合已有关节/TCP、夹爪与力度工具，
不调用深度重建或 GraspGenX，不复制运动实现，也不将像素坐标伪装成三维坐标。
`ai/prompts.ts` 按本轮开始时是否选择深度来源装配两份提示词；信号暂时断开不切换流程。
两份提示词共用工具权限、坐标单位、结果判断和任务结束步骤。
纯视觉提示词要求所有阶段优先采用能明显纠正偏差的调整，不因靠近目标就默认微小动作；
接近目标后频繁 IK 失败时，优先预览并直接执行关节目标调整构型。步长与朝向不写死，
后续对话沿用已确认的方向和动作效果，每轮工具调用前说明观察和动作意图。
正常完成抓放后释放、撤爪、回工作位，再取新图核对结果；
用户取消任务时不会自动开爪或回位。
网页保留原有栏目和操作，顶部提示当前是否选择深度相机；纯 RGB 绑定本身不提供三维定位。
地址、模型、reasoning effort 在 AI 配置中保存到 Redis；.env 提供初始默认值和仅服务端可见的密钥。
本地分割、候选、规划和执行不依赖外部 AI 服务。

### 跨会话经验

经验保存在现有 Redis 的 `robot-arm:ai:experiences`，复用 AOF 与持久卷，不放在 `temp/`，
不增加模型服务、向量数据库或训练流程。同一会话保留完整历史；新会话按机械臂模型、
深度／纯视觉模式及反馈来源加载经验目录，详情由 `recall_experience` 按需读取。

机器人请求返回失败时，应用自动保存工具、参数、错误和来源编号；同类错误合并，原调用仍在会话中。
抓空、滑脱等视觉判断由 AI 用 `save_experience` 补充，更新已有经验可保留其来源并修正结论。
记录区分自动失败事实、待验证推测、AI 判断有观测支持、AI 判断被推翻；控制器成功不会自动变成抓取成功。
证据编号引用本次任务已完成的工具调用，用户纠正可直接关联本次任务。此处的“学习”是经验检索与修正，
不是模型权重更新，也不自动修改运动参数、标定或提示词。换相机布局、物体或标定后仍须核对适用条件，
历史坐标不能直接当作当前目标执行。

AI 下方的“任务经验”可查找、查看来源、刷新和删除。删除只移除经验库条目，不删除历史任务，
不能撤回运行中模型已读到的内容；后续新失败仍可产生新的记录。
自动读取目录或归档失败时显示任务警告；AI 经验工具的读写失败显示在工具错误中。
这些错误不掩盖原动作结果，也不触发动作重放。

### 对话如何保存和继续

Responses 请求使用 `store:false`。完整消息记录保存在本地，图片文件保存在持久卷，消息通过文件引用关联图片，
后续对话不依赖供应商保存的会话。写入图片时先完成文件写入，再使它可被消息引用，避免读到半张图片。
文件名根据图片内容生成，相同内容无需重复存储。

发送给模型时保留各相机最近两帧，旧图仍留在本地，通过 `recall_image` 调回；这不是删除历史会话。
缺失图片会明确报错，不拿当前图替代。清理文件前必须检查是否仍被消息或运行记录引用，不能仅按时间删除。

### 模型配置与动作执行

模型与思考强度支持下拉和手动输入；模型目录来自配置的服务，目录或 HTTP 成功不等于能力验证。
思考强度分别记录请求值与服务端回显，缺少回显时标为未确认，不按耗时猜测或自动换档位。

每轮开始时向模型提供当前机器人和相机状态，有先后依赖的工具按顺序调用。
姿态以结构化数据提供，不额外生成整臂渲染图片。坐标说明区分底座轴、随夹爪旋转的工具轴及相机画面方向；
需要了解关节变化效果时使用只读预览，不把某一关节的正转固定解释成末端向上或向前。
提示词要求在用户目标完成前继续根据反馈推进，不以中间结果结束；用户暂停或停止指令优先，
工具确实不可用时明确说明尚未完成，不伪报成功。
候选 IK 失败不等于整个任务失败，模型可调整目标或通过关节目标改变构型；阶段变化和实际结果需向用户报告。
夹爪平行或垂直地面仅作为姿态选择经验，不是固定朝向、倾角过滤或额外规划约束。
运动工具的 `observe_role` 指定动作完成后从哪台相机取新图，工具同时返回实际反馈；
如果取图失败，保留已完成的动作结果并报告取图错误，不重做已经完成的运动。
未要求拍照的普通运动、回工作位和夹爪工具也会在动作完成后读取状态；状态读取失败不导致动作重放。
运动失败或动作后的相机取图失败时仍尝试返回实际姿态，便于模型调整下一次目标；原始错误保留。
`observe_camera(exclusive=true)` 顺序关闭另一路、开启本路并取图，保留绑定与分辨率。
相机开关请求需等到该次配置确实生效；相机已开启但首帧未到时继续等待，断开、驱动错误或取消则结束等待。
服务重启后，未完成的 AI 任务标为中断，不自动继续物理动作；失败结果保留原请求编号、状态和错误。
原始工具调用、各模型轮次耗时与 token 用量仍保存在运行记录中。

### 工具与页面的对应关系

工作位来自型号 `named_targets.work`，与网页按钮相同；全零默认位不是工作位。
绝对/增量 TCP 映射到同一个 MotionRequest，增量平移不是最终位置，保持朝向的增量四元数为 [0,0,0,1]。
场景默认返回摘要，硬件完整目录仅显式查询时提供；点云与抓取数组由后端处理，不进入模型上下文。
准备分割图像时，工具与网页“载入新分割帧”使用同一刷新操作，并读取这帧的序号、可用模型和提示配置。
定位或候选生成完成后，工具按返回的场景序号等待对应结果，避免把页面尚未更新的旧数据交给模型。

同一会话连续显示用户消息与 AI 回复，模型设置、工具记录和执行状态收在详情中。
模型内部思维不展示。默认由工具取相机图，上传仅用于补充参考图。
提交任务授权其范围内的已有工具，漏检可调整提示或框选；框选仍标记 manual，不冒充模型分割。
用户只读、暂停等指令仍生效。“本轮回复已结束”、控制器成功、视觉确认和用户验收分别表示不同事实。
