## 发现的问题，不能掩盖为已通过

1. **传输配置**：默认 Fast DDS 下 6,120 字节的尺寸隔离探针能进入回调，而完整帧不能。
   单独增大 Docker SHM 总量不够；显式配置 128 MiB SHM segment 后完整帧稳定进入。
   官方 [SHM 文档](https://fast-dds.docs.eprosima.com/en/2.x/fastdds/transport/shared_memory/shared_memory.html)
   明确提醒 segment 小于消息会丢数据。GUI 额外 participant 需要更大总 SHM，本次用 1 GiB。
   尝试同时增大 TCP/UDP socket buffer 曾被主机限制拒绝；最终配置只调整隔离实验实际使用的 SHM，
   未修改主机 sysctl 或生产 DDS 配置。
2. **诊断错误**：最初漏了 `world → base_link` 固定 TF；另一次将 GetPlanningScene 的 full Octomap
   当成 binary 读取，诊断解码器崩溃。已分别补齐 TF、按 `binary` 字段选择原生读法，重新完整测试。
   失败日志不充当成功证据；工具使用 `--ulimit core=0`，避免崩溃产物散落。
3. **目标边缘**：2 mm 图过滤后仍有 15 个占用叶节点，中心为 X=203 mm、Z=17 mm，沿方块侧面分布。
   同次 OBB 的 X 上界约 202.5845 mm。需要继续检查感知包围体与量化点/体素边界的覆盖关系，
   不能以 5 mm 图恰好清干净就宣称所有分辨率都成立，也不能擅自扩大碰撞体或删点。
4. **地面与底座**：2 mm 图报告 `base_link` 接触，所示穿透深度仅约 `4.55e-11 m`，接触 Z 接近 0。
   这是本次浮点/接触边界问题的证据，不是机械臂真实扎入地面若干毫米；需单独收敛。
5. **运输没有通过**：对原记录中抓取到释放之间的 74 个离散姿态作官方查询，5 mm 图 33 个无效，
   2 mm 图 74 个无效（包含上述底座接触，不能都解释为撞筐）。官方返回的筐附近接触分别为
   10 / 6 条，涉及夹爪/附着物，所报最大深度约 2.249 / 2.641 mm。
   GetStateValidity 返回的接触不是穷举，采样也不是连续扫掠；本轮没有重新规划，更没有完成无碰撞执行。

## 新观测是不是必须

**单次完整抓放规划不强制需要抓起后的新点云。** 可以在规划前建立一份一致场景快照，目标作为
独立世界对象，MTC 用 attach/detach 表达抓取、运输、释放。附着物体积参与碰撞检查。
不能持续重复发送旧观测，再期待它自己理解“物体已经抓走”。

如果以后启用持续环境更新，真机由相机产生新的 RGB-D；模拟源也应按相同消息契约提供观测。
不需要针对真机编写“删除方块”分支。本轮移动物体重渲染用于验证官方更新机制，**不是给每次抓放
增加强制刷新、等待新帧或生成动态图片的步骤**。

第一阶段之后收敛单次快照、目标体积、边缘残留和地面接触，再做正式 MTC 运输规划复测。
不用最高评分候选作为验收条件，按任一候选可达并完整无碰撞执行的标准验收。

## 第二阶段：生产快照集成与失败追查

同一 `WorldScene` 增加组织化光学 XYZ 二进制列及相机外参；Rust motion 转原生 PointCloud2，
自定义 MTC action 携带同次场景。仅在每次抓放规划前发送一次，等对应官方 filtered 回调后规划；
任务结束清理这份旧地图。没有持续重发、没有抓起后强制等待新观测、没有模拟专用删方块分支。
目标使用感知 OBB 体积，MTC 原生 attach/detach；筐由 Octomap 表示，不增加实心筐盒。

### 目标接触不是此次闭合失败的根因

MTC 在闭合前已经允许独立目标与 `link7_left/link7_right` 接触，仍检查夹爪与地面/环境。
初次完整推理与三轮复测都在闭合失败；实际生产场景的 121 点闭合对照结果为：

| 对照                                     | 无效闭合采样 | 碰撞双方                        |
| ---------------------------------------- | -----------: | ------------------------------- |
| 官方 updater、shape padding=0            |       38/121 | `<octomap>` 与 `link7_left` |
| 同姿态、同 ACM、仅移除地图（隔离诊断）   |        0/121 | 无                              |
| 同输入，官方 shape filter 余量为半个体素 |        0/121 | 无                              |

接触位于 Z=4.726～5.000 mm，最大穿透 0.414 mm。深度量化使部分地面点略高于 Z=0，
占入 [0,5 mm] 体素，产生高于解析地面的假凸起。修正是官方 shape filter 排除已知地面与目标的
重复点，`padding_offset=octomap_resolution/2`（本次 2.5 mm）；不是扩大碰撞允许值或下移地面。
同次对照目标 ROI 占用为 0，筐沿 ROI 仍是 889，筐内部 ROI 为 0。

诊断中一次错误加载缺少 ACM 的场景，造成 121/121 自碰撞；另一次缺少固定 TF 的 IK 返回 -21。
这些都不计入上述结果。工具已保留生产 ACM、启动 RobotStatePublisher，并重新取证。
隔离 MoveGroup 个别退出时在析构阶段崩溃，报告是在退出前完成；不将其称为干净进程退出。

### 抬升不能只看终点

地图问题修正后，失败转为“抬升后恢复支撑碰撞”：旧 `MoveRelative` 最小距离为 0，
上游实现会将零长度/未完成的 Cartesian 路径当作成功。指定完整距离后必须重新验证可达性。
针对一个实际抓取姿态，保持朝向的 7.74～30.97 mm 抬升 IK 查询均返回 -31（每点 5 秒）；
这是指定查询的结果，不能推导所有候选都不可达。

曾尝试放开抬升朝向，20 次独立感知和软件执行全部完成，附着真值物体与整臂也未撞筐；
但离线反馈复核发现 6/20 条路径的物体先下探地面，最深约 8.57 mm。原因是抬升期间仍允许目标与支撑面
接触，位置终点规划不保证中途向上。**这组不是最终验收通过。** 完整路径检查必须包含附着物
最低 Z，不能只检查筐、释放位置或 action 成功。工具已补入该项，仅忽略 double 机器精度舍入，
没有毫米级容差。固定物体闭合检查与刚性附着运输检查分别记录，不冒充摩擦/动力学验证。

进一步恢复官方 Cartesian 抬升并要求全程完成，24 个抓取分支全部在抬升失败（fraction=0），
因此不能把固定朝向当作普适答案。当前修正保留位置目标规划，使用 MoveIt 原生
[条件接触 ACM](https://moveit.picknik.ai/main/api/html/classcollision__detection_1_1AllowedCollisionMatrix.html)：
先查询当前附着物—地面最大接触深度，仅允许不超过该起始值的接触。没有引入固定容差、裁切目标、
降低地面、修改资产或增加另一套规划器。条件只存在 PipelinePlanner 的本地场景中；MTC 的标准
场景消息不能序列化 C++ 回调，不能将两者混淆。抬升终点恢复普通碰撞检查，运输仍检查完整附着体积。

### 方法级审查与证据

- `world_scene_to/from_arrow`：同一场景的元数据和二进制列一起传输，校验长度；没有 JSON 浮点数组副本。
- `world_scene_and_instance_clouds_from_aligned_depth`：复用官方 OpenCV 光线；一次得到光学 XYZ 和世界 XYZ，
  两个模型与运动共享这批观测，没有测试专用点云删改。
- `run_manipulation`：仅 MTC action 改原生类型，删除该边界 untyped JSON 反馈转换；其余运动入口不新增路径。
- `apply_scene/cleanup_scene`：独立目标先于官方过滤，等待匹配的更新，结束清理；不持续重发旧观测。
- `PositionOnlyPlanner`：复用已有 PipelinePlanner，只处理位置目标和有条件的起始支撑接触，
  不引入手写 IK、场景识别规则或备用规划器。原候选、关节限位、资产尺寸、地面高度未改。
- 离线几何工具使用同一测试网格生成器和 FCL，复用碰撞管理器；修复临时局部变量覆盖接触结果的诊断错误。
  新增地面检查曾出现 numpy bool 无法 JSON 编码，已转换为 Python bool 并重新完成整批检查。
