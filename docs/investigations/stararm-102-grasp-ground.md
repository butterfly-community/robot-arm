# StarArm-102 抓取与闭合穿地排查记录

记录截至 2026-09-07。本文按排查顺序保留失败、反证和最终修改；章节内的“本轮”只指该次试验，
不代表当前配置。当前资产与验收总表见 [REVIEW](../REVIEW.md)，收尾见[收尾验证](closure-20260908.md)。

## 当前结论

- 闭合穿地不是遗漏底座高度，也不是本轮标定误差造成的：旧采样参考深度取了扫描体中心
  60 mm，而真实 TCP 偏移是 93.38 mm，生成的抓取 TCP 因此落到地面以下。
- 官方场景筛选使用张开夹爪网格与环境点的距离，不检查闭合扫掠，也不把地面以下定义为实心区域。
  “给了完整地面点云”不能推导出“所有闭合姿态都不会穿地”。
- 最终从张开夹指网格测量采样参考深度，约 66.471 mm；真实 TCP、关节范围和测试场景不变。
  撤销地面下移，恢复 Z=0，20 轮独立感知及软件执行全部通过，闭合最低离地约 2.741 mm。
- **实际稳定夹持仍未证明。** 固定方块的几何检查不能模拟首指推动物体后的接触、摩擦和夹持力；
  不以 MTC 成功、附着成功或双指最后都接触替代这项验收。

## 排查顺序与取舍

| 阶段 | 对照与发现 | 处理 |
| --- | --- | --- |
| 旧通过结论复核 | 固定物体允许先接触的手指继续穿透，造成双侧接触假阳性 | 撤销旧抓取通过结论，增加反例测试 |
| 输入、模型与 IK | 核对 RGB-D、地面点云、运行 URDF/SRDF、关节限位与候选姿态 | 不通过更改物体尺寸或新增姿态约束凑通过 |
| 官方示例对照 | 分开 object/scene 入口，比较官方与生产筛选的同批候选 | 保持官方场景筛选，不新增地下候选专用分支 |
| 临时地面容许量 | 3 mm 不覆盖闭合中途最低点；5 mm 能放行但掩盖穿地 | 两者都只作为历史试验，最终撤销 |
| 深度来源定位 | 扫描体中心、扫描体前端、张开指尖、TCP 是不同几何量 | 不再把扫描体中心当指尖采样参考 |
| 70 mm 前端面对照 | 闭合不穿地，但该批正式候选无 IK | 不采用 |
| 66.471 mm 张开指尖 | 使用官方向导几何函数测量实际张开网格 | 采用；Z=0 下重新执行 20 轮并核对反馈 |

## 旧抓取失败：保留诊断，不保留通过结论

旧布局、旧相机下的[原始二十轮反馈](../../tools/diagnostics/results/pick-place-mtc-repeatability.json)
仍保留为反例输入。旧六图及其派生FK数据已清理，可从Git历史 `1a912bb` 追溯已提交内容；不依赖临时恢复包。
不得用新几何重放旧输入并声称同批次；新的六图须用新候选和新执行反馈重建。

失败事实：

1. 右指驱动关节角约25.8°首次接触，左指约9.2°才接触。旧算法固定物体，
   允许右指继续穿透后再判“双侧接触”，因此二十轮“抓住”判定已撤销。
2. 旧候选下方块中心在夹爪规范坐标约(-8.317,-4.864,95.211) mm，
   闭合指尖轴向位置约93.38 mm。这提示偏侧/浅夹取，但不能直接推出新候选应加多少补偿。
3. 官方扫描参考深度60 mm与实际控制TCP深度93.38 mm不同义。
   当前-2/0/+2 cm采样比官方场景默认多+2 cm；需同输入对照其影响，不盲目修改TCP或夹爪尺寸。
4. 接口执行成功、MTC附着、精确跟踪候选TCP，都不能证明物体位于有效夹持区域；
   软件反馈/网格几何不能证明真实摩擦与夹持力。

旧版本的全栈测试、模型调用和AI请求成功仅代表当时的软件链路状态，不作为新资产端到端通过依据。
旧通过表与重复旧资产报告从当前文档移除，历史提交 `1a912bb` 可追溯原记录。
下一阶段必须修正诊断假阳性并给出新的六图及实际反馈，不能恢复旧“通过”标签。

## 初期抓取诊断（历史失败，不作为最终验收）

另一次同输入深度对照固定 RGB-D、标定、分割和随机种子，仅把 `gripper.depth` 从
93.38 mm 改为当时向导的 60 mm：200 个扩散候选不变，环境筛选后的总候选由 613 增至
721，双侧网格接触候选由 520 增至 628。但两者只有相同的两个扩散候选可达，且均不能
双侧接触。该批对照不能证明后来的 66.471 mm 配置，也不能把候选变多当成抓取通过。
记录为 `temp/gripper-depth-{physical,wizard}/` 及同名前缀 IK/几何报告；升级上游后需重新核验。

同一1920资产、已应用外参、YOLOE-26x默认置信度，提示词为 `red cube, dark rectangle`，
后者只用于测试框选置物区域，不表示测试篮子的真实语义。三轮识别结果一致，运行态RGB与
源资产逐像素相同，深度预览与源Z16按生产公式转换后的图逐像素相同。
方块掩码IoU约0.92956，完整覆盖目标但包含约7.04%背景；其可见点AABB约
37.77×37.75×30.97 mm，不得当作30 mm实体方块体积。该偏差与≤0.1 mm外参误差分开报告。

- 五次重新感知后分别走正式MTC，均在闭合阶段失败；全部失败保留于
  `temp/grasp-current/repeated-baseline/`，不能挑一个候选图作为通过。
- 初始批119候选，200 ms及1 s只读IK查询均41个成功、闭合状态有效数0，结果逐项一致。
  这是有限查询结果，不是全局不可达证明。
- 候选17的闭合状态报告 `ground/link7_left`、`ground/link7_right` 碰撞，深度约1.14/1.88 mm。
  独立网格扫闭合也确认手指进入Z<0区域；图中视觉上夹在两指间不能抵消地面穿透。
- 同位置的两组较高候选，保持原旋转时失败；围绕世界X/Y轴分别改变0、±10、±20、±30、±45°，
  36个只读探针中16个有IK且闭合状态无碰撞。探针仅用于归因，不注入正式候选或测试资产。
- 独立URDF/scipy多起点拟合（16个初值）在原朝向下落到J4边界，位置残差约9.58/7.30 mm；
  无界拟合仅说明哪类超限姿态能到达，不作为可执行解。

运行态配置核对结果（`temp/grasp-current/moveit-config.json`）：

| 检查项 | 实际结果 |
| --- | --- |
| move_group与MTC的URDF/SRDF | 两者逐字一致 |
| 规划组/TCP | arm链为base_link→tcp_link；TCP与link6零位移零旋转 |
| world→base_link | 零位移、零旋转 |
| 电机角与URDF角 | 同符号、无软件偏移；J3使用已确认的负向范围 |
| J4限位 | ±90°，符合用户指定；无第二层位置上/下限覆盖 |
| IK | TRAC-IK、Distance、epsilon=1e-5、默认5 ms、完整位姿求解 |
| 碰撞模型 | padding=0，scale=1；当前世界只有ground，没有标定板/附着物 |
| 地面 | 2×2×1 m盒，中心Z=-0.5 m，顶面Z=0 |
| MTC额外抓取姿态路径约束 | 源码未设置；目标旋转来自GraspGenX候选 |

这里的“没有额外姿态约束”不表示只给了位置：MTC接收候选的完整6D位姿，必须满足其旋转。
此前官方OBB顶部采样的接近轴严格为世界-Z，侧面为OBB水平法向；该接口没有倾角采样参数。
这与用户指定“J4垂直”不同。运行URDF的J2/J3/J4轴平行，候选17的三关节分别为
131.11843°、-127.41803°、86.29939°，合计约90°，共同产生向下TCP。
同姿态单独将J6减少10°，TCP位置与接近轴不变，只改变两指排列方向；单独转J4或J5
则同时改变接近轴与TCP位置。以上为只读FK，不是电机实测，也不是放宽限位的理由。

按用户最新要求已从生产调用删除OBB定向采样和额外+2 cm采样，使用官方diffusion；
不加入离线诊断倾角，不改写输出旋转。官方评分/场景筛选、TCP变换与MTC链路仍保持一致。
后续验收必须记录这次变更后的候选，不能复用上面的OBB结果。

网格接触检查已提取为工具共用的 `contact_geometry.py`，记录逐指首次接触、首次双侧接触、
接触法向/深度及全程手指最低Z。若先有一指接触、之后继续穿透才出现双侧接触，报告为
无法证明静态夹持，而非通过。三个回归测试覆盖对称接触、旧假阳性、完全未接触。
这仍不是摩擦、力封闭或物体接触动力学证明；不把“必须同时接触”加入生产流程。

## 闭合穿地根因诊断（历史只读对照）

生产容器导出的配置摘要为`fb2f4273fc60006e6a9ad7a60f2d8cc573f65d31ecfcb139e5fb7c8cc5513436`：
OBB扫描深度60 mm、真实TCP深度93.38 mm。离线工具镜像缓存了旧的93.38 mm扫描深度，
但两份URDF、所有网格、开闭角及真实TCP相同。使用生产资产重跑首轮执行审计，
`runs`逐项完全一致；排除了旧工具配置改变此次最低点计算的可能，已记录复核要求。

当前向下的顶部OBB候选以物体上表面对齐扫描参考点，而不是闭合指尖：
`TCP高度≈上表面30.50 + 扫描深度60 - TCP深度93.38 = -2.88 mm`。
调用当前安装官方预处理和OBB函数，对旧抓包的5153个目标点独立计算，上表面约30.5075 mm，
对应TCP约-2.8725 mm，与该旧输入记录的浅入地OBB候选吻合；这不是本轮反馈的同次随机OBB复现。
即使用理想实体高度30 mm，公式仍给出-3.38 mm，不能将其解释成标定误差。

首轮实际反馈及生产夹指网格重算结果：

| 状态 | 左指最低Z | 右指最低Z |
| --- | ---: | ---: |
| 驱动关节60°（总开角120°） | 24.056 mm | 24.026 mm |
| 驱动关节0°（闭合端点） | -2.874 mm | -2.883 mm |
| 完整闭合途中最小值 | -3.715 mm（驱动8.647°） | -3.728 mm（驱动8.669°） |

原因不是MoveIt误报：转动夹指在闭合中途的最远伸出比闭合端点还大约0.845 mm。
官方`filter_colliding_grasps`仅取张开网格的表面点，对场景做20 mm最近距离检查；
当前张开全网格最低24.026 mm，光是加密Z=0地面点也不会使这份张开网格触发20 mm筛选。
它不检查闭合运动，不能把扫描体存在视为覆盖了闭合环境碰撞。
MoveIt使用真实关节模型检查整段闭合，原先正确拒绝；把地面下移5 mm只掩盖了这次约3.73 mm穿入。

真正修复需联合核对候选生成所用深度与夹指完整闭合几何，并在真实地面下验收；
不能简单把60改成93.38（会整体抬高33.38 mm，可能变成只擦物体顶面），也不能继续扩大地面容许量。
该次仅诊断，后续实施结果见下一节。证据为`temp/grasp-planner/ground-root-cause.json`、
导出的`runtime-gripper/`和`release-position-only-1/run-1/geometry-runtime-assets.json`。
