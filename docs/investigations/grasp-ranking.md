# 抓取候选：深度优先与运动代价（2026-09-08）

后续已将固定朝向抬升替换为持物回工作位；排名规则不变。
新的同输入对照和三轮软件执行结果见 [持物脱离调查](lift-departure.md)。下文保留此前测试事实。

用户要求保留充分夹入的优先级，同时让接近更直接、动作更少绕行的候选有机会胜过模型高分候选。
这里不修改 GraspGenX、不增加朝向门限、不改变地面/目标接触规则或控制器力度。

## 选择规则

1. 仅接收 MTC 找到的完整方案；接近、闭合、抬升、运输、释放、返回均须规划成功。
2. 按原始候选分组。每组优先额外插入最深的方案，同深度选择关节运动代价最低的方案。
3. 在各组代表方案中最小化 `C = (1 - p) + L`：
   - `p` 为该原始候选的 GraspGenX 判别器分数，未经索引映射或修改。
   - `L = mean_j(累计关节路程_j / 该关节最大行程_j)`，对完整轨迹所有路径点累计。
   - 并列时依次选模型分较高、运动代价较低、候选索引较小的方案，保证确定性。

`L` 调用 MTC 原生 `cost::PathLength`，从当前 RobotModel 的 arm 活动关节读取名称和最大行程；
权重是 `1 / (关节数 × 该关节最大行程)`。不重新实现 FK、关节角环绕或碰撞，不假定六个编号，
不把 J4/J6 另设权重，不包含夹爪开合运动。关节先转出去再转回来仍计入路程，不仅比较首尾姿态。
当前型号各轴有界，最大行程来自正式模型；归一化不是新增关节限制。

原生接口见 [MTC CostTerm](https://moveit.picknik.ai/main/doc/concepts/moveit_task_constructor/moveit_task_constructor.html#cost-calculator-for-stages)。
模型质量损失与平均关节行程等权相加，是本次明确选定的工程策略，不声称行业存在唯一最佳权重。
不随本批候选的极值缩放，也不设“分数差小于某值才比较路径”的新门限。
例如模型分降低 0.03，但平均归一化关节路程减少超过 0.03，则更直接的方案胜出。
路径可能往返多次，`L` 可以超过 1；`C` 不是成功概率，也不是秒、米或力。

## 深度语义与边界

- 仍沿 TCP +Z 按 Octomap 分辨率生成变体，保留原位和末端；朝向不变。
- 每个候选先取最深完整可行方案，避免短路径诱导同候选退回浅抓。
- 不跨候选比较额外移动量：原位置不同，“加深 20 mm”不一定比“加深 5 mm”包覆得更好。
- 没有新增双侧接触面积/摩擦评价，也没有将加深后的位姿重新送模型评分；原分数只表示原候选质量。
- 关节路径长度是少绕行的近似，不保证任意情况下 TCP 路径最短或动作视觉最自然。
- 排名只在本轮规划找到的完整方案中进行，不把模型高分、碰撞通过或规划 attach 当作实物抓稳证明。

## 消息与可观测性

`GraspCandidate` 把位姿和 `confidence` 绑定；JSON 保持 `position_m/orientation_xyzw` 平铺，
原有渲染工具仍直接读坐标。scene 不再在排序后丢弃分数，motion 将其同序传入 ROS action 的
`grasp_poses/grasp_confidences`。原生入口校验数量与有限值，不为旧消息补造分数或维护第二条路径。
旧归档可继续作只读渲染输入；若只有位姿而没有分数，不能拿它冒充新策略的完整动作请求。

MTC 保留自身原始规划代价；最终候选重排调用原生 PathLength，`selected_cost` 表示上述综合代价。
日志列出每个候选最深完整方案的原分数、加深量、归一化路程及综合代价；网页阶段信息在规划和执行
期间显示所选项，提示点说明代价语义。完整方案数量仍表示原生 MTC 总数，而不是分组后的候选数。

## 验证范围

- 原生 MTC 回归使用真实 RobotTrajectory/ComputeIK/SolutionSequence，而非伪造 `solution.cost()`。
  直接路径模型分 0.90、路程 0.1，综合代价 0.20；绕行路径模型分 0.95、路程 0.9，代价 0.95。
  前者胜出，但其更浅、更便宜的变体不会替代已找到的深抓。
- 同路径高模型分优先、同候选同深度短路径优先、深度属性跨 IK 转发、旋转目标采样边界均回归。
- 原有地面碰撞、闭合重采样漏检及正常目标接触放行测试继续通过。
- Rust 消息 round-trip、scene-core/scene-node、motion 原生 action 字段、前端契约和单元测试核对。
- 最终结果：上述 Rust 测试共 38 项、前端 23 项及原生 MTC 回归通过；scene/motion Clippy
  `-D warnings`、前端类型检查、五个应用构建、格式检查和文档链接检查通过。
  Clippy 检出的运动队列大枚举改为装箱存放，只调整内存布局、不改变控制逻辑。
- 测试源码位于 `tools/diagnostics/mtc-ranking-test` 及 `#[cfg(test)]`，不进入生产执行。
  本轮没有发送真机运动指令，不把离线轨迹评价当作新一轮真实抓放成功率。

复现见[原生排名回归](../../tools/diagnostics/mtc-ranking-test/README.md)。新 action 字段要求对应
ROS 包和 r2r 绑定一起更新，再整套服务重启；不只更新一个正在运行的节点，也不重编译基础依赖。

本轮已更新 scene、motion 和前端应用镜像，整套 down/up 后八个节点 daemon 健康，网页及三个
状态接口返回 200；未发现新契约反序列化或动态链接错误。日志仍有 RViz 图形/持久设置、未使用的
`/recognize_objects` 和 FIFO 调度权限提示，不将其误报为本次排序失败，也不宣称日志完全无警告。

## 正式模拟数据回归（2026-09-08，后续验收）

使用已部署的 e32e320、1920×1080 模拟 RGB-D、原有模拟外参和资产声明的
`red cube` / `dark rectangle` 提示词。模型为 yoloe-26x-seg.pt，场景筛选距离使用测试资产
声明的 20 mm，未拿真实薄片配置的 5 mm 冒充相同输入。每轮重新推理，经过正式 scene、
空间转换、MTC、执行节点的软件反馈；没有发送真机运动。三轮全部保留，未修改生产参数凑通过。

| 轮次 | 模型候选数 | 完整软件抓放 | 结果 |
| --- | ---: | --- | --- |
| 1 | 89 | 失败 | lift object 0/26，CartesianPath fraction=0；没有进入最终排序 |
| 2 | 95 | 成功 | 5 个完整方案；候选索引 53，加深 20 mm，19.37 秒完成并回工作位 |
| 3 | 91 | 失败 | lift object 0/32，CartesianPath fraction=0；没有进入最终排序 |

失败轮的候选级报告另含 no IK found、ground—link7_left；不能将这些汇总碰撞直接当作每个
抬升分支失败的原因。0/26、0/32 是规划阶段解的计数，不是物理执行进度。

成功轮分数 0.7812640071，归一化关节行程 1.0679661932，总代价 1.2867021861。
根据原生发布的 18 段轨迹独立累计重算，与服务结果相差约 6.7e-16。
5 个完整方案分组后只有一个原始候选，因此本轮证明深度/分数消息与代价进入了正式链路，
**没有证明不同模型候选间的运动改善或稳定成功率**。跨候选选择逻辑由原生确定性回归覆盖。

使用同一运行型号网格做 FK：实际规划加深 19.9961 mm，目标位置误差 0.01174 mm，
朝向差 0.0002001°；121 个闭合采样中的夹爪最低 Z 为 +1.5601 mm。
这些是离线模型量，不是实物抓持/力控证据，也不代替连续碰撞检查。

测试结束恢复真实物体的原文字/视觉提示配置和 5 mm 场景筛选距离，取消模拟相机选择，
执行器保持软件模式且未选串口，不自动重连。源码仅增加 tools 诊断，生产代码未改变。
原生排序/深度/闭合碰撞 CTest 再次通过，但完整三轮回归总结果是 **1 成功、2 失败，未全通过**。
原始随机候选、执行反馈及所选原生规划保存在
`tools/diagnostics/results/grasp-ranking-20260908.tar.gz`；可再生成的模型/图片不作为文档资产保存。

## 抬升方式对照：直线脱离与持物回工作位

[MTC 官方完整示例](https://github.com/moveit/moveit_task_constructor/blob/ros2/demo/src/pick_place_task.cpp)
使用闭合→attach→允许物体支撑接触→MoveRelative/CartesianPath 世界 +Z 抬升→恢复支撑碰撞→
采样规划器运输。官方允许配置最小/最大抬升距离，并非要求照搬某个机器人示例的厘米数。
对照前的工程固定最小=最大=观测物体高度，保持抓取朝向；另保留已有支撑接触深度的条件 ACM。

[MoveTo 官方接口](https://moveit.picknik.ai/main/doc/concepts/moveit_task_constructor/propagating_stages.html#moveto)
支持 SRDF 命名关节目标。用户提出的替代方式可用 MoveTo(work)+PipelinePlanner：
只给 arm 工作位，不给夹爪目标；物体保持附着、执行端保持夹持力度。它不是任意转腕的
“只约束抬升终点 XYZ”，也不是原地打开夹爪后回工作位。

| 方面 | 历史固定朝向直线抬升 | 持物先回工作位 |
| --- | --- | --- |
| 运动约束 | 整段 TCP 沿 +Z、保持朝向 | 终点关节角固定，中途可变朝向和绕障 |
| 优点 | 离开支撑方向明确、避免局部额外转腕 | 不依赖整段竖直连续 IK，可使用已定义的关节目标 |
| 代价 | 端点可达不代表每个插值点都可达 | 可能多走路，中途可能扫到桌面/筐或让物体倾斜 |
| 仍需检查 | IK、手指环境碰撞、附着物支撑接触 | 同样检查整臂及附着物，不能用空手回工作位替代 |

三轮失败发生在最终排序之前；不能仅凭 fraction=0 断言全由姿态约束造成。
本节先记录方法差异，后续已完成同输入对照并替换生产脱离阶段，未保留失败后再走备用业务链路。
对照复用同批观测、候选、机器人起点、地图与接触规则，让各方法完整求解，
比较完整任务成功数和实际轨迹，而非各自重抽模型候选；详细结果见上面的持物脱离调查。
