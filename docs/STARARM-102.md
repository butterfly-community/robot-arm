# StarArm-102 型号适配

本文说明 StarArm-102 使用什么舵机、关节角怎样对应实物、夹爪参考点在哪里，以及标定结果能代表什么。
通用调用链与抓放参数见
[架构文档](BACKEND.md)，源码入口见[设备目录](../backend/devices/stararm-102/README.md)。

## 模型来源与补丁

六轴和夹爪均为用户确认的 **RA8-U35H-M**；型号不能由总线 ID 推断。
[厂商产品页](https://fashionrobo.com/actuator-u35/23392/)涵盖多个变体，不能直接替代本型号配置。
用户指定最高电机速度 **34 rpm = 204°/s ≈ 3.56 rad/s**，不再折半。
速度由补丁后 URDF 统一供 MoveIt 与 ros2_control 读取，不写入舵机 EEPROM。

厂商模型固定使用提交 `0896306e40891c3ee4c97228e85dd708d61326de`。镜像构建时先校验原始模型，
应用 `backend/devices/stararm-102/patches/` 中的补丁，再校验生成结果。运行时统一使用该结果，
不再用另一份模型覆盖。
`model.patch` 管理范围/TCP/打包，`dynamics.patch` 管理动力学，`topic-io.patch` 管理 ROS 接口。
镜像标签只在[镜像清单](DOCKER.md)维护。

## 驱动与配置

| 配置 | 定义 / 来源 |
| --- | --- |
| UART | 1,000,000 bit/s，事务超时 100 ms；同一串口串行收发 |
| 位置编码 | 电机角 0.1°；不是末端定位精度 |
| 状态反馈 | 默认 100 ms，执行页 `feedback_interval_ms` 可保存 |
| 单条舵机位置命令的运动时间 | 100 ms，加/减速各 50 ms；ROS 的完整轨迹由多条命令组成，不是整条轨迹只运行 100 ms |
| 夹持目标 | 源码默认 50，执行页 `gripper_strength_percent` 持久配置为准 |
| 负载刻度 | 功率 400–2000 mW 映射到 0–100；不是牛顿力 |
| 舵机内部参数 | 以网页实时回读为准；作用、单位、调整效果见[驱动说明](../backend/crates/fashionstar-uart/README.md) |

串口可从枚举列表选择或手动输入 `/dev/serial/by-id/...`，配置不依赖 ttyUSB 编号。
连接时和点击“读取全部舵机信息”时，都分批读取参数。状态查询（Monitor）、参数查询和运动写入
依次使用同一串口，不同时发送。等待查询回包期间，只缓存最新完整位置目标，回包结束后再发送；
全部信息是否读完以页面进度为准。
固件版本来自 READ_DATA 地址 7，保留原始编码，不拿内部参数版本或推测的 Vxxx 替代。
电机序列号不保证唯一，设备身份仍由型号映射和串口配置确定。

公开参数写入后重新读取确认；内部参数按厂商流程依次卸力、等待、写入、恢复上力，再读取完整参数块。
即时回读不表示需要重新上电的参数已经生效。全部上力在当前反馈位置锁力，不跳回旧目标。

### 持续夹持反馈

闭合开始进入反馈调节，运输中持续运行；显式张开、卸力或断开后退出。
目标是持续保持设定负载，不是达到目标后固定夹爪角度或输出功率。
`gripper_feedback.rs` 根据每次新的电机功率反馈调整允许输出的功率上限：负载不足时增加，过高时减少。
内部保留浮点精度，发送舵机命令时才转换为协议整数；重复或比上一条更旧的反馈不再次参与调节。

更新为 `u ← u + a·u·(t−p)/(t+p)`，其中 u 为当前输出上限，t 为目标刻度对应功率，
p 为原始反馈，a 由采样间隔与单条位置命令的运动时间计算。尚未出现可测负载时，不因空载而持续增加输出。
协议 power=0 表示最大功率，因此闭环可编码范围为 1–2000 mW。
`transport_state` 显示目标、反馈与动态输出；摩擦、惯性和采样延迟会引起波动，不能直接据此证明抓住。

## 角度坐标基线（电机与模型）

业务接口中的 J1–J6 和夹爪角均指对应舵机的**电机旋转角**。业务零点就是 UART 位置命令和
反馈中的 0°，项目不另加软件零偏；正负号原样跨过 Web、Dora、motion、ROS controller 和
Rust execution。motion 与 perception 不得对任何一个轴另加反号或偏移。厂家原始 URDF 的
全部转动轴均为各自关节局部坐标系的 `axis="0 0 -1"`；项目补丁保留这些轴向，只调整声明
范围。URDF 中的 `-Z` 是运动学旋转轴，不是数值反号：对每个主动轴都满足
`q_urdf(rad) = angle_uart(deg) × π / 180`。

| 业务关节 | 舵机 ID | 厂家 URDF 轴 | 厂家提交范围 | 补丁后电机角范围 | UART 命令/反馈映射 |
| --- | ---: | --- | ---: | ---: | --- |
| J1 / `joint1` | 0 | `0 0 -1` | -2.27…2.27 rad | -110°…110° | 同符号、无偏移 |
| J2 / `joint2` | 1 | `0 0 -1` | 0…3.14 rad | 0°…180° | 同符号、无偏移 |
| J3 / `joint3` | 2 | `0 0 -1` | -3.14…0 rad | -270°…0° | 同符号、无偏移 |
| J4 / `joint4` | 3 | `0 0 -1` | -1.57…2.2 rad | -90°…90° | 同符号、无偏移 |
| J5 / `joint5` | 4 | `0 0 -1` | -1.2…1.2 rad | -65°…65° | 同符号、无偏移 |
| J6 / `joint6` | 5 | `0 0 -1` | -3.14…3.14 rad | -150°…150° | 同符号、无偏移 |
| 夹爪驱动 / `joint7_left` | 6 | `0 0 -1` | 0…1.57 rad | 0°…90° | 同符号、无偏移 |
| 从动夹指 / `joint7_right` | — | `0 0 -1` | -1.57…0 rad | -π/2…0 rad | `joint7_left × -1`，不经过 UART |

J3 的机械行程幅度是 0–270°，但该轴在已经由真机确认的 UART/业务坐标中沿负方向运动，
因此模型中的有符号范围写作 -270–0°；这不是额外反号。运行时的唯一型号定义、补丁后 URDF、
MoveIt、前端滑杆以及 execution 串口写入前校验必须保持上表一致。模型加载时会核对 URDF 与
型号定义，任何漂移都会直接阻止服务启动。

真机反馈可以因舵机零点误差短暂落在机械范围外，例如 J2 在 0°附近返回 -0.3°。execution
保留并对外发布这个原始反馈；motion 仅在把当前状态交给 ROS/MoveIt 时，将越界值裁到上表最近的边界，避免
`ros2_control` 因当前值越界而中止所有轨迹。例如 -0.3° 在规划状态中按 0° 处理，标定仍使用 -0.3°。
此处理没有额外容差常量，也不放宽规划或 UART
命令范围；下一条动作可直接从边界状态继续，不存在单独的解锁或恢复流程。

厂家 ROS Python 驱动会对夹爪做一次反号转换，但本项目没有使用该驱动：Rust execution 直接
收发 FashionStar ID 0–6，因此夹爪也采用上表的同符号电机角。不得把厂家 Python 驱动的
转换复制到本项目。真机已确认 J3 负电机角是抬起方向；自动标定要求的是“负向幅度至少
10°”，即 `J3 ≤ -10°`，`-11°` 有效而 `-9°` 无效。

`stararm-102-model` 从最终 URDF 生成模型信息和资源清单。execution 对外提供模型资源，
并负责关节与舵机 ID 的映射。GraspGenX 的设备清单只保存无法从模型自动推导的参数；
计算镜像构建时，从同一份已打补丁模型生成夹爪 URDF、网格、抓取体积和配置。

## 唯一 TCP

TCP 是指定末端位置和朝向的参考点。本型号使用 `tcp_link`，位于两侧夹爪尖端之间。
它通过零位移、零旋转的固定关节连接到机械结构 `link6`；两者当前坐标相同，但用途不同：

| 坐标系 | 含义 | 是否用于业务目标 |
| --- | --- | --- |
| `link6` | 第六轴末端结构坐标系 | 否 |
| `tcp_link` | 夹爪尖端中心、MoveIt 规划末端 | 是 |
| `link7_left` / `link7_right` | 两侧活动夹指 | 否 |

厂家夹指转轴位于 `link6` 的 `z=-73.13 mm`，夹指网格延伸到 `z≈0`。因此新增 `tcp_link`
只是显式命名厂家模型已有的尖端中心，没有引入工具偏移。MoveIt group tip、FK、IK、抓放目标、
附着物体、模型元数据与标定观测都使用 `stararm_102_model::TCP_FRAME`。

`ARC_PIVOT_TO_TCP_M = [0, 0, 0.07313]` 只表示夹爪转轴到尖端中心的圆弧演示几何，不是
`link6 → tcp_link` 变换，不能用于 FK、IK、抓放、附着或相机标定。

## 命名位与标定

默认位为全轴 0°；工作位为 J3=-60°、J4=+60°，其余为 0°，夹爪闭合。
九组默认采样姿态来自型号库 `calibration_targets()`，表中均为电机角：

| 姿态 | J1 | J2 | J3 | J4 | J5 | J6 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1（工作位） | 0° | 0° | -60° | 60° | 0° | 0° |
| 2 | -60° | 0° | -60° | 60° | 0° | 0° |
| 3 | 60° | 0° | -60° | 60° | 0° | 0° |
| 4 | 0° | 0° | -60° | 40° | 0° | 0° |
| 5 | -60° | 0° | -60° | 40° | 0° | 0° |
| 6 | 60° | 0° | -60° | 40° | 0° | 0° |
| 7 | 0° | 0° | -60° | 30° | 0° | 0° |
| 8 | -60° | 0° | -60° | 30° | 0° | 0° |
| 9 | 60° | 0° | -60° | 30° | 0° | 0° |

标定按以下顺序执行：

1. 保持夹爪当前状态，先回工作位。
2. 依次到达九个采样姿态，每组等待 10 秒后采图，并取得新的电机实际反馈。
3. 用实际反馈角计算末端姿态，与图中的标定板姿态一起求解相机外参。不使用命令角或规划时裁剪后的角度。
4. 回到工作位，确认回位成功后，网页才允许“确认并应用标定”。

标定期间不发送夹爪开合目标。开始抓放前需取下标定板。

已应用外参保存在 `backend/config/runtime/camera.json`，网页显示其当前值；
选择同一设备可复用，相机与机械臂安装关系变化时重新标定。文档不保存外参副本或残差成绩。

## 夹爪角度与指尖

- 夹爪驱动关节角：舵机/左指角度；右指按 -1 齿轮联动。
- 两指总开角：驱动关节角的两倍；机械范围 0–180°。
- 抓取常用 open：驱动角 60°，总开角 120°；close：驱动角 0°。
- 开口宽度：两指之间的线性距离，以 mm 表示，不与角度混用。
- 两个指尖参考点来自各活动指 CAD 末端，经 FK 变换；不是整个指头或 TCP 轴。

指尖倾角描述两指尖是否等高：两尖同高时为 0°，一高一低时倾角增加。
计算式为 `asin(|n·(右尖−左尖)|/两尖距离)`，其中 n 是地面的单位法向量。
用户指定过滤倾角 ≥20° 的候选。这里只限制两指尖连线，不要求整个夹爪水平，也不固定 J6 或夹爪张合平面。
地面和候选在同一任务坐标系，地面法向为 +Z；不能使用相机视角下的高度差。

## MoveIt 与 MTC

使用原生 MoveIt/MTC，Rust 管理请求与反馈，C++ 构造阶段并执行完整任务。
[调用链、参数和模块](BACKEND.md#stararm-102-motion-node)只在架构文档维护。
地面是 base_link 的 Z=0；厂商模型已包含底座高度，不再加到地面、TCP 或目标上。
原生 JTC/TOTG 判定轨迹完成；力度保持独立运行。
`execution_duration_monitoring=false` 表示等待控制器 action 结果，不按估算时长取消，
不表示关闭控制器错误或碰撞检查。

## 真机精度与适用限制

- 标定拟合残差表示：使用求出的相机外参后，各组观测能否互相吻合。最大残差取最差一组，RMS 反映所有样本的总体误差。用户接受最大残差 ≤10 mm；这不表示机械臂在任何位置都能达到 10 mm 定位精度。
- 实际角反馈无法消除连杆误差、零位、间隙与受力变形；0.1° 是协议单位。
- 打印板缩放/平整度、夹持刚性、角点质量及相机内参均影响标定。
- 图像与电机反馈由软件按采样流程配对，不是同时曝光、同时采样的硬件同步；物体边缘还可能存在彩色与深度不完全对应的误差。
- 碰撞地图来自一次观测，不持续更新移动障碍；清除夹爪自身点时，附近其他物体的点也可能被一起清除。
- 规划完成、附着对象或软件成功不证明实物夹持；硬物、透明/反光物和不同摆放须观察实际效果。
- 释放不承诺精确落点；模拟资产的 ≤1 mm 几何标准不是真机精度承诺。

这些限制用于解释结果，不作为新增动作门限或另一套恢复流程的依据。
