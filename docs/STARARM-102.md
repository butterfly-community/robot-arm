# StarArm-102 型号适配

本文件集中维护 StarArm-102-FL 独有的模型、坐标、命名位、夹爪、规划与验收事实。通用服务
架构不依赖这里的关节数、尺寸或舵机协议。

型号源码、ROS 包、补丁和镜像入口集中在
[`backend/devices/stararm-102`](../backend/devices/stararm-102/README.md)。感知节点通过通用
`RobotModelInfo.gripper_asset_id` 获取夹爪资产 ID，不保存或判断本型号名称。

## 模型来源与补丁

### 实装舵机

用户于 2026-09-05 确认：六个机械臂关节和夹爪的舵机全部为 **RA8-U35H-M**。
型号事实不依赖可重新设置的总线 ID。官方资料为
[35KG 系列产品页](https://fashionrobo.com/actuator-u35/23392/)，覆盖 RA8/HA8、U35/U35H 多个变体。

该页确认 UART/TTL、角度/轮式/阻尼模式，以及位置、电压、电流、功率和温度反馈。但页面存在
内部矛盾：概览写空心杯、34 rpm（0.298 s/60°），参数表写铁芯、55 rpm（0.208 s/60°）；
55 rpm 与 0.208 s/60° 本身也不等价；编码器写 12 bit，分辨率又写 2048 阶/圈。
因此这些数值不能直接作为该 H 型号的精确速度、精度或加速度配置。

**用户最终约定（2026-09-05）：最高电机角速度直接采用 34 rpm = 204°/s ≈ 3.56 rad/s，
不再除以 2，并已授权应用到本型号的软件模型。** 34 rpm 是用户选择的最高值，
不是一个需要再次折半的空载基准，也不声称它恰好等于 55 rpm 的一半。
夹爪也按电机/驱动关节角速度计，不把两指总开角速度混入电机参数。

机械装配范围继续采用已确认的型号角度表，不用产品页的单圈/多圈协议范围覆盖。规划和
ros2_control 的速度必须同时取自同一 URDF；厂商 MoveIt YAML 中 3.14 rad/s 的覆盖值与
原始 URDF 机械臂关节的 1 rad/s 不一致。型号补丁把全部转动关节的 URDF `velocity` 统一为
`3.560471674 rad/s`（34 rpm 的单位换算），同时删除 YAML 中的速度覆盖，MoveIt 与 ros2_control
共同继承 URDF。保留换算精度仅用于模型文件，文档/界面可显示 3.56 rad/s。未写入舵机 EEPROM，
也不改变其他机械臂或通用 TCP 手动控制速度。

### 参数归属与当前值

| 参数 | 当前值 / 约定 | 唯一配置来源与含义 |
| --- | --- | --- |
| 全部舵机型号 | RA8-U35H-M | 用户确认；不是通过 ID 推测 |
| UART 波特率 / 单次超时 | 1,000,000 bit/s / 100 ms | `fashionstar-uart`；现有总线配置，产品页 500 kbit/s 表述不据此覆盖 |
| 全电机反馈周期 | 默认 100 ms，可配置 | execution 的 `feedback_interval_ms`，后端文件持久化；与网页显示频率无关 |
| UART 位置量化 | 0.1° | 协议编码单位，不等于实际定位精度或编码器位数 |
| 电机角 / URDF 角 | 同符号，° 转 rad，无软件偏移 | `stararm-102-model` 与厂商 `axis=0 0 -1` |
| J1–J6、夹爪驱动关节速度上限 | 34 rpm = 204°/s ≈ 3.56 rad/s | 型号补丁 URDF；MoveIt 与 ros2_control 同源，不再除以 2 |
| 两指总开角速度 | 驱动关节角速度的两倍 | 齿轮联动派生量，不是独立电机参数 |
| 规划加速度 | 当前 30 rad/s² | 既有 `dynamics.patch`，非手册额定值；本次不改变 |
| 普通运动速度/加速度倍率 | 默认 1.0，可按请求指定 | motion 的 MoveGroup 请求参数；倍率作用于模型上限 |
| UART 命令时间 / 加减速时间 | 100 ms / 50 ms / 50 ms | execution 的现有平滑位置命令字段，不是 ROS 轨迹时长 |
| 夹爪功率 / 反馈空载基线 | 2000 mW / 400 mW | execution 现有命令与反馈映射；反馈 `(功率−400)/(2000−400)` 映射到 0–100 |
| Kp / HoldKp 等内部参数 | 以当前真机回读为准 | 不把先前 800/900 等调试值写成默认；修改后读回核对 |

参数相同不表示含义相同：100 ms 的串口超时、反馈周期与动作时间分别属于不同环节，不能为了
“统一”合成一个全局数字。角度范围和命名位见下表，不在其他服务重复定义。

### 厂商模型版本

厂家源码固定在提交 `5979b346eb3a417840b29b76740754e4005d071a`。构建先用
`tools/verify-model.py` 验证该提交的原始关节定义，再应用
`backend/devices/stararm-102/patches/` 中的型号补丁，最后再次验证成品模型；不直接修改厂商
仓库，也不维护运行时模型覆盖。关节范围、夹爪范围、TCP 和 ROS 2 打包修正位于
`model.patch`，动力学与 ROS topic 修正分别位于 `dynamics.patch` 和 `topic-io.patch`。

### 角度坐标基线

业务接口中的 J1–J6 和夹爪角均指对应舵机的**电机旋转角**。业务零点就是 UART 位置命令和
反馈中的 0°，项目不另加软件零偏；正负号原样跨过 Web、Dora、motion、ROS controller 和
Rust execution。motion 与 perception 不得对任何一个轴另加反号或偏移。厂家原始 URDF 的
全部转动轴均为各自关节局部坐标系的 `axis="0 0 -1"`；项目补丁保留这些轴向，只调整声明
范围。URDF 中的 `-Z` 是运动学旋转轴，不是数值反号：对每个主动轴都满足
`q_urdf(rad) = angle_uart(deg) × π / 180`。

| 业务关节 | 舵机 ID | 厂家 URDF 轴 | 厂家提交范围 | 补丁后电机角范围 | UART 命令/反馈映射 |
| --- | ---: | --- | ---: | ---: | --- |
| J1 / `joint1` | 0 | `0 0 -1` | -2.27…2.27 rad | -110°…110° | 同符号、无偏移 |
| J2 / `joint2` | 1 | `0 0 -1` | 0…3.14 rad | 0°…180° | 同符号、无偏移 |
| J3 / `joint3` | 2 | `0 0 -1` | -3.14…0 rad | -270°…0° | 同符号、无偏移 |
| J4 / `joint4` | 3 | `0 0 -1` | -1.57…2.2 rad | -90°…90° | 同符号、无偏移 |
| J5 / `joint5` | 4 | `0 0 -1` | -1.2…1.2 rad | -65°…65° | 同符号、无偏移 |
| J6 / `joint6` | 5 | `0 0 -1` | -3.14…3.14 rad | -150°…150° | 同符号、无偏移 |
| 夹爪驱动 / `joint7_left` | 6 | `0 0 -1` | 0…1.57 rad | 0°…90° | 同符号、无偏移 |
| 从动夹指 / `joint7_right` | — | `0 0 -1` | -1.57…0 rad | -π/2…0 rad | `joint7_left × -1`，不经过 UART |

J3 的机械行程幅度是 0–270°，但该轴在已经由真机确认的 UART/业务坐标中沿负方向运动，
因此模型中的有符号范围写作 -270–0°；这不是额外反号。运行时的唯一型号定义、补丁后 URDF、
MoveIt、前端滑杆以及 execution 串口写入前校验必须保持上表一致。模型加载时会核对 URDF 与
型号定义，任何漂移都会直接阻止服务启动。

真机反馈可以因舵机零点误差短暂落在机械范围外，例如 J2 在 0°附近返回 -0.3°。execution
保留并对外发布这个原始反馈；motion 仅在把当前状态交给 ROS/MoveIt 时投影到上表边界，避免
`ros2_control` 因当前值越界而中止所有轨迹。该投影没有额外容差常量，也不放宽规划或 UART
命令范围；下一条动作可直接从边界状态继续，不存在单独的解锁或恢复流程。

厂家 ROS Python 驱动会对夹爪做一次反号转换，但本项目没有使用该驱动：Rust execution 直接
收发 FashionStar ID 0–6，因此夹爪也采用上表的同符号电机角。不得把厂家 Python 驱动的
转换复制到本项目。真机已确认 J3 负电机角是抬起方向；自动标定要求的是“负向幅度至少
10°”，即 `J3 ≤ -10°`，`-11°` 有效而 `-9°` 无效。

`stararm-102-model` 从最终 URDF 生成模型信息与资源 manifest；execution 是模型资源和
FashionStar UART 映射的唯一所有者。GraspGenX 只在设备目录保存不可推导的清单；计算镜像
构建时从同一份已打补丁模型自动生成夹爪 URDF、网格、扫描体和配置，不读取预生成资产。

## 唯一 TCP

`tcp_link` 是该型号唯一工具中心点，位于两侧夹爪尖端之间。它通过零位移、零旋转固定关节
连接到结构链接 `link6`。两者当前数值位置相同，但语义不同：

| 坐标系 | 含义 | 是否用于业务目标 |
| --- | --- | --- |
| `link6` | 第六轴末端结构链接 | 否 |
| `tcp_link` | 夹爪尖端中心、MoveIt 规划末端 | 是 |
| `link7_left` / `link7_right` | 两侧活动夹指 | 否 |

厂家夹指转轴位于 `link6` 的 `z=-73.13 mm`，夹指网格延伸到 `z≈0`。因此新增 `tcp_link`
只是显式命名厂家模型已有的尖端中心，没有引入工具偏移。MoveIt group tip、FK、IK、抓放目标、
附着物体、模型元数据与标定观测都使用 `stararm_102_model::TCP_FRAME`。

`ARC_PIVOT_TO_TCP_M = [0, 0, 0.07313]` 只表示夹爪转轴到尖端中心的圆弧演示几何，不是
`link6 → tcp_link` 变换，不能用于 FK、IK、抓放、附着或相机标定。

## 关节、命名位与夹爪

| 名词 | 定义 | 单位 |
| --- | --- | --- |
| J3/J4 关节角 | 机械臂第三、第四关节各自的角度 | ° 或 rad |
| 夹爪驱动关节角 | 舵机直接驱动的 `joint7_left` 命令角；模型中的 `joint7_right` 由齿轮反向联动 | ° 或 rad |
| 两指总开角 | 左右夹指之间的实际夹角；按 2:1 齿轮联动为夹爪驱动关节角的两倍 | ° |
| 夹爪开口宽度 | 两夹指之间的线性距离 | mm |

- 默认位：J1–J6 全 0°，夹爪闭合。
- 工作位：J3=-60°、J4=+60°，其余 J1–J6 为 0°，夹爪闭合。这里是电机角；在保留
  厂家 URDF `-Z` 轴后，`-60°/+60°` 才是抬起的有效工作构型。MoveIt 实测
  `+60°/+60°` 会让 link4–link7 穿过地面并产生自身碰撞，不能作为工作位。
- 自动外参标定姿态由型号模型声明为完整 J1–J6 关节角，感知节点不保存轴数或角度。
  下表是当前标定测试采用的 URDF 关节角（接口为弧度，表中换算为度）；换成度后与本机
  舵机命令角同符号、无额外偏移，不因 URDF 的 `-Z` 轴再反转 J3/J4。唯一来源为型号库的 `calibration_targets()`。
  九组均通过当前 MoveIt 的静态碰撞检查，FK 与同一补丁 URDF 一致；这不是实机确认。
  三轮正式软件反馈标定已通过，报告见 [验收记录](REVIEW.md)。
  **J4已恢复；按用户安排，先通过模拟抓取验收，再进入真机测试。这九组姿态尚非真机确认。**

这些值只定义StarArm-102的自动采样视角，通过现有手动关节运动接口执行；当前九组由补丁URDF
计算并经软件执行验证，不是从旧截图抄取的电机角，不固化真机落点偏差。标定计算记录实际
关节反馈和 TCP 位姿，不把命令角当作观测值，因此 MoveIt 成功后不再用另一套关节误差门限
阻塞采样。自动标定先经同一运动接口回到型号声明的 `work`，随后执行九组采样姿态。
工作位准备动作不算标定样本，每组采样运动成功后固定等待 10 秒；其他机械臂通过同一字段
声明自己的工作位和姿态组。用户先前提供的前三组实机记录为 J1=`0/-60/+60°`、J3=`-60°`、
J4=`60°`、其余为 0°；只保留为历史实机记录，不能当作当前九组已经实测的证据。
- `primary_tool=0` 表示夹爪驱动关节角 60°，对应两指总开角 120°；
  `primary_tool=1` 表示夹爪驱动关节角 0°，对应两指闭合。
- 夹爪机械模型、手动控制和 Web 允许夹爪驱动关节角达到 90°，对应两指总开角 180°。
  MTC 与 GraspGenX 的常用工作开度仍为夹爪驱动关节角 60°，对应两指总开角 120°；工作开度
  是抓取配置，不是机械限制。
- `夹爪开口宽度` 专指两夹指之间以 mm 表示的线性距离，不得与上述两种角度混用。
- J1–J6 与夹爪在模型信息中分栏，但经同一 `ArmCommand` 和 execution 节点执行。
- 执行页的“全部卸力”和“全部上力”直接使用厂家停止指令的广播 ID `0xff`，一次作用于
  J1–J6 和夹爪。“全部上力”在当前反馈位置重建锁力，不先跳转到历史命令。写入舵机内部
  参数会按厂家要求先卸力，写入结束后必须立即对该舵机重新上力。
- `StarArmBus` 只在型号边界把 J1–J6 与夹爪驱动关节绝对角编码成 FashionStar 命令并解析 ID 0–6
  的反馈；软件和真机使用同一状态契约。

## MoveIt 与 MTC

`stararm-102-motion-node` 负责该型号的 TCP 数学、MoveIt/Servo 以及 MTC Action 桥接。
`stararm_102_mtc` 只封装 `arm` 规划组、`tcp_link`、夹爪关节和工作位，使用标准 MTC stage
构造完整抓放任务。抓取候选来自 GraspGenX，生产场景不硬编码型号专用抓取姿态。

任务开始原地打开夹爪，完成接近、抓取、attach、搬运、放置、detach 和回撤，回到工作位后
闭合夹爪。任务对象和放置区域通过设备无关的 `WorldScene` 决定中心位姿；PlanningScene 只
加入刚性地平面和可附着的微米级目标中心参考点。原始图像、点云、分割包围体和其他感知几何
不进入 ROS，也不会通过第二条路径重复成为碰撞物。

释放仅约束所选位置的XY和离地至少10 cm（若所选点更高则保留其高度），不限定TCP朝向或
夹爪张合平面。MTC的释放`MoveTo`复用`PipelinePlanner`，只构造MoveIt位置目标；
位置容差沿用库默认1e-4 m，目标球最低点满足请求高度。不再叠加7 cm或枚举12个朝向。
`PickPlace.placement_pose`的orientation不参与释放规划；该字段的Z表示最低释放高度。

物理桌面仍为`base_link`的Z=0；当前厂商底座网格底面也在Z≈0，底座最高点54.4 mm，
J1轴心已由URDF放在Z=28.35 mm，不能再次把底座高度加到地面或目标位姿。
MTC地面碰撞盒顶面与物理地面统一为Z=0；已撤掉临时5 mm下移。
GraspGenX的OBB深度由官方向导几何函数测量张开活动夹指最前端，约66.471 mm；
不是扫描中心60 mm或扫描盒前端70 mm。真实TCP深度仍为93.38 mm。不能通过降低地面掩盖闭合扫掠穿地；自碰撞、模型网格、
点云外参及GraspGenX官方距离筛选不变，闭合轨迹仍由MoveIt检查。

型号模型或笛卡尔目标修改后必须核对：

1. 最终 URDF 存在 `link6 → tcp_joint → tcp_link`，MoveIt group tip 是 `tcp_link`。
2. 模型元数据、FK 和 IK 都引用同一个 `TCP_FRAME`。
3. 平移只改变 TCP 位置，定点旋转不改变 TCP 位置，圆弧只使用 `ARC_PIVOT_TO_TCP_M`。
4. 感知抓取位姿可直接作为 TCP 目标，不出现额外 73.13 mm 加减。
5. 仿真与真机继续接收同一关节命令，execution 不解释 TCP。

## 抓放验收状态

旧20轮只证明执行接口和软件反馈完成，不能证明真实夹持；旧接触判据存在穿透假阳性，
通过结论已撤销。反例、当前资产与后续验收边界统一见 [验收记录](REVIEW.md)，不在型号文档
重复维护某一测试场景的成功率、耗时或候选统计。用户已确认J4恢复，先完成模拟抓取验收再进入真机测试。

## 禁止重复处理

- 不得在 motion、perception、Web 或 execution 再实现 `link6` 与 TCP 的位置换算。
- 不得修改任一关节的厂家 URDF 轴向来纠正电机方向；若真机方向事实变化，先更新本节完整
  坐标基线和构建期验证，再修改唯一的设备适配边界。
- 不得在标定姿态、motion、perception 或 Web 中单独处理 J3/J4 的正负号。
- 不得添加业务层腕部补偿，或把标定板到测试爪的变换当成正常夹爪 TCP 偏移。
- 不得让模拟、真机、手动控制和抓放使用不同末端坐标系。
- 真实测量需要修正 TCP 时只修改 URDF 的 `tcp_joint`；下游仍只使用 `tcp_link`。
