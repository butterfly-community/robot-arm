# StarArm-102 型号适配

本文件集中维护 StarArm-102-FL 独有的模型、坐标、命名位、夹爪、规划与验收事实。通用服务
架构不依赖这里的关节数、尺寸或舵机协议。

机器人点云自过滤使用本型号 `self-filter.json` 的网格误差范围。
旧观察位可见性选择已随二次观测/规划删除；不维护另一条观察路径。

型号源码、ROS 包、补丁和镜像入口集中在
[`backend/devices/stararm-102`](../backend/devices/stararm-102/README.md)。感知节点通过通用
`RobotModelInfo.gripper_asset_id` 获取夹爪资产 ID，不保存或判断本型号名称。

## 模型来源与补丁

### 实装舵机

用户于 2026-09-05 确认：六个机械臂关节和夹爪的舵机全部为 **RA8-U35H-M**。
型号事实不依赖可重新设置的总线 ID。官方资料为
[35KG 系列产品页](https://fashionrobo.com/actuator-u35/23392/)，覆盖 RA8/HA8、U35/U35H 多个变体。

该页确认 UART/TTL、角度/轮式/阻尼模式，以及位置、电压、电流、功率和温度反馈。但页面存在
内部矛盾：概览写空心杯、34 rpm（0.298 s/60°），参数表写铁芯、55 rpm（0.208 s/60°）；
55 rpm 与 0.208 s/60° 本身也不等价；编码器写 12 bit，分辨率又写 2048 阶/圈。
因此这些数值不能直接作为该 H 型号的精确速度、精度或加速度配置。

**用户最终约定（2026-09-05）：最高电机角速度直接采用 34 rpm = 204°/s ≈ 3.56 rad/s，
不再除以 2，并已授权应用到本型号的软件模型。** 34 rpm 是用户选择的最高值，
不是一个需要再次折半的空载基准，也不声称它恰好等于 55 rpm 的一半。
夹爪也按电机/驱动关节角速度计，不把两指总开角速度混入电机参数。

机械装配范围继续采用已确认的型号角度表，不用产品页的单圈/多圈协议范围覆盖。规划和
ros2_control 的速度必须同时取自同一 URDF；厂商 MoveIt YAML 中 3.14 rad/s 的覆盖值与
原始 URDF 机械臂关节的 1 rad/s 不一致。型号补丁把全部转动关节的 URDF `velocity` 统一为
`3.560471674 rad/s`（34 rpm 的单位换算），同时删除 YAML 中的速度覆盖，MoveIt 与 ros2_control
共同继承 URDF。保留换算精度仅用于模型文件，文档/界面可显示 3.56 rad/s。未写入舵机 EEPROM，
也不改变其他机械臂或通用 TCP 手动控制速度。

### 持续夹持反馈

`execution/src/gripper_feedback.rs` 的控制目标是现有 0–100 实测负载值，不是夹持角度。
闭合开始就进入反馈调节，运输中持续运行；不等待首次达到目标后锁存位置，不改写 MTC
夹爪轨迹为采样角。闭合开始以现有负载刻度对应的功率作为初始估计，而不是直接从最大
功率开始；此后每个新的 Monitor 用未封顶的原始功率反馈动态修正，不能用界面封顶的 100
掩盖更大的超调。目标对应的功率是反馈误差的单位换算，不是固定下发命令。
修正系数 `a=实际采样间隔/(实际采样间隔+原生位置命令时间)` 沿用已有 100 ms 命令时间。
令 `u` 为当前动态功率上限、`t` 为目标刻度对应的功率、`p` 为原始实测功率，
每次更新为 `u ← u + a·u·(t−p)/(t+p)`，然后沿用原有协议范围。积分保留浮点精度，
只在 UART/消息边界量化，避免小于 1 mW 的纠偏永久丢失。这里不是固定输出 `t`，也不按
物体调参。028 实测中原先的绝对误差减法曾将上限骤降至 1 mW，随后失去夹持；相对误差
更新避免单个大反馈样本直接扣光当前出力。海绵已有十次持续持物至释放的实测，硬盒仍不稳定；
这不证明任意物体稳固或反馈无异常，详见 [验收边界](REVIEW.md)。首次出现可测负载前，现有 400 mW
空载基线及以下不累加正误差。自由运动的摩擦也可能超过该基线，因此不能据此断言
首次接触前完全没有积分累积；出现负载后即使再次归零仍继续纠偏，不能冻结低输出导致失去预紧力。
负载低于目标时增加驱动、高于目标时降低驱动，持物中持续执行。重复/倒序采样不重复积分。
位置目标仍表达闭合意图，实际受到物体阻挡的角度不是需要追踪的保持目标。

上限沿用原有 2000 mW；厂商协议 power=0 表示最大功率而不是零出力，因此闭环减力时
最小可编码值为 1 mW。这是协议语义，不是增加物体拒绝条件，也不修改舵机内部保护配置。
显式张开、全部卸力、断开连接退出闭环；相同闭合目标和后续运输不能重置调节结果。
开合意图按同一 UART 0.1° 位置编码比较，避免轨迹端点浮点噪声错误退出调节。
同步写入只发编码变化的舵机，其他关节变化不会重复下发未变化的夹爪命令。
该原生字段是可用执行输入，不等同于硬件提供了直接牛顿力矩模式；真实效果必须实测。

此刻度是功率推导的负载指标，不是测力传感器的牛顿值，也不能消除惯性、电机摩擦和采样延迟。
“维持 50”是闭环目标，不是每个瞬间精确等于 50 的保证，实际稳定性必须查看真机反馈曲线。
`transport_state` 暴露目标、实测值和当前动态输出 `gripper_control_power_mw`，不再暴露
“保持角度”；正式执行诊断同时记录这些值和真实关节采样时间，不用软件成功覆盖用户现场判定。
原始 `gripper_feedback_telemetry` 和 `gripper_feedback_time_ns` 保留同次 Monitor 数值，
其中功率限制是采样前已下发值；动态输出字段是处理新反馈后的值。用户接受力度正常波动，
验收重点为持续调节、无意外张开及驱动/通信异常，不要求每个采样都等于目标。

### 厂商模型版本

厂家源码固定在提交 `0896306e40891c3ee4c97228e85dd708d61326de`。构建先用
`tools/verify-model.py` 验证该提交的原始关节定义，再应用
`backend/devices/stararm-102/patches/` 中的型号补丁，最后再次验证成品模型；不直接修改厂商
仓库，也不维护运行时模型覆盖。关节范围、夹爪范围、TCP 和 ROS 2 打包修正位于
`model.patch`，动力学与 ROS topic 修正分别位于 `dynamics.patch` 和 `topic-io.patch`。

厂商资产镜像标签统一见 [镜像清单](DOCKER.md)。升级时核对实际模型差异及补丁后校验结果，
不从提交标题推断模型变化；不覆盖已验证旧标签，不因上游文档更新重编全部服务或重新标定。

### 舵机信息读取

`fashionstar-uart::REGISTERS` 是公开读取字段的唯一声明：地址 1–8 为电气状态、
型号编码、固件版本编码和序列号；33、34、36–53 为厂商已定义的配置字段。
不扫描未知或保留地址，不因为有读取能力就修改参数。地址 45 的功率滞回定义来自
[厂商工作台](https://fashionstar.com.cn/wiki/software/servo/data/web-controller/)，
其余类型与地址来自[官方 SDK 只读/自定义参数表](https://github.com/servodevelop/servo-uart-rs485-sdk/blob/main/STM32F103/README.md)。
旧版 SDK 标作保留的 45 等可能因固件差异不响应；记录该字段的错误，
不能返回零、套用其他固件默认值或阻止读取后面的字段。

固件字段是 `READ_DATA(0x03)` 地址 7 的两个小端字节，**不是内部参数块的
`version_info`**。2026-09-13 七电机直接实读：ID 1、2 返回 `30 03`（`0x0330`），
ID 0、3、4、5、6 返回 `25 02`（`0x0225`）。原始整数分别是 816 和 549；
现有来源没有明确 Vxxx 的显示编码，界面保留原码和原始整数，不把它们武断标为
V816/V549，也不根据版本数值自动切换控制协议或升级固件。

连接后及网页“读取全部舵机信息”启动同一个增量扫描，读取 27 个公开字段和一个内部参数块，
共 196 次事务。已弃用轮式控制及地址 47 不提供兼容入口。
`begin_data_read/poll_data_read` 只处理已有字节，跟 Monitor 事务交替占用
**同一个串口**；事件循环可继续接收位置目标，但必须等待当前回包事务结束才能发送。
等待期间只保留最新完整目标，不积压轨迹点。到期的 Monitor 优先于下一字段；
当前字段超时使用原驱动超时和一次重试，随后记录错误继续。内部参数读取允许已有的
200 ms 响应延迟。禁止用第二个串口读线程抢响应。刷新请求表示启动扫描，
完成以 `parameter_reading=false` 和完成计数为准，不把 HTTP 接受当作读完。

公开参数与内部参数各自保留逐项读取时间及错误；开始扫描会清除旧参数结果，断开连接后
明确标为历史缓存。Monitor 的完整 `arm_telemetry` 随正常 transport 输出，包含七电机的
角度原值、圈数、电压、电流、功率、温度 ADC 和状态位；不把其他电机反馈丢弃为仅夹爪。
温度保留原始值，未确认型号适配前不套用转换公式。读取测试不改变零点、PID、上力状态或目标。

七个电机型号编码分为 `0x0102` / `0x0203` 两组，不凭编码猜硬件型号；
序列号地址 8 全部报告 `10000001`，本批实物该字段不唯一，不能作为设备唯一身份。
可复现网页验收入口为 `tools/diagnostics/verify-servo-information-ui.mjs`，截图和原始状态输出到
调用者指定的 `temp/` 子目录。只读验收不代替运动或平滑性验收。

### 参数写入与解释

执行连接提供明确的串口下拉框和手动路径输入，共用 `fields.port`；节点启动时枚举，
“刷新串口”重新查询当前设备并显示厂商、产品、序列号（设备提供时）及系统路径。
枚举失败返回原始错误，不伪装成空列表；刷新不覆盖手动草稿。
连接操作持久保存路径，刷新页面回填；已连接时需先断开才能更换。
下拉选项来自实时枚举，不把 `/dev/ttyUSB0` 当作固定设备身份；需要稳定路径时可手动输入
`/dev/serial/by-id/...`。该路径需在执行容器中可访问。

完整的驱动能力、各 SDK 差异，以及 **42 项参数逐项的作用、单位和调整效果**见
[FashionStar UART 驱动说明](../backend/crates/fashionstar-uart/README.md)。网页执行页的参数选择框
与表头提示使用同一份解释；文档表格由同源元数据生成并校验，不维护另一个口径。
网页开放 17 个普通参数和 7 个 PID 字段，写入后必须回读一致才显示完成。
这里的完成仅指写入及即时回读，不表示上电生效参数已完成行为验证；软件服务重启不等于舵机重新上电。
没有运动副作用的普通配置不用卸力；内部参数按厂商流程卸力、等待、写入、恢复上力、整块回读。
该过程采用增量状态机，不用旧的同步 Kp/HoldKp 专用处理分支。
内部写入完成、失败或取消后清除已发送位置的去重缓存，因为 Stop 会中断旧目标；
不主动重发位置，只让下一条正常目标仍可执行。普通寄存器写入不改变该缓存。
ID/波特率在通用驱动提供写入，但当前机械臂页面保留既有设备映射，不单独改掉连接契约。

真机写入验收仅覆盖 J1 软启动时间的修改、即时回读与恢复；PID 内部写入的整块保留、
失败恢复和目标缓存失效通过 PTY 测试覆盖，未在真机修改 PID。
实际测试范围统一见 [验收说明](REVIEW.md#舵机驱动验收)，不宣称所有可写字段均已完成真机验收。
连接 Ping 统一使用按指令码及 ID 匹配的回复事务，不再把串口中的第一包直接当作 Ping 回复。

### 角度坐标基线（电机与模型）

业务接口中的 J1–J6 和夹爪角均指对应舵机的**电机旋转角**。业务零点就是 UART 位置命令和
反馈中的 0°，项目不另加软件零偏；正负号原样跨过 Web、Dora、motion、ROS controller 和
Rust execution。motion 与 perception 不得对任何一个轴另加反号或偏移。厂家原始 URDF 的
全部转动轴均为各自关节局部坐标系的 `axis="0 0 -1"`；项目补丁保留这些轴向，只调整声明
范围。URDF 中的 `-Z` 是运动学旋转轴，不是数值反号：对每个主动轴都满足
`q_urdf(rad) = angle_uart(deg) × π / 180`。

| 业务关节 | 舵机 ID | 厂家 URDF 轴 | 厂家提交范围 | 补丁后电机角范围 | UART 命令/反馈映射 |
| --- | ---: | --- | ---: | ---: | --- |
| J1 / `joint1` | 0 | `0 0 -1` | -2.27…2.27 rad | -110°…110° | 同符号、无偏移 |
| J2 / `joint2` | 1 | `0 0 -1` | 0…3.14 rad | 0°…180° | 同符号、无偏移 |
| J3 / `joint3` | 2 | `0 0 -1` | -3.14…0 rad | -270°…0° | 同符号、无偏移 |
| J4 / `joint4` | 3 | `0 0 -1` | -1.57…2.2 rad | -90°…90° | 同符号、无偏移 |
| J5 / `joint5` | 4 | `0 0 -1` | -1.2…1.2 rad | -65°…65° | 同符号、无偏移 |
| J6 / `joint6` | 5 | `0 0 -1` | -3.14…3.14 rad | -150°…150° | 同符号、无偏移 |
| 夹爪驱动 / `joint7_left` | 6 | `0 0 -1` | 0…1.57 rad | 0°…90° | 同符号、无偏移 |
| 从动夹指 / `joint7_right` | — | `0 0 -1` | -1.57…0 rad | -π/2…0 rad | `joint7_left × -1`，不经过 UART |

J3 的机械行程幅度是 0–270°，但该轴在已经由真机确认的 UART/业务坐标中沿负方向运动，
因此模型中的有符号范围写作 -270–0°；这不是额外反号。运行时的唯一型号定义、补丁后 URDF、
MoveIt、前端滑杆以及 execution 串口写入前校验必须保持上表一致。模型加载时会核对 URDF 与
型号定义，任何漂移都会直接阻止服务启动。

真机反馈可以因舵机零点误差短暂落在机械范围外，例如 J2 在 0°附近返回 -0.3°。execution
保留并对外发布这个原始反馈；motion 仅在把当前状态交给 ROS/MoveIt 时投影到上表边界，避免
`ros2_control` 因当前值越界而中止所有轨迹。该投影没有额外容差常量，也不放宽规划或 UART
命令范围；下一条动作可直接从边界状态继续，不存在单独的解锁或恢复流程。

厂家 ROS Python 驱动会对夹爪做一次反号转换，但本项目没有使用该驱动：Rust execution 直接
收发 FashionStar ID 0–6，因此夹爪也采用上表的同符号电机角。不得把厂家 Python 驱动的
转换复制到本项目。真机已确认 J3 负电机角是抬起方向；自动标定要求的是“负向幅度至少
10°”，即 `J3 ≤ -10°`，`-11°` 有效而 `-9°` 无效。

`stararm-102-model` 从最终 URDF 生成模型信息与资源 manifest；execution 是模型资源和
FashionStar UART 映射的唯一所有者。GraspGenX 只在设备目录保存不可推导的清单；计算镜像
构建时从同一份已打补丁模型自动生成夹爪 URDF、网格、扫描体和配置，不读取预生成资产。

## 唯一 TCP

`tcp_link` 是该型号唯一工具中心点，位于两侧夹爪尖端之间。它通过零位移、零旋转固定关节
连接到结构链接 `link6`。两者当前数值位置相同，但语义不同：

| 坐标系 | 含义 | 是否用于业务目标 |
| --- | --- | --- |
| `link6` | 第六轴末端结构链接 | 否 |
| `tcp_link` | 夹爪尖端中心、MoveIt 规划末端 | 是 |
| `link7_left` / `link7_right` | 两侧活动夹指 | 否 |

厂家夹指转轴位于 `link6` 的 `z=-73.13 mm`，夹指网格延伸到 `z≈0`。因此新增 `tcp_link`
只是显式命名厂家模型已有的尖端中心，没有引入工具偏移。MoveIt group tip、FK、IK、抓放目标、
附着物体、模型元数据与标定观测都使用 `stararm_102_model::TCP_FRAME`。

`ARC_PIVOT_TO_TCP_M = [0, 0, 0.07313]` 只表示夹爪转轴到尖端中心的圆弧演示几何，不是
`link6 → tcp_link` 变换，不能用于 FK、IK、抓放、附着或相机标定。

真机最终验收使用用户指定的九组最大平移拟合残差 ≤10 mm（1 cm），RMS 供参考；
这是观测一致性，不是独立物体定位精度。模拟资产单独使用用户最新指定的 ≤1 mm 标准。

2026-09-10 核对 D415 持久配置，最大拟合残差为 **8.639 mm**，RMS **5.691 mm**，
通过用户的 10 mm 标准；以后更新标定以网页与持久配置为准，不使用历史数值覆盖。
正式外参按相机来源持久保存在 `backend/config/runtime/camera.json`，不依赖 `temp/`；
相机与机械臂相对位置改变后重新标定。不再维护历史轮次、逐组残差和外参副本。

### 真机精度与适用限制

闭合完成与力度保持是不同语义。运动节点用同批真实编码器位置/时间差计算速度，
ROS JointState 传递实际采样时间，速度只作真实反馈保留。机械臂与手部恢复经过抓放验证的
原版 JTC position 状态/position 命令契约，不再修改底层完成判定。
不增加容差或固定等待，不要求夹着物体时到达空载闭合角；动态力度保持独立继续。
TOTG 与 JTC 的实验性补丁均撤出生产构建，避免停稳检查与非零末点速度互相叠加造成回归。
原生与历史对照方法见 [MTC 回归工具](../tools/diagnostics/mtc-ranking-test/README.md)。
回到执行基线不证明实物夹持成功，必须重新核对抓取、搬运和释放的实拍。
MoveIt 的 `trajectory_execution.execution_duration_monitoring=false` 使上层等待控制器
实际 action 结果，而不是按估算轨迹时长取消。实测短手部动作曾在 JTC 报成功后、
结果传回前触发 TEM 的 0.538 s 预算，属于两层完成时序冲突；不以增大任意秒数规避。
错误和取消结果照常处理，并未关闭执行等待、控制器判定或规划碰撞检查。

当前真机标定已按用户的最大拟合残差 ≤10 mm 标准通过。精度提升仅作为本节的背景说明，
不列入 TODO，也不是项目收敛或继续抓放的前置条件；不因此新增代码门限、重新标定或修改默认姿态。

最大拟合残差描述九组观测中最差的一组一致性，RMS 描述这九组平移残差的均方根。
两者都不是对整个工作空间的定位误差保证，也不包含抓取中滑动、挠曲等实际效果。
该拟合结果不能解释为“任何物体都能定位到相同误差以内”。

- 电机实际反馈用于 FK，但不能直接测出连杆、零位、间隙和受力变形；UART 的 0.1° 单位不是末端精度。
- 打印缩放、板面平整度、夹持刚性、有效角点和相机内参匹配均影响求解，不能仅由残差归因。
- 图像与同批反馈 FK 为软件时间配对，不是曝光与电机读数的硬件同步。
- RGB-D 深度、彩深对齐和目标边缘另有观测误差；模拟的 1 mm 标准不是真机精度承诺。
- 实际抓放已由用户确认完成率可接受，没有全工作空间的独立精度测量；不据此新增待办或门限。

## 夹爪控制语义

- `primary_tool=0` 表示夹爪驱动关节角 60°，对应两指总开角 120°；
  `primary_tool=1` 表示夹爪驱动关节角 0°，对应两指闭合。
- 夹爪机械模型、手动控制和 Web 允许夹爪驱动关节角达到 90°，对应两指总开角 180°。
  MTC 与 GraspGenX 的常用工作开度仍为夹爪驱动关节角 60°，对应两指总开角 120°；工作开度
  是抓取配置，不是机械限制。
- `夹爪开口宽度` 专指两夹指之间以 mm 表示的线性距离，不得与上述两种角度混用。
- J1–J6 与夹爪在模型信息中分栏，但经同一 `ArmCommand` 和 execution 节点执行。
- 执行页的“全部卸力”和“全部上力”直接使用厂家停止指令的广播 ID `0xff`，一次作用于
  J1–J6 和夹爪。“全部上力”在当前反馈位置重建锁力，不先跳转到历史命令。写入舵机内部
  参数会按厂家要求先卸力，写入结束后必须立即对该舵机重新上力。
- `StarArmBus` 只在型号边界把 J1–J6 与夹爪驱动关节绝对角编码成 FashionStar 命令并解析 ID 0–6
  的反馈；软件和真机使用同一状态契约。

## MoveIt 与 MTC

`stararm-102-motion-node` 负责该型号的 TCP 数学、MoveIt/Servo 以及 MTC Action 桥接。
`stararm_102_mtc` 只封装 `arm` 规划组、`tcp_link`、夹爪关节和工作位，使用标准 MTC stage
构造完整抓放任务。抓取候选来自 GraspGenX，生产场景不硬编码型号专用抓取姿态。
`stararm_102_mtc/action/PickPlace` 是本项目自定义请求名，内部调用 MTC `Task`，不是旧版
MoveIt Pick/Place 流水线，也不调用 `MoveGroupInterface::pick()` / `place()`。

任务开始原地打开夹爪，完成接近、抓取、attach、搬运、放置、detach 和回撤，回到工作位后
闭合夹爪。任务对象和放置区域通过设备无关的 `WorldScene` 决定中心位姿。MTC 将感知目标的
包围体作为可附着的独立对象，保留刚性地面；同一次感知点云保留真实模型可能接触的范围后由官方
`PointCloudOctomapUpdater` 建立环境快照。独立目标的重复点由官方形状过滤处理，不把筐等
其他实例改成实心包围盒，也不另开相机或 ROS 感知业务链。

范围是全部运动链与碰撞几何的保守包络，加上任一候选持物偏移和一个体素对角线；不是指定半径
或新的可达性限制。范围内不降采样；GraspGenX 仍接收原来的目标/环境点云。
每个抓放请求只发布一次点云，等待对应的官方 filtered cloud 回调后才规划。运输阶段由 MTC
attach/detach 移动目标体积，不持续重发旧点云，也不要求抓起后获得新观测。任务结束清除该次
快照及临时目标；下一次任务重新建立快照。地图体素为 5 mm，不是地面容差或允许穿透距离。单视角未观测到的
表面仍未知，点云规划不等于对所有真实表面的碰撞保证。
真实深度边缘缓坡曾在目标盒外留下阻挡闭合的体素。建图期间仅对抓取目标使用一层体素
的形状过滤包络，收到同帧回调后同步恢复真实目标尺寸，再启动 MTC 规划；不扩大实际附着物。
同一候选沿 TCP +Z 按地图分辨率生成加深变体，保留原位、不改变朝向。候选 IK 使用关节组
原有查询预算；将每个候选扩大到 5 s 的实测未改善当轮结果，反而导致数分钟乃至更长等待，
已经撤回。独立查询的时间预算不能无验证地乘到整批候选上。候选变体按现有软质量成本
稳定排序、逐个送入原生 MTC；失败后继续下一变体，不提前排入数千个接口状态。
使用 MTC `plan(1)` 获取首条完整抓放方案（不是单个 IK 成功），然后保持原有选中候选
深度精修，穷尽其深度与平面起点变体。优先最深的完整可行方案，同深度再选更小关节行程。
不再为扩大排名池等待二十条完整方案；首条完整解不等于全部候选的全局最优。软质量成本仍为：
`(1−原始模型分)+(夹持跨度+夹取几何偏差)/观测对象对角线`，越小越好。
质量成本相同时才比较指尖高低差比例，再比较归一化关节行程；不设置“相近”的人为门限，
不让指尖等高抵消更好的抓取质量。搜索仍以相同质量成本工作，完整方案排序才增加指尖择优项。
左右指尖由 `fingertips.hpp` 的两个 `FingertipReference` 定义：各指头实际 CAD 网格沿局部
`+X` 最末端面/边的包围中心，附着于 `link7_left/right`，用原生 RobotState FK 随指头运动。
不新增碰撞体、不修改 TCP，不把 GraspGenX 的单个采样深度 `fingertip` 当成两个指尖。
评分取接近结束时既有 `open` 姿态的两个点，变换到候选所在坐标系后计算
`|右指尖.z−左指尖.z| / 两指尖距离`，即连线离水平角的正弦，范围 0–1。
实际夹持开度由力反馈决定，规划时未知；这个指标不是实际接触或闭合全过程等高的保证。
这是用户要求的“两个指尖离地等高”择优项：顶部、侧向、倾斜接近均可，不固定 J6、
不限制张合平面、不修改候选位姿。按用户随后明确指定的规则，接近结束时张开指尖连线
相对地面倾角 **达到或超过 20° 直接过滤**；角度大小取绝对值，左右指尖互换不影响结果。
过滤发生在候选进入 ComputeIK 之前，粗搜索和深度精修共用，不是规划后再丢弃。
唯一代码数值源为 `fingertips.hpp::kMaximumFingertipTiltDegrees`。
参考为任务地面的法向，
不是相机视角或底座前边方向；本任务地面与候选同处 `goal.frame_id`，法向为 +Z。
一般定义是 `asin(|n·(右指尖−左指尖)|/|右指尖−左指尖|)`，`n` 为同坐标系的单位地面法向。
本任务的 `ground(goal.frame_id)` 明确定义 Z=0 上表面，因此代码中的 Z 差就是上述点积；
不能把相机坐标下的 Z 差代入。若未来改变地面定义，必须同步更新法向，不能沿用当前坐标约定。
小于 20° 的倾斜候选仍可执行；过滤后无候选则报告原因，不回退到大倾角候选。
最终还须实际抓取验收，等高本身不证明夹持成功。
它不要求指头本体、张合平面或整个夹爪平行地面。
不按接近方向过滤；拒绝条件仅是上述两指尖连线与任务地平面的相对角度。
排序只在应用层完成，不改变官方 MoveIt、碰撞规则或候选位姿；实物验证范围见验收说明。
本型号 TCP 位于闭合指尖。将观测中心转入最终加深后 TCP 坐标，记为 `(x,y,z)`，
夹取几何偏差为 `sqrt(x²+y²+max(z,0)²)`：保留横向偏心与未深入的距离，
不再把中心已经进入指尖后方的有效深度当作“离中心太远”。它是中心到 TCP 内向半轴的
距离，不是改写候选或允许碰撞。原来的对称欧氏距离曾将浅抓和深入夹持近似等价排序。
普通 TCP 到中心距离仍单独显示供诊断；观测中心不是实测质心，指标不证明物理接触，
不作硬拒绝条件。
投影诊断 `sqrt((x/sx)²+(y/sy)²+(max(z,0)/sz)²)` 只留作分析，不参与排名。
不能把中心位置当成接触质量或真实成功的证明。轴向绝对优先的历史实验也未部署。
搜索通过 MTC 公共 `setCostTerm` 减少上述同一软质量成本，其他运动阶段不再用默认行程代价
覆盖这一主目标；完整轨迹的
关节行程仍由原生 `PathLength` 计算并用于最终次级选择。没有修改 MTC/IK/OMPL 库或碰撞。
最终执行前，对选中的候选另用同一任务工厂、同一冻结起始状态/完整 Octomap 穷尽其有限
深度网格（`plan(0)`），保留最深完整方案；不是把所有候选无限扩搜。抓放只提交一次完整任务，
在实际执行前完成该精修，不再先走观察位并二次感知。没有更深完整解则保留已验证的方案，不执行失败 IK。
深度档位从深到浅生成，但不能单靠生成顺序宣称搜索充分，MTC 仍有自己的阶段调度和成本。

说明之前“已找到方案中的最深”遗漏了可行深度；并非地面碰撞必然阻止深入。

投影宽度 `Σ(size_i × |axis_i|)`；本型号描述规定闭合轴为 TCP X。尺寸、OBB 朝向
均取当次观测，不绑定物体类别、固定尺寸、世界方向或“顶部抓取”，也不添加拒绝门限。
该值只是外包络宽度，不是内外表面接触、局部夹沿宽度或力闭合证明；不生成或改写模型候选。
闭合沿用 MTC 的允许手指/目标接触、规划闭合、附着流程，仍检查地面和其他障碍。
不再使用包围盒相对接触 `PredicateFilter`：运输外包络无法描述开口容器的内外表面，
不能据此否定夹沿姿态，也不再以实体 OBB 接触估算参与排序。真实失败回放发现该估算
