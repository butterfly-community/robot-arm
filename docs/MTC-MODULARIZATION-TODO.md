状态：模块化仅计划，尚未开始实现。用户另行授权核对并提交现有修改作为基线；本文不授权模块拆分、重启或运动测试。

## 目标与边界

将当前 `pick_place_server.cpp` 中的职责拆开，使测试直接调用生产模块，而不是
通过重命名 `main`、包含整个服务 `.cpp` 来获得内部函数。不是换规划算法或扩大服务数量。

保留现有唯一业务链路与动作：张爪、接近并抓取、持物回工作位、释放、直接回工作位、闭爪。
不改变姿态、速度、力度、深度优化、候选评分、碰撞许可、消息结构或错误语义。
不恢复独立直线抬升/退离，不增加兼容分支、策略开关、新门限或自动降级。
当前已完成的行为变更见 [持物脱离与退离简化](investigations/lift-departure.md)。

## Rust 是否更合适

建议保留现有分工：Rust 管请求、状态、Dora 消息和执行编排；C++ 管紧贴 MTC/MoveIt 的对象。
这不是断言 Rust 做不到，而是当前方案要直接操作 `Task`、`Stage`、`PlanningScene`、
`RobotTrajectory`、条件接触回调及原生代价函数。把这一层搬到 Rust，会额外引入对象生命周期、
错误传递和回调的 FFI 维护，不能仅凭语言变化认定更简单。

[MTC 官方仓库](https://github.com/moveit/moveit_task_constructor)的核心接口和本项目所用扩展
均围绕这些原生对象。现有 Rust 已经通过 ROS action 调用它，无需为模块化再加一层桥接。
纯候选数值处理有迁移可能，但现有排名直接消费 MTC 完整解与原生 PathLength，
并非整个模块都与 MoveIt 无关；不在本次计划中复制一套 Rust 排名或运动学实现。

- [ ] 实施前核对所用版本的官方接口和 Rust 绑定覆盖范围；不把“ROS 有 Rust 客户端”当作“MTC 已有完整 Rust API”。
- [ ] 只有能证明减少总依赖、胶水代码和测试成本，才调整语言边界；本次优先原语言内模块化。

## 拟拆职责

以下是职责边界，不强制文件数量或名称；实现审查发现更短路径可以调整，不为了分层制造空壳。

| 模块 | 拥有的内容 | 测试边界 |
| --- | --- | --- |
| 抓取候选 | 深度变体、候选身份传递、完整解排名、原生运动代价 | 不启动服务，输入确定性候选与原生测试轨迹 |
| 规划适配 | 闭合重采样检查、条件支撑接触、位置目标规划 | 原生离线场景与轨迹，无设备 |
| 场景管理 | 目标几何、冻结地图更新时序、目标过滤与还原、任务清理 | 几何单测与 ROS 场景集成测试分开 |
| 任务组装 | 按当前规则构建 MTC 阶段树 | 可构建/检查任务，不必启动 action 服务或执行运动 |
| 服务入口 | 接收请求、反馈、规划/执行调用、结果与错误返回 | 调用上述模块，不重复算法 |

## 实施时的环境约束

ROS/MoveIt 测试在 motion 所属镜像内执行；产物放工程 `temp/`，停止服务后该目录可随时清空。
只增量构建受影响的应用包，不因拆文件重编基础环境。需要更新运行栈时整套关闭、整套重启。
测试输入和诊断代码只留在 tests/tools；不为模拟器建立另一条生产链路。
