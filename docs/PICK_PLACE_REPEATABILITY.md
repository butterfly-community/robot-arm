# 抓放重复性验收

## 最终结论

抓放已经从四次独立、仅约束位置的 MoveGroup 请求迁移为一份完整的 MoveIt Task Constructor
任务。最终确定性场景连续执行 20 次，20 次均完成规划、执行、放置、回撤和返回工作位，成功率
100%。每次均找到 7 个完整任务解，由 MTC 的标准代价排序选择一份执行；没有旧八步编排、
position-only 目标、运行时额外回撤或失败后的专用恢复路径。

最终原始数据位于
`tools/diagnostics/results/pick-place-mtc-repeatability.json`，诊断工具位于
`tools/diagnostics/pick-place-repeatability.mjs`。

## 最终测试条件

- 时间：2026-08-31
- 次数：连续 20 次
- 链路：网页 API → Rust FIFO → StarArm-102 MTC → MoveIt/ros2_control → execution 软件反馈
- 感知：固定 RGB 经真实 YOLOE 分割，确定性深度生成实例点云，GraspGenX 从点云生成抓取候选
- GraspGenX：固定推理种子 0；相同点云产生相同候选，不在测试数据中硬编码抓取姿态
- 抓取物：红色立方体，中心约 `(0.1625, -0.0104, 0.0400) m`，高度 8 cm
- 放置区：灰色置物筐内部，中心约 `(0.1523, 0.0940, 0.0400) m`，筐高 8 cm
- 最终位：工作位 J3=60°、J4=60°，其余 J1–J6 为 0°，夹爪闭合
- 真机串口：未连接；这组高重复性数据只使用软件反馈

## 最终 20 轮数据

| 项目 | 结果 |
| --- | ---: |
| 成功 | 20 / 20 |
| 单轮耗时（最小 / 平均 / 最大） | 8.281 / 8.368 / 8.412 s |
| 完整候选方案 | 每轮 7 个 |
| 选中代价（最小 / 平均 / 最大） | 24.337 / 24.548 / 28.526 |
| 工作位最大终点误差 | 0.006° |
| 全部关节最大相邻反馈变化 | 1.936° |
| J6 单轮范围（最小 / 平均 / 最大） | 126.570° / 126.578° / 126.584° |
| J6 累计行程（最小 / 平均 / 最大） | 253.140° / 253.152° / 253.161° |

J6 仍有较大运动，但 20 轮的范围差只有约 0.014°，不是旧实现中同一目标随机切换 IK 构型的
离散行为。它来自 GraspGenX 候选姿态和 MTC 选中的完整可行解；MTC 已搜索全部完整方案并采用
标准代价排序，项目没有再加入腕部角度门限或自定义加权规则。轨迹的最大相邻反馈变化小于 2°，
没有单帧跳到 90°。

控制器曾拒绝 MTC 生成的非零终点速度。最终使用
`joint_trajectory_controller` 自带的 `allow_nonzero_velocity_at_trajectory_end` 配置，避免在
项目代码里重写或截断轨迹。最终 20 轮均完整执行。

## 迁移前问题基线

迁移前原始数据保留在
`tools/diagnostics/results/pick-place-repeatability.json`。旧链路把接近、抓取、搬运和放置拆成
四次独立的 position-only 请求，同一位置可以选择任意末端姿态和 IK 构型；运行容器还因 Cargo
target 跨构建缓存运行过与源码不一致的额外回撤步骤。

| 项目 | 迁移前结果 |
| --- | ---: |
| 成功 | 19 / 20 |
| J6 单轮范围最大值 | 227.07° |
| J6 累计行程最大值 | 809.77° |
| 同一目标的 J6 终点跨度最大值 | 约 244° |

第 14 轮旧实现失败后，第 15 轮能从实际反馈状态重新开始，证明不需要隐藏恢复路径。迁移后
MTC 使用 `CurrentState` 同样从当前反馈构建任务。Docker 构建也不再挂载跨构建 Cargo target，
运行二进制与当前源码一致。

## 数据解释边界

最终测试证明的是正式软件链路、规划完整性、确定性和连续性。实体舵机允许存在既有的 3–5°
机械偏差；它不进入软件成功门限。测试点云、候选抓取位姿和 MTC 轨迹均保存在原始 JSON 中，
文档不使用前端渲染结果替代规划与反馈事实。
