## 当前实现与边界

采用分阶段的 **stop–look–move（停稳、观测、重规划）**，复用现有分割、
GraspGenX 场景点云接口和 MoveIt Task Constructor，不手写新的抓取/伺服算法。
这不是已经实现 ViSP 连续视觉伺服，也不声称通过重看目标消除了末端定位误差。

1. 人类在原网页运行感知、选择物体与放置区、点击执行抓放。
2. MTC 仍先搜索完整可执行方案。在其 `move to pregrasp` 原生路径上，从后向前
   查询相机至目标表面点的视线是否被机械臂网格挡住，选择最后一个最大可见的路点。
   保留此前阶段与场景差量，只截短 Connect；使用 MoveIt TOTG 重定时、核对实际输出
   路径碰撞，并将终点场景更新为真实截断关节姿态。尚不接近、闭合或搬运。
3. 原任务保持执行中，通过 Dora 请求 scene-node 二次观测。scene-node 异步等待
   请求之后接收到的新 RGB-D 帧，再使用同一已保存的模型/提示词处理。
4. 以原选择的类别和三维中心最近邻关联新实例，不能依赖每帧变化的检测编号。
   放置位置保留人类已选定的任务目标，不随第二帧检测编号变化、消失而改选。
   未检出抓取目标时不使用旧位置继续闭合。
5. 使用新目标、新候选和同帧完整点云，从当前反馈状态重新生成完整 MTC 方案，
   成功后执行抓取与放置。第二阶段不再重复触发二次观测。
6. UI 仍是一次抓放任务，展示前往预抓取位、重新观测、重规划和执行状态；
   预抓取到达不能作为整个任务成功。

局限：固定相机在末端靠近时可能被夹爪遮挡，重新识别的几何必须实测核对。
最近邻关联适用于当前静止、分开的物体；不等于通用多目标跟踪。
相机还未独立测量实际夹爪位姿，因此机器人柔性、关节误差、手眼误差不由此自动消除。
若需要这类修正，应比较可见夹爪的模型跟踪与实际 RGB-D，再引入闭环位姿反馈，
不能将 FK 预测伪装成视觉测量，也不能偷偷平移目标而不更新碰撞场景。
