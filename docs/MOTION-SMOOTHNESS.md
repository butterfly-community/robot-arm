2026-09-11 在连续五次真实海绵抓放通过、基线提交 `150ca70` 后开始。
本阶段目前完成测量工具及首轮五次记录分析，**尚未修改运行参数，也未声称抖动已改善**。
不改官方 MoveIt/JTC/TOTG，不为制造平滑效果修改实际反馈或添加未授权门限。

这些是观察值，不是新的限制。五次各关节最小非零编码器步进约0.1°，因此约100ms差分
本身会出现约1°/s的量化台阶，不能将差分的变化直接命名为真实加速度或jerk。
最长同目标段包含运动后的初始收敛；046/049的0.9°/0.8°范围不能直接当作稳态振幅。
快照轮询可能漏过中间硬件样本和命令，最大间隔不能单独证明UART停顿。

## 已核实的控制链与下一处测量

1. 官方控制器输出位置 → ROS适配 → 同一 `arm_command` → execution → 厂商UART位置命令。
   Dora的两处定时输入为10ms，execution配置反馈读取周期为100ms；读取和写入共享同一串口。
2. 当前UART运动字段是100ms运动时间、50ms加速、50ms减速；角度编码为0.1°。
   execution仅发送编码后实际变化的舵机命令，不能把所有反馈快照当成重复写入。
3. `ArmCommand.controller_time_ns` 当前在适配层生成，不是ROS原始输出时间，更不是实际UART
   写完时间。因此本轮工具只报告“可见命令间隔”，不冒充整个下发时序。
4. 下一处有价值的测量是同一次运动的原生控制器输出、适配层接收、UART写入/读反馈时间，
   区分队列积压、串口读写互斥与舵机反复接收梯形位置命令。确认实际瓶颈后才改相应层；
   不根据现在的100ms快照盲调PID、滤波反馈或改规划器。

输入分别由 `audit-gripper-feedback.mjs --live` 和 `measure-grasp-ui.mjs` 新录制；后者会真实

工具不调用网络、不下发运动；输出严格区分旧任务带入的目标、当前窗口命令和反馈采样时间。
