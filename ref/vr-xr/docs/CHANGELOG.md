# NOLO CV1 当前有效变更记录

本文件只保留对当前实现仍然有效的结果。已经被迁移替代的中间方案可从 Git 历史追溯，不能
作为现行接口或操作说明。当前操作以 [入口说明](../README.md) 为准，接口与验收状态以
[统一控制实现与验收记录](TODO.md) 为准。

## 2026-08-26：全面审查与后端人体参考

- 三个实体按键重新统一：Trigger 按住接管、松开停止；右侧 Squeeze 静止长按 6 秒标定；
  Menu 按下闭合夹爪、松开打开。真实 USB 和虚拟报告使用同一映射，执行链字段改为功能名，
  不再把 Trigger 误称为夹爪输入。
- 串口连接不检查软件或真机的起始位；先读取 ID 0–6 的真机反馈，成功后统一状态立即采用
  真机实测位置。
- 启动虚拟 NOLO 只切到手柄控制并开始虚拟报告，不再要求模拟机械臂起始位，也不提交
  J1–J6 或夹爪运动。
- 重复连接串口时先释放后端已有句柄，再打开同一设备，不再因自身的独占锁失败；重联
  直接从当前真机反馈恢复。
- 页面在真机串口已连接时隐藏端口输入和“连接”按钮，改为显示设备路径、J1–J6/夹爪命令去向和
  “断开”按钮。
- MoveIt Servo 暂停恢复后留下的 `-1: Invalid` 不再被项目解释为停止或闭锁；下一条有效手柄
  命令仍会发给 Servo，并由 Servo 自身更新后续状态。
- 六轴 IK 插件由厂家默认 KDL 替换为 Jazzy 二进制提供的 TRAC-IK，保留现有 `5 ms`
  timeout 和 Jazzy 2.0.2 插件默认 `Distance` 模式。容器日志确认 Servo 与 move_group
  都加载新插件，`/compute_ik` 实测成功；同轮模拟仍出现 1/3，说明该状态来自 Servo 独立的
  雅可比奇异判断，不是 KDL 求解失败。
- 网页源码删除厂家 URDF、STL 和模型说明副本。`nolo-usb-server` 镜像构建时对独立厂家
  临时副本应用与 MoveIt 相同的三个补丁，再由 TypeScript 辅助脚本生成网页模型目录；
  页面继续直接读取生成 URDF 的关节范围，不维护第二份参数。
- 采用厂家单独提供的新版 URDF 和 9 个 STL；`joint3` 几何改为明确的
  `xyz="0.12162 -0.0021 0"`。删除项目对 J1–J7 位置范围的覆盖和 Rust 配置中未使用的第二套
  位置限位，MoveIt 与网页使用厂家 URDF 范围；仅将厂家 ros2_control 中冲突的 J5 和夹爪
  command interface 同步为同一 URDF 的范围。保留此前由用户按官方资料确认的动力学参数。
- 厂家更新把 description 外壳误导出为 ROS 1 `catkin`，构建补丁仅将它适配为 ROS 2
  `ament_cmake`，不改 URDF 几何和位置范围。
- 删除未经实测且实际落在左夹爪转轴上的 `tool0`，MoveIt arm 链、TF、IPC 和配置统一改用
  厂家已有的 `link6`；以后只有完成夹爪 TCP 实测后才新增工具坐标系。
- 人体坐标原点和姿态参考由当前 Rust 后端会话持有。普通 Squeeze 标定完成后写入
  `/api/human-reference/{source_id}`；虚拟 NOLO 在会话开始时直接登记确定参考。网页刷新和
  来源切换只读取 `/api/status.humanReferences`，不使用浏览器存储，也不再用预抬升后的
  Teleop 接管锚点反推人体原点。
- IPC 升为 schema v5。J1–J6 使用固定顺序的唯一 `joints_rad` 数组，不再传递一套人为关节
  名称，也不再同时保存可逆的逻辑角和模型角。页面、软件反馈和串口反馈消费同一数组。
- `stararm102-control` 中只保存当前控制状态；删除旧纯仿真命名的状态模块、常量和页面 ID。
  ROS IPC 断开时不再把网页反馈重置为冷启动姿态，重连后继续使用 `ArmJointIo` 保留的状态。
- Unix IPC 启动时会替换异常退出遗留的 socket；正常 `docker compose down` 仍由 Rust 删除
  socket，不需要管理脚本或手工清理卷。
- FashionStar 帧编解码和串口通信收敛到独立 `fashionstar-uart` crate。协议库完整解码
  Monitor 帧用于兼容性测试；生产 `ArmJointIo` 只消费 ID 和位置，不发布其他遥测字段。
  Rust 角度编码改为与 Python `round()` 一致的半单位取偶数，流式解码会跳过损坏帧并继续
  同步下一个有效帧，且不会把厂家无效 Monitor 位置标记当作真实角度。
- 删除两项只锁定重复关节表示的 Rust 测试和一项语义错误的前端反推公式测试，新增后端人体
  参考、异常退出 socket、UART 协议、厂家默认位置范围及模型同步测试。最新全量结果为
  Rust 99、Python 13、Deno 23，共 135 项；另外连续三次完成厂家 Python SDK 1.3.12 与
  Rust 的 64 轮双向伪串口交叉测试。

## 2026-08-26：确定性虚拟姿态修正

- 标准模拟动作统一为上、下、左、右、前、后空间移动，以及左旋、右旋、前部抬起、前部
  往下。左旋/右旋表示从机械臂上方向下看时夹爪尖端在水平面内逆时针/顺时针移动，不再表示夹爪自身滚转；
  不保留独立的左转向、右转向路径。
- 根据真机隔离复现修正姿态手势的输出语义：姿态手势保持夹爪后部安装基准点不动，同时提交位置和姿态；
  前部抬起/前部往下使尖端沿同一条竖直圆弧向上/向下移动，左旋/右旋使尖端沿水平圆弧逆时针/顺时针移动。
  虚拟手柄姿态测试使用用户指定的 `8°`；机械臂圆弧使用厂家 URDF 的 `7.313 cm` 夹爪几何，
  不再把前部抬起/前部往下实现成与上/下空间移动重复的纯平移。
- 虚拟 USB 使用独立且不持久化的 Fusion 状态，不应用真实设备手工零偏，也不运行 Offset
  自适应零偏补偿，避免把确定性的慢速主动旋转学习成陀螺仪零偏。
- 虚拟 Fusion 使用生成报告自身的固定时间轴计算采样间隔，不把 Docker 调度延迟当成 IMU
  时间；真实 USB 继续使用实际接收时间。
- 标准循环为 30 秒：上下和前后各 5 cm、左右各 2 cm；左旋 8° 后右旋 8° 返回，前部抬起
  8° 后前部往下 8° 返回。姿态回程反向重走去程。
- 真机复现发现此前 LeRobot 单帧适配器的 350 ms 位置命令不适合当前 100 Hz 连续跟随，
  Monitor 会稳定停在 ROS 命令之前。运行时改用厂家 `Python_SDK/stararm102_ro.py` 连续 follower
  的 `100 ms / 50 ms / 50 ms / power 0`，并按最终 0.1° 整数协议包精确去重；命令变化立即发送，
  命令未变则让上一条命令执行完成，不引入角度门限。J4 命令和反馈的串口边界取反保持不变。

## 2026-08-25：统一机械臂控制路径

- ROS 收敛为一个 launch、一个控制器配置、一个 `JointStateTopicSystem` 和一个 IPC。
  是否连接真机只在 Rust `ArmJointIo` 边界形成一次分支。
- 删除旧 Rust IK、Python 串口执行器、模拟/真机双 ROS 配置、专用起始位执行器、浏览器本地
  机械臂覆盖和布尔夹爪协议。
- 手柄控制使用 MoveIt Servo；任意 J1–J6 目标和起始位都使用相同 `MotionRequest`、MoveGroup
  和 `ExecuteTrajectory`；夹爪绝对角独立交给 `hand_controller`。
- 统一起始位为 J1–J6 `[0°, 0°, -3°, 0°, 0°, 0°]`，夹爪冷启动为 `+1°`。普通起始位
  运动保持夹爪当前角度，完成条件与任意普通 J1–J6 目标相同，以 MoveIt 轨迹执行结果为准。
- 真实起始自碰撞导致首次规划失败时，只把本次检测到的接触对加入本次 ACM，再重试相同
  MoveGroup 路径；没有控制器直发或起始位旁路。
- 示教平移比例为 1:2，即 `translation_scale=0.5`；姿态保持 1:1。J1–J6 动力学补丁保留
  用户依据官方资料确认后选取的 `30 rad/s²`。
- 服务统一使用 `docker compose up -d` 和 `docker compose down`。Compose 不使用 host
  网络，只把 HTTP `8765` 发布到 `192.168.100.10`，Rust 与 ROS 通过专用 Unix socket 卷通信。

## 当前边界

- 真机串口协议、假串口、统一软件反馈和网页路径已经自动化验证；实物串口反馈和运动已完成
  部分定性验收，剩余定量项目保留在 TODO。
- `communication_fresh` 只描述采样序号是否继续变化，不冒充光学跟踪有效性。
- NOLO 没有已确认的磁力计输入，yaw 不会由重力修正。
- 任何后续测量只用于修正模型或可复现缺陷，不自动转化为新的项目门限、保护或拒绝流程。
